# The pre-commit lint gate: fmt, clippy and `cargo xtask affected-checks`

CLAUDE.md rule 2 is the policy: run `cargo fmt --check` and `cargo clippy --workspace --all-targets --features e2e,e2e-live -- -D warnings` before every commit, unless `cargo xtask affected-checks` finds the change is mapped text only. This page is the evidence behind that rule — why each flag is there, what the command is a superset of, what it costs, and how `affected-checks` decides — moved out of CLAUDE.md by issue #905 so a reviewer challenging the rule can find it, without every agent paying for it on every task. It is unrelated to [`build-gate.md`](build-gate.md), which bounds concurrent linking across worktrees.

## How `cargo xtask affected-checks` decides

**Which gates a change needs is what `cargo xtask affected-checks` prints** (issue #1575). It reads the change from the merge-base with `origin/main` to the working tree, untracked files included (`--base HEAD` narrows it to what is not yet committed; paths given as arguments replace the diff), and prints the commands, each changed path annotated with why; `--run` then runs them in order and exits non-zero at the first failure. When any changed path is Rust, a build input (`Cargo.toml`, `Cargo.lock`, `build.rs`, `.cargo/`, a toolchain or rustfmt/clippy config), or a path its text mapping does not cover — the fail-safe default, so `scripts/`, `site/`, `tests/CATALOG.md` and anything new land here — it prints CLAUDE.md rule 2's two commands and CLAUDE.md rule 5's `cargo test-fast`, and everything below applies unchanged. When every changed path is mapped text (`docs/`, `.claude/skills/`, `changelog.d/`, `.github/`, `devbox.json`, `renovate.json`, `prds/`, and `CLAUDE.md`/`AGENTS.md` with the other root-level prose files), it prints the tests that read those files instead: every xtask package's tests, plus the root-package tests that read the changed files. That is not "text needs nothing": `build.rs` embeds the published docs and several fast-tier tests read text from the checkout, so a docs change still builds the root package and runs `tests/embedded_docs_boundary.rs`, `tests/e2e_cli_docs.rs` and `src/embedded_docs.rs`'s unit tests. Skipping the two commands is sound for mapped text because rustfmt formats `.rs` files and clippy lints Rust, and no Rust changed; the one place mapped text becomes Rust today, `build.rs`'s generated table of the published docs, is compiled by the root-package command the docs mapping prints. The mapping lives in `xtask/linkage-check/src/affected_checks.rs`, and a guard test there scans the root package and the desktop crate — the two crates a narrowed plan does not run whole — for string literals naming a mapped path, and fails when the mapping does not run the test that reads it. It is a literal scan with a reviewed allowlist for literals that are not checkout reads (a test HOME's `.claude`, a scratch root's `changelog.d`), so a read whose path never appears as a string literal escapes it; it already caught one, `src/embedded_docs.rs`'s read of `docs/published.toml`, which the issue's own list had missed. **This narrows when the rule applies, not what it demands of code**: a change with any Rust or build input in it gets CLAUDE.md rule 2's two commands and CLAUDE.md rule 5's `cargo test-fast` exactly as before, and CI is untouched — a PR runs there whatever it ran before this helper existed.

## Why all four clippy flags are there

**All four flags are load-bearing** — `--all-targets` and `--features e2e` per issue #407, `--workspace` per issue #436, `e2e-live` per issue #502 (the paragraph on it below). The rule before issue #407 said `cargo clippy -- -D warnings`, which type-checks *no test file at all*: without `--all-targets` cargo builds only lib and bin targets, and every `tests/e2e_*.rs` file opens with a `feature = "e2e"` cfg (a minority add a `unix` term, and the lane-2 files add `feature = "e2e-live"`), so without `--features e2e` they compile to empty crates. An e2e-only change therefore passed the gate instantly and meaninglessly — measured by injecting a deliberate `E0308` into `tests/e2e_handshake.rs`: `cargo clippy -- -D warnings` and `cargo clippy --all-targets -- -D warnings` both exited 0, and only the feature-enabled command caught it. `cargo fmt --check` is *not* affected — rustfmt is cfg-blind and walks the cargo target list, so it has always covered these files.

## Why the command is a strict superset of the old one

The one command is a strict superset of the old one, and here is the accurate version of why — the claim that used to sit in CLAUDE.md rule 2 ("no `not(feature = "e2e")` or `not(feature = "e2e-live")` cfg exists anywhere, and `src/` never references either feature") was simply false, and had been since before `e2e-live` existed. `src/` **does** reference `e2e`, in `#[cfg]` attributes across several files; count them with `git grep -n '#\[cfg(.*feature = "e2e"' -- src` rather than trusting a number here, since this sentence once said five and line numbers beside them, and both went stale (13 attributes on 2026-10-03). Most only *add* test seams, but two are genuine feature-off arms (`git grep -n 'not(feature = "e2e")' -- src`): the `not(feature = "e2e")` arm of `effective_current_exe` in `src/platform/paths.rs`, which is exactly the point of gating that test seam on a feature instead of an env var (read the doc comment above it), and the Unix-only `all(unix, not(feature = "e2e"))` arm of `legacy_endpoint_root` in the same file. So `--features e2e` does not merely *add* code to `src/`: it swaps those two functions. What holds, and what the superset argument actually needs, is the narrower fact: **no `not(feature = "e2e-live")` cfg exists anywhere and nothing under `src/` references `e2e-live` at all** (`grep -rn 'feature = "e2e-live"' src/` is empty), so adding `e2e-live` to a command that already passed `e2e` can only widen what is compiled. The `e2e` half rests on something different, and it is not "nothing is swapped": each feature-off arm is a one-expression fallback (`std::env::current_exe()`, and `PathBuf::from(LEGACY_ENDPOINT_ROOT)`), and each is still clippy-linted by a required job that stays on bare `cargo clippy -- -D warnings` (paragraph below) and therefore lints precisely the feature-off configuration this command does not: `build-macos` lints both, `build-windows` only the first, since the second is `cfg(unix)`. So every arm is covered across the required jobs, just never by one command, which is worth knowing before writing a `not(feature = "e2e")` block with anything substantial in it. It is also **cheap**: cargo caches the feature-on and feature-off fingerprints side by side, so alternating this with `cargo test-fast` costs ~0.2s warm; a from-scratch re-check of every e2e target was ~14s when there were 62 of them (unremeasured since). **Re-measured 2026-08-31 and that "~0.2s warm" does not hold as an absolute cost, though the property behind it does.** Warm, back to back, 16 cores, all three runs `--workspace`: this command takes **9.3–10.4s** and the bare `cargo clippy -- -D warnings` takes **3.8–4.4s**, and neither ever reaches a no-op — both print `Compiling dot-agent-deck` every time, because `build.rs` watches `.git/index` for build-id freshness (PRD #103) and that file moves constantly. What survives is the part the claim was really about: running this straight after `cargo nextest list --workspace` costs 10.4s against its own 9.5s floor rather than a full re-check, so the two feature configurations genuinely do not evict each other. The ~5.5s over the bare command is re-linting the `tests/e2e_*.rs` targets, which is the whole point of the flags. `bacon.toml`'s `[jobs.clippy]` carries the same command and the same measurement.

## A type-check and lint, not the e2e tier

This is a *type-check and lint*, not the e2e tier — it spawns no binaries and hits no LLM APIs, so naming the e2e features here does not put either e2e lane into this gate — in particular it does not run a single credentialed test, and never did (CLAUDE.md rule 5 has the lanes). Before this change, e2e code was clippy-linted by no gate anywhere and type-checked only by `cargo test-e2e`, which at the time ran nowhere but a contributor's own machine. The Linux CI `build` job runs the same command; `build-windows` / `build-macos` deliberately stay on bare `cargo clippy -- -D warnings` (see the comments there — the L2 tier is Unix-only and reports dozens of E0425s under the Windows target).

## `--workspace` (issue #436)

**`--workspace` covers the `xtask/*` members** (issue #436). Cargo's default target selection is the root package alone, so `xtask/docs`, `xtask/linkage-check` and `xtask/spec` were linted by no gate anywhere. `xtask/spec` and `xtask-docs` are path dev-dependencies so they were at least *built*, but building is not linting, and `xtask/linkage-check` was not even built — which is how an `unnecessary_sort_by` sat in its `clean_tmp.rs` on `main` long enough to be discovered by an unrelated PR. That lint was fixed in the same commit that added this flag, so the widened gate landed green. The widening is **free warm**: measured back to back, `--workspace` and root-only both return in 0.20s once cargo has the fingerprints, since the three `xtask` members are small and dependency-light. Note `--workspace` does **not** change which features reach the root package, so this stays a strict superset of the pre-#436 command.

## `e2e-live` (issue #502)

**`e2e-live` is now the ONLY thing in CI that type-checks a third of the tier** (issue #502). The split moved the real-agent files to `#![cfg(all(feature = "e2e", feature = "e2e-live"))]`, so under `--features e2e` alone every one of them compiles to an **empty crate** — the #407 hole reopened, just narrower, and the same hole class #436 and #489 each closed in their own corner. Measured exactly the way #407 was, by injecting a deliberate `E0308` into `tests/e2e_dispatcher_mode.rs` (a file that moved into the live set): `cargo clippy --workspace --all-targets --features e2e -- -D warnings` exited **0** and reported nothing, while the same command with `--features e2e,e2e-live` exited **101** and reported the `E0308`.

**This flag was originally justified by the credentialed CI lane existing. That lane is gone, and the flag matters MORE, not less — the justification inverted rather than weakened.** While lane 2 ran in CI, a type error in those files would eventually have been caught by the lane itself, and this command merely caught it sooner. Nothing in CI runs them now: no test that reaches a real agent runs on a runner (CLAUDE.md rule 5 has the decision and the two reasons). So this one command is the **entire** CI-side coverage of the lane-2 files — **26 of the tier's 79 when last counted, on 2026-09-10**, a third of it. That is the one count in CLAUDE.md rule 2 that was kept as a number rather than reworded, because here the size *is* the argument; recount it with the commands in [`e2e-lanes.md`](e2e-lanes.md) rather than trusting this sentence (issue #900). Its failure mode without the flag is silent: clippy exits 0 having compiled nothing, and the break surfaces whenever some developer next runs `cargo test-e2e-live`, which may be weeks. **Do not "simplify" `e2e-live` out of this command.** It costs nothing at run time (it is a type-check and a lint — it spawns no binary, hits no API, and needs no credential; naming an e2e feature here has never put an e2e lane into this gate) and it is the last line of defence for the files CI otherwise never sees.

`cargo fmt --check` was separately proven unaffected for the reason given above — a formatting violation inside a live-gated file was caught by bare `cargo fmt --check` with no features at all, because rustfmt walks the cargo target list and is cfg-blind. The Linux CI `build` job runs the same two-feature command; `build-windows` / `build-macos` still stay on bare `cargo clippy -- -D warnings`, and that divergence is untouched by this — it is caused by `--all-targets --features e2e` against the Windows target, and adding a second feature to a command those jobs do not run changes nothing for them.
