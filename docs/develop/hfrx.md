# H-FRX: contained, opt-in M-FR-X tooling

H-FRX is opt-in local measurement tooling for PRD #1666, Q35-29, implementing parts of the containment and evidence contracts in core amendments 5 §3.5 and 6 §3.6/U3. It lives in `scripts/hfrx/`; credential-free self-checks have a Linux lane-1 wrapper, while real-agent measurement requires separate local authorization. It changes no production code. This revision has been self-checked with stand-ins; no real measurement has been run. The current task authorizes writing and self-checking it only. Review and a subsequent explicit run instruction are still required before `run-x2`.

## Rows and dependencies

`python3 scripts/hfrx/hfrx.py plan` prints the machine-readable inventory, including the editor setups and every M-FIRST field. “Runnable now” means the executable driver can measure Codex itself without part-3 daemon changes, once pins are supplied and execution is separately authorized; its real-agent behavior remains unverified until that run. “Needs implementation” means this revision provides the evidence contract or reducer, but deliberately provides no executable driver for that row. These are dependencies, not zero counts or successful measurements.

## Self-check and dry run

These commands start no agent. The unittest suite uses fixture files, mocked subprocess calls, synthetic capture/trace data and one detached Python stand-in process tree to verify pidfd/subreaper cleanup. `harness/hfrx/001` (`hfrx_001_offline_safety_controls`) runs this suite in Linux deterministic lane 1, outside the fast tier because its process-tree control sleeps. Missing Python, writable `/var/tmp`, Linux pidfd or subreaper support fails the check; it does not produce a green skip. Self-check fixtures deliberately mock disk-backing metadata so CI overlay storage can host stand-in files. The disk-preflight implementation is exercised separately with accepted ext4 and refused tmpfs mount fixtures; this does not relax the measurement driver's real mount check. The dry run hashes any supplied pins, constructs a fresh fixture git repository and allowlisted environment, checks refusals, writes a plan, then stops before subprocess, namespace, mock-provider, daemon or editor startup. An empty pin map is valid for this preflight-only action; it is refused by the measurement driver.

```console
python3 -m unittest discover -s scripts/hfrx -p 'test_*.py' -v
python3 scripts/hfrx/hfrx.py plan
python3 scripts/hfrx/hfrx.py dry-run --root ../dot-agent-deck-p3-measure/runs/unique-id --pins /absolute/path/to/pins.json
```

Pins are a JSON object mapping fixture names to absolute executable paths and SHA-256 digests, for example `{"python3":{"path":"/absolute/path/to/python3","sha256":"64 lowercase hex digits"}}`. X2 requires `python3`, `strace` and each selected `codex-<release>`; the default selects both 0.160.0 and 0.164.0. A small pilot can select one release with `--release 0.164.0 --samples 10`; that means ten total startups. Namespace prevention additionally needs `unshare`, `ip` and `true`. Symlinks to those explicitly pinned executables are installed only in `<run>/bin`, the only PATH directory. Executable bytes are checked again immediately before a run. Operators must independently verify the release identity behind each Codex pin; a filename is not version evidence. `run-authorization.json` records the executing script's SHA-256 alongside the supplied reviewed commit, selected releases, samples per release and namespace requirement. That commit is operator attestation, not verification that the current checkout matches it. These hashes do not pin Python imports, dynamic libraries, shebang interpreters or a symlink target replaced after the check, and Codex's interpretation of EDITOR/VISUAL remains an indirect launch boundary. The harness does not download binaries or images.

The run root is a fresh, uid-owned 0700 disk-backed directory, normally `../dot-agent-deck-p3-measure/runs/<short-id>/`. Its Unix socket paths must fit the platform limit. Both `<run>/work` and `<run>/home` are walked to `/`; a `.dot-agent-deck.toml` anywhere in either ancestry is refused except for the tool's exact fixture file. An auth.json in CODEX_HOME, changed fixture configuration, non-bin symlinks, production/non-run socket overrides and inherited environment additions are refused. The disk preflight recognizes ext2/3/4, xfs, btrfs, zfs and f2fs from Linux mount metadata; it refuses tmpfs, ramfs and other filesystem types, overlay included, rather than inferring their backing store. A root under the real HOME's .codex/.claude directories is refused before creation. Production endpoint comparisons include runtime, per-uid fallback and legacy spellings from `src/platform/paths.rs`; the preflight also rejects endpoint paths outside the run and does not open or connect to them. The test suite's “production socket” is a stand-in path, not the actual daemon.

The constructed environment contains PATH, TERM, LANG, HOME, CODEX_HOME, the XDG config/data/state/cache/runtime paths, the run-owned deck state/socket/attach/log paths, pinned experimental presentation and idle shutdown disabled. X2 adds only its run-owned EDITOR/VISUAL invocation. It inherits no OPENAI_API_KEY, ANTHROPIC_API_KEY, SSH_AUTH_SOCK, DBUS_SESSION_BUS_ADDRESS, DISPLAY or WAYLAND_DISPLAY. Its fixture config disables update checks and analytics and names only a run-owned loopback mock provider with `sk-fixture-not-a-key`. It never reads the real `~/.codex` or `~/.claude` directories. The explicit PTY CPR responder returns a fixed 1;1; these measurements are not evidence about production CPR handling.

## Network and host boundary

After a separately authorized real-run instruction, the outer subreaper probes `unshare --user --net --map-root-user --fork true` using pinned tools. When that succeeds, the measurement supervisor, mock provider, Codex and its trivial editor run together in a fresh user/network namespace; `ip link set lo up` runs inside it. There is no host veth or route setup. If support/tools are unavailable, the default run is labelled **detection-only**. Use `--require-namespace` to refuse before starting the measurement supervisor, provider or Codex instead of falling back; the probe itself can still run. Without that flag, explicitly accept detection-only fallback before execution. The containment label stays in both authorization metadata and row results. No namespace probe happens during the dry run or unit tests.

Connect tracing detects attempts; it does not prevent them. Each retained trace is checked for the exact mock IPv4 address/port or an absolute AF_UNIX path beneath `<run>/`; foreign, abstract, malformed or otherwise undecodable endpoints make containment UNVERIFIED and stop the series, failed connects included. A connect trace does not establish that untraced syscalls or preexisting descriptors could not communicate. Namespace rows prevent ordinary external IP reachability; neither HOME/XDG isolation nor network namespaces isolate host filesystem paths or host AF_UNIX endpoints. A copied configuration/plugin can still name and modify absolute host paths. A later real-editor driver must accept only user-named copies into `<run>/home`, record the copy's identity, and require the user to read that copy before execution. Scrubbed artifacts do not prove absence of host side effects.

## Processes, editors and containers

The Linux supervisor sets PR_SET_CHILD_SUBREAPER before starting a child and captures a pidfd for each child it starts. Cleanup enumerates reparented children through `/proc/<root>/task/*/children` before and after signalling, so a descendant adopted after its TERM-resistant parent's final KILL gets another capture/signal pass. TERM has a 2 s observation budget and KILL a 1 s budget. Reaping is nonblocking, capped at 4,096 waits per pass and checked against the phase deadline. A verified-empty result requires both an empty captured live set and waitpid reporting no children; deadline exhaustion or cleanup errors report `survivors: null`, `survivors_status: "unknown"` and the last captured survivor set separately. The distinction is covered by a deterministic final-KILL adoption control and mocked unsettled-child/error controls. Repeated SIGTERM/SIGINT are ignored during provider shutdown and cleanup; cleanup attempts remaining operations after expected OS errors, closes captured pidfds and writes PID-qualified survivor/error reports even on a failed series. Unknown survivors also print an operator-visible UNVERIFIED notice. Filesystem failure can still prevent artifact creation. Signals use pidfd_send_signal. It uses no sudo or pattern kill. A per-sample strace process is stopped by its captured pidfd. PTY/session setup runs in a fresh Python interpreter after exec, avoiding a Python `preexec_fn` callback in the threaded provider process. The outer supervisor's timed wait encompasses inner startup and the sample series (10 + 36 × selected releases × samples seconds); it does not bound the outer Popen call, provider shutdown, cleanup or an uninterruptible kernel operation. This tooling's execution support is Linux; a macOS equivalent is still UNVERIFIED, while the M-FIRST schema/reducer accepts macOS observer records.

The unused container primitive has been removed: a prospective generated name did not prove ownership and cleanup could delete a preexisting container after a creation collision. Container editor rows need implementation of a creation primitive that captures a proven-new immutable container ID before registering cleanup ownership, with collision, creation-failure and cancellation controls. It must retain `--pull=never` and `--network=none` and remove by the captured identity in an explicitly chosen run-owned store. No Podman operation is available in this revision. Emacs rows must start their own run-unique daemon/server socket under `<run>/`, with a client naming that socket; nvim's LSP must be a run-owned stdio stub. Those row drivers are implementation dependencies, not substitutes using existing host servers.

## Evidence contract for the pending drivers

The disposable daemon uses the branch binary with its state, log and two sockets under the same run root. An Authority override must be compiled into an e2e build only, unavailable in a production build, scoped to that daemon and used for X3 alone. Hold stays the default and X4 never enables Authority. The current revision does not invent an environment variable or protocol for these unfinished seams and does not start a daemon. The later adapter must prove those seams before changing any row label.

Frontier and EC records need generation identity, checked byte offset, CLOCK_MONOTONIC and CLOCK_REALTIME. X1's driver must retain the helper report, missing/late frontier classification, full 10 s quiet-stand-in observation, time of each foreign marker and orphan-group SIGHUP/SIGCONT, including unavailable editors. No frontier means no qualified negative. The X1 reducer requires the same explicit `population` object (`setup`, `release`, `method`, `containment`, `harness_revision`) on each input record and refuses mixed populations or more than 100,000 records. Unknown helper reports can contribute qualified full post-frontier byte-observation windows; `zero_in_n` describes foreign bytes during those windows, not a Clean helper verdict. The current reducer retains aggregate marker incidence and frontier latencies; per-marker/orphan timing remains a future driver's evidence. X3 needs gate-entry, genuine-enable offset, writer acknowledgement, EC evaluation and gate-release evidence. X4 needs the same clocks and byte offsets, a direct-incidence verdict separate from a calibration verdict, and a distinct unknown-order count. None-in-N uses the rule-of-three bound (approximately 3/N) for that exact population. It predicts neither another setup nor future sessions.

For a taken X1 frontier, `window_ns` must be a nonnegative signed-64-bit integer, at least 10,000,000,000 ns; booleans, fractional/nonfinite floats and strings are refused. `standin_silent`, `orphan_sighup` and `orphan_sigcont` must be booleans. Silence must be true to qualify a window. These schema checks validate the supplied fields, not the future observer's factual accuracy.

M-FIRST consumes JSONL with these fields. Each is **needs implementation: Q35-07 observer**, rather than available data:

| Field | Meaning |
| --- | --- |
| platform, generation | Linux/macOS and an opaque generation identity, without paths or message content |
| duration_ns | Observed generation duration, including a generation ending without a stop |
| first_stop_ns | Spawn-to-first-actual-stop elapsed time, or null when censored |
| cause | NativeEditor, CheckEditor, ToolEditor, ShapeEditor, UnknownEditor, UnarmedThenSpawnFailed, Survivors, UnknownReport, DroppedObservation, EditorUnconfirmed or ScanDroppedAtCap; null when censored |
| attribution | Owned, NotOwned, Unattributable or Pending; the pending observer adapter must preserve the final seam's vocabulary |
| held_input_discarded_at_restart | Whether held input was discarded at the restart; null if not yet observed |
| pending_count | Total Pending episodes; these episodes are not stopping events |
| pending_median_ns, pending_max_ns, pending_median_method | Integer nanosecond aggregates with median ≤ maximum ≤ generation duration; this offline contract accepts exact/fixture-exact. With zero episodes, both durations are null and method is none. Approximate methods need an explicit reviewed adapter/validation extension before consumption |
| pending_resolutions | Counts for Armed, Unarmed, Tool and ExitNoDecision; must sum to pending_count |

Pending→Armed counts the avoided amendment-5 scan-order taint. Pending holds until a decision or retirement; its duration is not silently classified as a first stop. `summarize-first` retains censored generations and reports a null Kaplan–Meier median when survival never reaches one half. It refuses duplicate or invalid generation IDs, bool/fractional/nonfinite counts and durations, unknown attribution/method values and nonboolean restart-discard states (null means unknown). Numeric fields are nonnegative signed-64-bit integers. It caps records at 100,000 and retains bounded per-generation Pending aggregates/methods, attribution counts and restart-discard counts, with no per-episode history. The observer remains unimplemented; these validations do not establish its factual accuracy. Use one platform per analysis and observe a week's actual use before claiming a normal duration. “Milliseconds normally” is still an expectation, not evidence.

## Artifacts and export

Raw master captures, chunk clock JSONL, per-pid strace files, per-sample JSON, row summaries and cleanup reports stay below `<run>/`. The executable X2 driver stops at an unverified cycle or containment detection rather than extending a misleading series. A fresh run id is required for a repeat. Do not export raw artifacts directly.

`python3 scripts/hfrx/hfrx.py export <run> <fresh-destination>` scans the selected run's regular files for key-shaped strings, including decoded strace hex/plain literals. It scans individual literals, their conservative concatenation in file order without newline separators, and decoded write/writev payloads concatenated per fd within each file. This catches splits across iovecs or successive writes even when another fd writes an intervening newline. Payloads are scanned conservatively, including unsuccessful writes; fd reuse can cause false positives. It does not reconstruct fd aliases, unfinished/resumed calls, streams across separate files or arbitrary encodings. The exact fixture-key exemption is applied after reconstruction, so an appended secret tail is refused. Limits are 16 MiB per file, 64 MiB aggregate input, 4,096 files, 100,000 decoded literals and 1,024 write streams per file; exceeding a limit refuses export before destination creation. It repeats preflight, refuses symlinks outside the fixture bin, and rejects a destination under the real agent configuration directories. A scrubber is a heuristic, not a proof that arbitrary secrets are absent; inspect the export before sharing. The scan makes no claim about host side effects.

Export checks destination ancestry for symlinks before resolving the path, then checks the resolved destination against the agent-configuration locations and the resolved run root. This refuses `..` aliases into those locations, symlink/`..` spellings and dangling symlink ancestors before creating the export. It is a path-input safeguard, not protection against concurrent same-user filesystem replacement.

## Requirements and estimated budget for a later run

Intended Codex model spend is zero, conditional on the trusted pinned tools following the configured fake-key local-mock path. Configuration isolation is not host filesystem confinement: same-user tools can still reach host paths and AF_UNIX sockets, and detection-only fallback may attempt a connection before trace inspection. A successful namespace run prevents ordinary external IP reachability, not host-file access. Prefer a separately authorized small X2-arrival pilot with successful namespace isolation before estimating a larger series; any detection-only fallback needs explicit disclosure and authorization. Use a disposable VM without production sockets/configuration/credentials when stronger host isolation is required. The user's real editor configurations, host namespace support and local image availability still affect future rows. Claude rows require a separately authorized lane-2 run with the developer's own credential path and real Claude binary; the present runner neither accepts nor copies that credential. Estimate that cost separately once the number of real Claude interactions and model are chosen.

Have the two verified Codex release binaries, Python 3.11+ with pidfd support, strace, and (for namespace prevention) unshare, ip and true already installed and pinned. Later rows additionally need the branch e2e daemon/helper, reviewed gate supervisor and requested editors, Emacs/LSP fixtures and preloaded rootless-container images. User namespaces may be disabled by the host; the current dry run deliberately does not probe them. No sudo, image pull or binary download is part of H-FRX.

Budget estimates are planning arithmetic, not measured durations: X1's 50×10 s windows impose at least 8 min 20 s per setup, before editor startup/exit; X4 adds 70 editor interactions per setup. The planned two-method X2 inventory is 400 fresh Codex startups/editor returns across two releases, with up to 3 h 20 min of 30-second cycle waits alone, plus startup, parsing and teardown. Only arrival is currently offered (200 samples at the full inventory); instrumented remains blocked. A failed/unverified cycle stops the series early. The outer inner-process wait timeout is additional protection, not a whole-run hard deadline. X3's gate can add up to 2 s per calibration trial; a count must be selected before estimating its total. M-FIRST spans a week of ordinary use. There is no basis yet for a measured expected duration or a Claude dollar estimate.
