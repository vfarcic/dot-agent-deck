# H-FRX: contained, opt-in M-FR-X tooling

H-FRX is local lane-2 measurement tooling for PRD #1666, Q35-29, implementing the containment and evidence contracts in core amendments 5 §3.5 and 6 §3.6/U3. It lives in `scripts/hfrx/` because the plan assigns a measurement gate rather than a Rust test ID, and the tool needs Linux namespaces, pidfds, external pinned binaries and trace artifacts. It changes no production code. This revision has been self-checked with stand-ins; no real measurement has been run. The current task authorizes writing and self-checking it only. Review and a subsequent explicit run instruction are still required before `run-x2`.

`python3 scripts/hfrx/hfrx.py plan` prints the machine-readable inventory, including the editor setups and every M-FIRST field. “Runnable now” means the executable driver can measure Codex itself without part-3 daemon changes, once pins are supplied and execution is separately authorized; its real-agent behavior remains unverified until that run. “Needs implementation” means this revision provides the evidence contract or reducer, but deliberately provides no executable driver for that row. ## Self-check and dry run

These commands start no agent. The unittest suite uses fixture files, mocked subprocess calls, synthetic capture/trace data and one detached Python stand-in process tree to verify pidfd/subreaper cleanup. The dry run hashes any supplied pins, constructs a fresh fixture git repository and allowlisted environment, checks refusals, writes a plan, then stops before subprocess, namespace, mock-provider, daemon or editor startup. An empty pin map is valid for this preflight-only action; it is refused by the measurement driver.

```console
python3 -m unittest discover -s scripts/hfrx -p 'test_*.py' -v
python3 scripts/hfrx/hfrx.py plan
python3 scripts/hfrx/hfrx.py dry-run --root ../dot-agent-deck-p3-measure/runs/unique-id --pins /absolute/path/to/pins.json
```

Pins are a JSON object mapping fixture names to absolute executable paths and SHA-256 digests, for example `{"python3":{"path":"/absolute/path/to/python3","sha256":"64 lowercase hex digits"}}`. X2 requires `python3`, `strace`, `codex-0.160.0` and `codex-0.164.0`; namespace prevention additionally needs `unshare`, `ip` and `true`. Symlinks to those explicitly pinned executables are installed only in `<run>/bin`, the only PATH directory. Executable bytes are checked again immediately before a run. Operators must independently verify the release identity behind each Codex pin; a filename is not version evidence. The harness does not download binaries or images.

The run root is a fresh, uid-owned 0700 disk-backed directory, normally `../dot-agent-deck-p3-measure/runs/<short-id>/`. Its Unix socket paths must fit the platform limit. Both `<run>/work` and `<run>/home` are walked to `/`; a `.dot-agent-deck.toml` anywhere in either ancestry is refused except for the tool's exact fixture file. An auth.json in CODEX_HOME, changed fixture configuration, non-bin symlinks, production/non-run socket overrides and inherited environment additions are refused. The disk preflight recognizes ext2/3/4, xfs, btrfs, zfs and f2fs from Linux mount metadata; it refuses tmpfs, ramfs and other filesystem types, overlay included, rather than inferring their backing store. A root under the real HOME's .codex/.claude directories is refused before creation. Production endpoint comparisons include runtime, per-uid fallback and legacy spellings from `src/platform/paths.rs`; the preflight also rejects endpoint paths outside the run and does not open or connect to them. The test suite's “production socket” is a stand-in path, not the actual daemon.

The constructed environment contains PATH, TERM, LANG, HOME, CODEX_HOME, the XDG config/data/state/cache/runtime paths, the run-owned deck state/socket/attach/log paths, pinned experimental presentation and idle shutdown disabled. X2 adds only its run-owned EDITOR/VISUAL invocation. It inherits no OPENAI_API_KEY, ANTHROPIC_API_KEY, SSH_AUTH_SOCK, DBUS_SESSION_BUS_ADDRESS, DISPLAY or WAYLAND_DISPLAY. Its fixture config disables update checks and analytics and names only a run-owned loopback mock provider with `sk-fixture-not-a-key`. It never reads the real `~/.codex` or `~/.claude` directories. The explicit PTY CPR responder returns a fixed 1;1; these measurements are not evidence about production CPR handling.

## Network and host boundary

After a separately authorized real-run instruction, the outer subreaper probes `unshare --user --net --map-root-user --fork true` using pinned tools. When that succeeds, the measurement supervisor, mock provider, Codex and its trivial editor run together in a fresh user/network namespace; `ip link set lo up` runs inside it. There is no host veth or route setup. If support/tools are unavailable, the run is labelled **detection-only**. This label stays in both authorization metadata and row results. No namespace probe happens during the dry run or unit tests.

Connect tracing detects attempts; it does not prevent them. Each retained trace is checked for the exact mock IPv4 address/port or an absolute AF_UNIX path beneath `<run>/`; foreign, abstract, malformed or otherwise undecodable endpoints make containment UNVERIFIED and stop the series, failed connects included. A connect trace does not establish that untraced syscalls or preexisting descriptors could not communicate. Namespace rows prevent ordinary external IP reachability; neither HOME/XDG isolation nor network namespaces isolate host filesystem paths or host AF_UNIX endpoints. A copied configuration/plugin can still name and modify absolute host paths. A later real-editor driver must accept only user-named copies into `<run>/home`, record the copy's identity, and require the user to read that copy before execution. Scrubbed artifacts do not prove absence of host side effects.

## Processes, editors and containers

The Linux supervisor sets PR_SET_CHILD_SUBREAPER before starting a child and captures a pidfd for each child it starts. Cleanup also enumerates reparented children through `/proc/<root>/task/*/children`, captures their pidfds, sends TERM, waits up to 2 s, sends KILL, then makes one bounded 1 s observation. It reports remaining captured processes without chasing them. Signals use pidfd_send_signal. It uses no sudo or pattern kill. A per-sample strace process is stopped by its captured pidfd. This tooling's execution support is Linux; a macOS equivalent is still UNVERIFIED, while the M-FIRST schema/reducer accepts macOS observer records.

The container primitive requires a pinned podman, checks `image exists`, generates its own run-unique names, and uses `run --pull=never --network=none`. It never accepts an existing user container name. Cleanup invokes `podman rm -f` with each generated name as a direct argv, with a bounded wait and survivor report. No container operation was executed by the self-check. Future namespace-escape rows must run only inside those run-owned containers, with removal as the escape cleanup boundary. Emacs rows must start their own run-unique daemon/server socket under `<run>/`, with a client naming that socket; nvim's LSP must be a run-owned stdio stub. Those row drivers are implementation dependencies, not substitutes using existing host servers.

## Evidence contract for the pending drivers

The disposable daemon uses the branch binary with its state, log and two sockets under the same run root. An Authority override must be compiled into an e2e build only, unavailable in a production build, scoped to that daemon and used for X3 alone. Hold stays the default and X4 never enables Authority. The current revision does not invent an environment variable or protocol for these unfinished seams and does not start a daemon. The later adapter must prove those seams before changing any row label.

Frontier and EC records need generation identity, checked byte offset, CLOCK_MONOTONIC and CLOCK_REALTIME. X1's driver must retain the helper report, missing/late frontier classification, full 10 s quiet-stand-in observation, time of each foreign marker and orphan-group SIGHUP/SIGCONT, including unavailable editors. No frontier means no qualified negative. X3 needs gate-entry, genuine-enable offset, writer acknowledgement, EC evaluation and gate-release evidence. X4 needs the same clocks and byte offsets, a direct-incidence verdict separate from a calibration verdict, and a distinct unknown-order count. Summaries group by setup, release, method, containment label and harness commit; none-in-N uses the rule-of-three bound (approximately 3/N) only for that exact population. It predicts neither another setup nor future sessions.

M-FIRST consumes JSONL with these fields. Each is **needs implementation: Q35-07 observer**, rather than available data:

| Field | Meaning |
| --- | --- |
| platform, generation | Linux/macOS and an opaque generation identity, without paths or message content |
| duration_ns | Observed generation duration, including a generation ending without a stop |
| first_stop_ns | Spawn-to-first-actual-stop elapsed time, or null when censored |
| cause | NativeEditor, CheckEditor, ToolEditor, ShapeEditor, UnknownEditor, UnarmedThenSpawnFailed, Survivors, UnknownReport, DroppedObservation, EditorUnconfirmed or ScanDroppedAtCap; null when censored |
| attribution | Attribution of that stopping observation |
| held_input_discarded_at_restart | Whether held input was discarded at the restart; null if not yet observed |
| pending_count | Total Pending episodes; these episodes are not stopping events |
| pending_median_ns, pending_max_ns, pending_median_method | Duration aggregates and the median's method/precision; the future observer must aggregate with bounded memory and disclose approximations |
| pending_resolutions | Counts for Armed, Unarmed, Tool and ExitNoDecision; must sum to pending_count |

Pending→Armed counts the avoided amendment-5 scan-order taint. Pending holds until a decision or retirement; its duration is not silently classified as a first stop. `summarize-first` retains censored generations and reports a null Kaplan–Meier median when survival never reaches one half. It caps records at 100,000 and retains no per-episode history. Use one platform per analysis and observe a week's actual use before claiming a normal duration. “Milliseconds normally” is still an expectation, not evidence.

## Artifacts and export

Raw master captures, chunk clock JSONL, per-pid strace files, per-sample JSON, row summaries and cleanup reports stay below `<run>/`. The executable X2 driver stops at an unverified cycle or containment detection rather than extending a misleading series. A fresh run id is required for a repeat. Do not export raw artifacts directly.

`python3 scripts/hfrx/hfrx.py export <run> <fresh-destination>` scans the selected run's regular files for key-shaped strings, including decoded strace hex strings, exempts exactly the fixture key and refuses the entire export before copying on a match. It repeats preflight, refuses symlinks outside the fixture bin and oversized artifacts, and rejects a destination under the real agent configuration directories. A scrubber is a heuristic, not a proof that arbitrary secrets are absent; inspect the export before sharing. The scan makes no claim about host side effects.

The user's real editor configurations, host namespace support and local image availability still affect what can be verified. Estimate that cost separately once the number of real Claude interactions and model are chosen.

Have the two verified Codex release binaries, Python 3.11+ with pidfd support, strace, and (for namespace prevention) unshare, ip and true already installed and pinned. Later rows additionally need the branch e2e daemon/helper, reviewed gate supervisor and requested editors, Emacs/LSP fixtures and preloaded rootless-container images. User namespaces may be disabled by the host; the current dry run deliberately does not probe them. No sudo, image pull or binary download is part of H-FRX.

Budget estimates are planning arithmetic, not measured durations: X1's 50×10 s windows impose at least 8 min 20 s per setup, before editor startup/exit; X4 adds 70 editor interactions per setup; X2 has 400 return samples across two releases and two methods, with a 30 s per-cycle timeout (up to 3 h 20 min for cycle waits alone, normally expected to be much less). X3's gate can add up to 2 s per calibration trial; a count must be selected before estimating its total. M-FIRST spans a week of ordinary use. There is no basis yet for a measured expected duration or a Claude dollar estimate.
