# Synthetic composer external editing

Set `DOT_AGENT_DECK_TEST_COMPOSER_EXTERNAL_EDIT=1` to enable Ctrl+G in `empty_composer.py`, `claude_composer.py`, or `codex_composer.py`. Unset, empty, `0`, and other values leave the old input/render path in use. Copy `composer_external_edit.py` beside an installed copy of a composer; the existing Rust fixture installers do this. This companion module is loaded only when editing is enabled. These are trusted test programs; their editor commands run with the fixture's permissions. Use a private HOME, TMPDIR, CODEX_HOME, work directory and endpoints, as their consumers do.

The stand-in with no agent-specific screen uses Claude's export/selection convention for testing; there is no real agent measurement for that synthetic profile. A Ctrl+G exports the current bytes, disables bracketed paste, starts the selected editor with the export as its argument and waits for it, then enables bracketed paste and redraws. Success imports the edited bytes; a failed editor preserves the previous draft. Codex additionally draws `Failed to open editor: editor exited with status exit status: 1` for exit 1 and keeps that line on redraw. Claude does not gain Codex's failed-exit line. Enabled startup emits a paste-mode enable. No timer synthesizes an editor decision or resumption.

The following files beside `base` steer subsequent candidates. They are ordinary test controls, independent of whether an identical input byte came from a human or the deck; the fixture does not infer the source of Ctrl+G.

| Control | Effect |
| --- | --- |
| `.edit-mechanism` containing `H-chunk` | After invoking, discard the suffix of the same `os.read` that contained the candidate. |
| `.edit-mechanism` containing `H-flush` | Immediately before starting the editor, discard queued tty input with `tcflush(TCIFLUSH)`. |
| `.edit-mechanism` containing `H-ignore` | Read and discard tty input during a 500 ms dispatch window. |
| `.edit-delay` present | Read the candidate, wait 500 ms, then dispatch. With no loss mechanism the bytes queued during this delay remain queued. |
| `.edit-drop` present | Drop each candidate without exporting, invoking or emitting a suspension/resumption pair (CX-H). Remove it to permit a later candidate. |
| `.edit-ignore-next` present | Remove this file and ignore one candidate, with no markers or editor. Use it for a human-ignored candidate or Claude's lapse followed by a retry. It confers no knowledge about the byte's source. |
| `.edit-dispatched` | Written with a monotonic timestamp after an accepted candidate is read, before its dispatch delay. The test can send input into the window without guessing when the candidate was read. It is a test witness, not a production protocol. |

The three loss mechanisms are synthetic hypotheses defined in the core design revision 6, section 3.1. The 500 ms dispatch delay, dropped/ignored candidates and non-returning editor are injected conditions. By default a suffix already in the candidate's `os.read` is retained; discarding that suffix requires explicit `H-chunk` injection on each profile, including Codex. This retention matches M44d's sampled Codex BEL/D3/same-frame controls (20/20 retained on each measured release); retaining Claude's suffix is a synthetic no-loss baseline, contrary to that cell's 0/20 retention. Separately, Codex discards unread tty input from its suspended editor interval, implementing M31's observed loss without claiming Codex uses that internal mechanism. A user editor that reads its stdin receives subsequently written keys on the same tty. The fixture restores the original tty flags while the child runs and restores raw mode without a flush on Claude's return.

`composer_test_editor.py` is a reusable editor fixture. Copy it to a private executable path and choose `VISUAL='<executable> <mode> <absolute-base>'`. It appends no shell evaluation. The composer appends the export filename. Modes `fast`, `fail`, and `trim` have no deliberate sleep: they write `EDITED`, exit 1 after writing `EDITED`, or write `EDITED` followed by spaces and a newline. Modes `wait`/`hang` wait without a deadline for `<base>.editor-go`; `read` first reads a line from stdin, saves it in `.editor-input`, then waits for `.editor-go`. Mode `late-hang` publishes `.editor-publish-waiting` and waits without a deadline for `.editor-publish-go` before publishing its PID, then behaves as `hang`; this forces the failure-cleanup publication race. The helper atomically publishes `.editor-started` with its captured pid, argv, original bytes, file mode and three `isatty` booleans; it records no termios flags. `.editor-finished` is a completion witness. Failure cleanup publishes sticky releases for both barriers before reading the PID, supplies a newline for a blocked `read` editor, and keeps the composer alive while waiting up to three seconds for child exit/reaping. If a published child remains, cleanup kills that captured PID and waits up to another three seconds for exit/reaping before stopping its composer; a late publisher sees the release files. These bounds belong to cleanup, not normal hang-mode execution. The immediate-editor control deliberately places the first 50 ms observer scan after the child has exited; it tests an observer that missed the lifetime, not a wall-clock scheduling guarantee on an overloaded host.

The enabled keyboard map copies agent-specific ordinary-composer observations from M44e (`r5wake-measurements/q35m6-m44e-summary.json`):

| Form | Claude 2.1.310 invokes/trials | Codex 0.160.0 and 0.164.0 invokes/trials (each) |
| --- | --- | --- |
| Raw BEL; `CSI 103;5u` | 4/4 each | 4/4 each |
| Press/repeat `CSI 103;5:1u` / `CSI 103;5:2u` | 0/4 each | 4/4 each |
| modifyOtherKeys `CSI 27;5;103~`; uppercase implicit `CSI 71;5u`; uppercase modifyOtherKeys `CSI 27;5;71~` | 4/4 each | 0/4 each |
| Release `CSI 103;5:3u`; uppercase explicit `CSI 71;5:1u`, `CSI 71;5:2u`, `CSI 71;5:3u` | 0/4 each | 0/4 each |

The self-tests pin those sampled invoking and non-invoking cases; these counts establish neither a globally inert set nor behavior in another state, client or release. The empty-screen profile copies Claude's map as a synthetic convention. Split-read scheduling is a synthetic parser control, rather than a claim that M44e measured each split. ESC-prefixed BEL is swallowed here as a synthetic simplification; M44e's composer counts vary (0/4 for Claude and Codex 0.160.0, 2/4 for Codex 0.164.0). A bracketed paste is literal text, with Claude retaining pasted BEL and Codex removing it. This is a limited input fixture rather than the production tokenizer: it does not implement arbitrary keyboard protocols, navigation, Vim undo, cursor insertion, paste placeholders, menus or tool environments.

## Measured sources and limits

The source records below live in the orchestration workspace's gitignored `.dot-agent-deck/`; they are provenance, not files generated by these controls. The fixture self-tests are `composer_001_external_editor_and_input_mechanisms` under the existing `harness/composer/001` entry. They exercise synthetic processes, not actual agents, attestation, a gate or release authority. `SpawnFailed` and `WaitUnknown` remain outcomes of the real editor helper and its existing fault harness (`inbox/probe/067`); this fixture waits for whichever VISUAL executable the test selects and does not fabricate those IPC outcomes.

The marker counts below were measured for actual editor invocations. This fixture also emits a pair if command resolution or its direct editor exec fails; the native marker behavior for those two cases was not measured in the cited records. Use the existing real-helper fault harness for OQ5, rather than treating that fixture convention as native evidence.
