## Mail Stuck Behind an Agent That Only Looks Busy Is Now Shown

When an agent's card shows it thinking or working, the deck waits for it to finish before waking it for its messages, and until now it said nothing however long that took. If the deck missed the end of the agent's turn, the card kept showing it busy while it sat idle, and a worker's report could wait in an orchestrator's inbox for an hour or more with nothing on screen saying so.

Now, when an agent's messages have waited 15 minutes and the agent has sent the deck nothing in that time (no tool use, no status change), its card in the TUI and its tile in the desktop app say `not taken: the agent shows as busy but has sent nothing for a while. Ask it to run dot-agent-deck inbox fetch.` When that agent is an orchestration's start role, the same words appear at the top of the screen in both clients. `dot-agent-deck daemon status` shows `stalled` after the agent's inbox counts, and `daemon status --json` reports `wake_stalled: true` with `wake_hold: "no_activity"`, so a supervising agent can spot it too.

An agent that is really working keeps the words away: any tool use or status change starts the 15 minutes again. If you see them, look at the agent's pane, and if it is idle, ask it to run `dot-agent-deck inbox fetch` and continue.

See [Delivery in the TUI and desktop app](https://agent-deck.devopstoolkit.ai/docs/orchestration.md) for every reason a card gives for waiting messages.
