## Message one standalone agent by name or pane with `inbox send`

`dot-agent-deck inbox send` can now reach one standalone agent when its folder holds several. Before, `--folder` alone was refused as ambiguous whenever two standalone agents shared a folder, such as a `dispatcher` and an `observability` agent in the same project, and there was no way to pick one.

`--name <name>` picks the standalone agent with that name, as the NAME column of `dot-agent-deck roles` shows it, for example `dot-agent-deck inbox send --folder . --name dispatcher --text '…'`. `--pane <pane>` picks the agent in that pane, from the PANE column: a standalone agent or an orchestration's orchestrator, never a worker. Both combine with `--folder`, and an address that still matches several agents is refused as before, listing each one. The ambiguity refusal now suggests `--name` and `--pane`, `roles` accepts the same two filters to preview who a send reaches, and the reply command the deck writes into a message names the sender with `--name` when its folder alone would not reach it.

The new options need a daemon from this release; an older running daemon refuses them with exit status 2 and sends nothing, and `dot-agent-deck daemon restart` moves it onto the new build. See [Messaging an orchestrator from outside](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#messaging-an-orchestrator-from-outside).
