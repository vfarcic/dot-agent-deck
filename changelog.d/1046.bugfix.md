## The desktop toast's dismiss button now works for daemon errors

Clicking the X on a toast raised by a daemon-side failure did nothing, and the message stayed on screen until something else moved the runtime's state. The toast renders when either the app's own `notice` or the runtime's `error` is set, but the dismiss handler cleared `notice` alone — so for an error-sourced message it set an already-empty field, left the string that was actually on screen, and re-rendered the same toast. Since the two sources render identically, whether the X worked depended on which field had filled it, with nothing on screen to tell them apart. Found by clicking it during PRD [#741](https://github.com/vfarcic/dot-agent-deck/issues/741)'s M13 walk; it predates that work.

The handler could not have cleared the error even if it had tried: `useDeckRuntime` held it in `useState` and returned the value without a setter or any equivalent, so the capability was missing rather than merely unwired. The hook now exposes `clearError` and the button clears both halves. Clearing is safe because this error is transient per-action state — an action and a reconnect each drop it before their next attempt — and it is not what the connection banner reads, which is `snapshot.connection` and is untouched here.

`clearError` is a required member of the runtime interface rather than an optional one, so a runtime that cannot clear its error stops type-checking instead of silently reproducing the bug. The fix covers the whole seam: that toast is the only place the runtime's error reaches the screen, and the only toast the app renders.

Two tests cover it, and both fail against the old code: one drives the click against a deck whose error is real state and asserts the toast is gone, and one asserts the hook's `clearError` drops the error a failed action recorded while leaving the connection as it was. A test written against `notice` would have passed against the broken code, which is why nothing caught this earlier.
