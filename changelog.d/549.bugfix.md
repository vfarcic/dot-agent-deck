## Delegation Commands Reach the Deck That Wrote Them

The `delegate`, `work-done` and `pane restart` commands the deck writes for agents — in the orchestrator's context, a worker's task file, a dispatched unit's opening prompt, and the daemon's busy-worker and worker-exited/blocked notices — now name the deck by the absolute path of the running binary instead of a bare `dot-agent-deck`. Those commands run later in the agent's own shell, and a bare name was looked up in that shell's `PATH`, which can differ from the deck's: a login shell that put `~/bin` first could hand a `work-done` to a different, stale `dot-agent-deck`, and the report was lost without an error anywhere.

The commands are now longer — `/home/you/.local/bin/dot-agent-deck work-done …` — and a permission rule written against the bare name, such as a Claude Code allow rule `Bash(dot-agent-deck work-done:*)`, no longer matches them. Write such rules against the path the generated instructions show.

See [Orchestration → Context handoff](https://agent-deck.devopstoolkit.ai/docs/orchestration#context-handoff).
