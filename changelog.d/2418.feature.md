## Agent cards as a tree, with pull requests and issues the deck checked

The desktop Dashboard's Cards view now starts with the agents you started — a dispatcher, an orchestration, an agent on its own — instead of a grid of every agent. Open a card to see the agents it started: a dispatcher's units, an orchestrator's roles, an orchestration a dispatcher started, as deep as they go. The cards in the top row stay in place when statuses change or you open one; an open card's tree is drawn below its row, joined to it by a line. A closed card is coloured by the most urgent status at or under it, with a bar of how many agents under it are in each status and a line such as "4 under it · 1 needs you". **Needs you only** now opens the way to every card that needs you and fades the rest, and keeps opening the way to a card that comes to need you while it is on. The app remembers which cards you opened.

Cards are compact and the same size: name, whether it is a dispatcher, orchestrator, role or agent, its status in the same words as the table and the TUI, **Needs you**, its pull requests and issues, and an issue's labels in their GitHub colours. Click a card's name to open the agent's terminal, as a table row does; click anywhere else on the card to open its overlay. The card's one action is a **Close** button, which asks before closing exactly as **Close** in the overlay does. The agent's summary, progress, next step, agent type, other fields and actions are in the overlay, which now starts with the agent's summary, its questions and a reply box that is always there when the agent takes a reply. The exact text an action sends is shown as a quotation. Pressing an action whose text the agent wrote, such as one it suggested or an answer to its question, now opens a step that shows the whole text, and **Send** there sends it; actions from your catalog still send when pressed.

**Explain** is no longer one of the default card actions. To keep offering it on every card, add it to the `[catalog]` table of your user configuration with `always = true`; the Agent Cards page has the entry to copy. An existing `remove = ["explain"]` keeps working and no longer needs to be there.

When an agent reports a pull request or an issue in its `pull-request` or `issue` field, or another field of either type, the deck looks it up on GitHub with `gh` on the daemon's host and shows what GitHub says: a pull request's state, CI and review, an issue's state and labels. Click a badge to open GitHub's page inside the app, from a stopped agent's card too. **+N** opens the overlay's list of every one when they do not all fit, and a reference the deck could not check says why, such as "no GitHub access" or "not found or private". A number such as `#123` in the agent's other text is not read.

Voice control can open and close a card's tree ("open the dispatcher's tree") and open the pull request or issue on a card ("open the issue on the coder's card"). `dot-agent-deck card list` includes each card's `parent`, `kind`, `rollup` and `checked_refs`. The TUI does not draw the tree. A daemon from an earlier release shows its cards side by side, and says so; update dot-agent-deck on that daemon's machine to get the tree.

See [Agent Cards](https://agent-deck.devopstoolkit.ai/docs/desktop/agent-cards.md).
