## Orchestration Tabs Flag Config Drift on Reattach

Reattaching the TUI to a daemon whose running orchestration no longer matches `.dot-agent-deck.toml` used to rebuild the tab silently, so the role cards stopped matching the file you had just edited and nothing on screen said why. That happens when the orchestration was renamed or removed in the file, and when one of its roles was renamed, removed or re-ordered while the orchestration kept running.

The rebuilt tab is now labelled `[config drift]` in the tab strip for as long as it is open, the status line explains the marker when the tab appears, and a warning is printed when the deck exits. The warning names the orchestration, its directory, the roles the daemon is running and, for a role change, the roles the file now lists. It also says that `dot-agent-deck delegate` still routes to those panes by the role names they were started with, so delegating to a role renamed in the file reaches no pane until the orchestration is restarted. Reconnecting to a remote daemon whose directory has no local config stays quiet, as before. The same check runs when a daemon-dispatched orchestration appears while the TUI is attached.

When `dot-agent-deck delegate` reaches no worker for a role, its error now lists a fourth cause next to the other three: the role was renamed or added in `.dot-agent-deck.toml` after the orchestration started.
