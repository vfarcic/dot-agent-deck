**The daemon now owns each agent's terminal size, and sizes it to the smallest attached client.** Previously every client asserted its own geometry and the last writer won, with no policy and no negotiation — so switching between the TUI and the desktop app left panes wrong-sized until you resized a terminal by hand, and a client could be left parsing an agent's output at a grid the agent was not drawing on.

A pseudo-terminal has exactly one size, so per-client sizing of a live agent is not available: the agent lays out for one answer and draws at absolute positions on that grid. The daemon therefore picks one size — the smallest pane among the clients attached to that agent — and larger clients leave the remainder blank. This is the rule tmux has used for twenty years (`window-size smallest`), for the same reason. The constraint is released when a client detaches, so hiding a small view lets the agent grow back.

**Why this is a compatibility break.** `AttachRequest::Resize` keeps its wire shape but changes meaning: it is now a *request* that the daemon may only partly honour, and it answers with the geometry it actually applied. A client that assumes its request took effect will render at a size the agent is not using. `PROTOCOL_VERSION` moves 8 → 9, and the attach stream gains a `KIND_GEOMETRY` frame that pushes size changes to attached clients — sent only to clients that opted in by declaring a viewport when they attached, so an older client is never sent a frame it would mistake for the end of its stream.

Two behaviours are now expected rather than faults, and both are documented in [Troubleshooting](troubleshooting.md): a pane that does not fill its box while a smaller client is attached to the same agent, and an empty scrollback replay for a client that attaches after a size change.
