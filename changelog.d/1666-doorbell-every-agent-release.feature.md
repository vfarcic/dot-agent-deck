## The doorbell works with every Claude Code and Codex release, and can be turned off per agent

The deck types its doorbell into every release of Claude Code and Codex, and checks the input box of every Claude Code release it starts directly on Linux, so an agent that updates itself keeps getting its messages without a prompt. A pre-release build, whose version carries a suffix such as `-beta.1` or `-alpha.1`, gets no doorbell and no input-box check: the deck can't read its version, so its card says `waiting for the agent to fetch it. Send it a prompt.` when nothing else delivers its messages.

If an agent update makes the doorbell misbehave (the line lands in the wrong place, Enter isn't taken, or Claude Code's input box flickers or your editor opens on its own), turn it off for that agent until a deck release fixes it: `dot-agent-deck config set doorbell.claude false` or `dot-agent-deck config set doorbell.codex false`. The daemon reads that key each time it starts an agent, so it works with a running daemon and with the desktop app. `DOT_AGENT_DECK_DOORBELL_CLAUDE=0` or `DOT_AGENT_DECK_DOORBELL_CODEX=0` wins over the key, but only in the daemon's own environment when it starts; a daemon that is already running keeps its own. The setting applies to agents started after the change, in the TUI and the desktop app alike. With the doorbell off, the deck types nothing into that agent and doesn't check its input box; its messages arrive through its own wake-up and hooks or at your next prompt, and its card says `waiting for the agent to fetch it. Send it a prompt.` when nothing else delivers them.

See [Orchestration → Turn the doorbell off for an agent](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#turn-the-doorbell-off-for-an-agent) and [Troubleshooting → The doorbell misbehaves after an agent update](https://agent-deck.devopstoolkit.ai/docs/troubleshooting.md#the-doorbell-misbehaves-after-an-agent-update).
