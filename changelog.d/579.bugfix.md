## The `Needs Input` status is readable on a light terminal

The colour that says an agent is waiting for you was yellow, which is the one named ANSI colour that all but disappears on a light terminal background. Measured against white it came to **1.70:1**, and **1.07:1** on terminals that render bold as the bright variant — against the 4.5:1 that WCAG AA asks for, and about as close to invisible as two colours get. Every status surface resolves through one palette role, so the same yellow was carrying the deck card's `Needs Input` badge and border, the embedded pane's border, the stats bar's waiting count and the orchestration tab labels. The status you are least able to afford missing was the hardest one to see.

It is now magenta, which reads on a light terminal and on a dark one. That is a narrower choice than it sounds: contrast against black and contrast against white pull in opposite directions, and the best *any* single colour can do when it has to satisfy both is 4.58:1 — so the answer had to come from measurement rather than taste. Magenta's luminance lands within 3% of that optimum and no other free slot is close; on a terminal whose palette is tuned to its own background it clears AA in both directions (4.69:1 on white, 6.70:1 on black), and even in the bold-as-bright case that produced the 1.07:1 reading it holds 3.14:1, above WCAG's 3:1 floor for non-text interface elements. Red measures as well, and is already the error colour. Nothing else about the status changes — the badge still reads `Needs Input`, still in bold, and every other status keeps the colour it had.

The reason no test caught this is worth naming, because it is the part that could have recurred. The theme tests assert which colour a role resolves *to*, and a constant compares equal to itself however unreadable it is: nothing ever put a foreground and a background in the same equation. A new guard computes the WCAG contrast ratio from whatever the palette actually holds, against a light and a dark terminal and in both the plain and the bold-as-bright rendering, so a future palette edit that lands on an illegible colour fails the fast test suite instead of shipping. The other status hues have the same weakness against a light background to a lesser degree and are a separate decision, since their colours are already spoken for.
