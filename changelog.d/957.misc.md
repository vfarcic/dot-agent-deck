## Column picker dismissal, independent of where focus landed

The agent overview's column picker now closes on Escape through a listener on `document`, alongside the outside-click listener that was already there, instead of through a handler on the picker's own root that saw the key only while focus was inside it.

Clicking the trigger is what put focus inside, and whether a click moves focus to a `<button>` is a property of the browser engine rather than of the app. It does in Chromium and in the WebKit build the browser test tier runs — both measured — while Safari on macOS is documented not to. Whether WKWebView, which is what the packaged macOS app renders in, behaves like either is unmeasured, and nothing has been seen failing anywhere. This change removes the dependency rather than settling the question.

The rest of the picker is untouched: the trigger still toggles rather than reopening, an outside click still dismisses, and Escape raised outside the picker is passed on rather than swallowed, so an overlay that wants the same press still gets it.
