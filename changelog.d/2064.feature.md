## Upgrading the deck also upgrades the resource collector beside it

A resource collector (`dot-agent-deck-collector`) downloaded from a release used to stay on its old version after every deck upgrade until you replaced it by hand, so its figures drifted apart from the deck's runs.

On Linux, when you upgrade a downloaded `dot-agent-deck` from the TUI, with `dot-agent-deck upgrade` or from the desktop app, a release collector in the same directory is now upgraded to the same release and checked the same way as the deck: its checksum, the build provenance when `gh` can check it, and its version. The plan says so before you confirm. When the `dot-agent-deck-collector` systemd user service runs that file, it is restarted; otherwise the result says that a collector you started yourself keeps running the old version until you restart it. In a directory you cannot write, the new collector is downloaded and checked, and the `sudo` command that installs it is shown.

A collector anywhere else, such as one built from source or found elsewhere on your `PATH`, is left alone and the result names it, and with no collector installed the upgrade installs none. Homebrew and Nix installs already upgrade the collector with their package. The collector moves only when the deck beside it does, and the upgrade to this release runs from your older deck, so replace the collector by hand this once. See [Installation → The resource collector after an upgrade](https://agent-deck.devopstoolkit.ai/docs/installation.md) and [Telemetry](https://agent-deck.devopstoolkit.ai/docs/telemetry.md).
