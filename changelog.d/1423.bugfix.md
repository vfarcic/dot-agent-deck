## No Idle-Worker Report for a Task That Never Reached the Worker

When a `delegate` was accepted but its task never reached the worker, the orchestrator was later told that the worker had gone idle on that task. This happened when a `clear = true` worker could not be restarted, when the restarted worker exited before it was ready, or when the deck refused to hand the task to the worker's pane. The report came after `worker_response_timeout_minutes` (two hours by default). The deck now cancels the idle-worker watch as soon as it knows the task was not delivered. A task that was delivered keeps its watch, and so does a newer delegation to the same worker.
