## Desktop app settings, in a file you own

The desktop GUI now has a Settings sheet, and a settings file behind it. The **Settings** button in the rail used to be a stub that opened nothing and showed a toast promising a "local configuration seam"; there was no such seam, and the app had no application-settings mechanism of any kind — the only thing it persisted was four browser-local keys holding project drafts.

Settings opens from that rail button, from the command palette (⌘K, *Open settings*), and closes the way every other sheet in the app closes: Escape, a click on the backdrop, or the close button. The sheet's footer names the file it writes, so "where did that go?" is answerable without reading any documentation.

Your preferences live in `~/.config/dot-agent-deck/desktop.toml`, a sibling of the TUI's own `config.toml` and `keybindings.toml` on the same machine. It is a small, readable TOML document you can open, edit or delete with the app closed, and `DOT_AGENT_DECK_DESKTOP_CONFIG` points the app at a different path if you want one somewhere else — an absolute path naming a regular file, since anything else (a directory, a device, a named pipe, a symlink, a relative path) is refused with a line in the log rather than acted on, and a document over 256 KiB is not read at all. It is written atomically and readable only by you. Nothing in it is worth failing a launch over: a missing, corrupt or unreadable file starts the app cleanly on defaults, and a section written by a newer build of the app survives an older build saving over it. Note that the file is re-rendered when the app writes it, so hand-added comments do not survive a save ([#825](https://github.com/vfarcic/dot-agent-deck/issues/825)).

Everything here is deliberately about *this installation on this machine*, and none of it syncs. That is the boundary the desktop app is built around: it gets the project, the agents and the run from the daemon wherever that daemon runs, and the only thing it owns is its own settings. Credentials are the one thing that will never go in this file — a future setting may record which keychain holds a key, but never the key itself.

The first setting to arrive in it is the light/dark appearance override ([#743](https://github.com/vfarcic/dot-agent-deck/issues/743)). Daemon endpoints ([#741](https://github.com/vfarcic/dot-agent-deck/issues/741)) and the voice backends ([#802](https://github.com/vfarcic/dot-agent-deck/issues/802)) each get their own section when they land.
