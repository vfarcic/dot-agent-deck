## Agents run the deck's own `dot-agent-deck`, not whichever one comes first on their PATH

The doorbell line the deck types into Claude Code and Codex now names the `dot-agent-deck` the deck daemon runs from by its full path, for example `… waiting, run: /home/you/.local/bin/dot-agent-deck inbox fetch`. Before, it named a bare `dot-agent-deck`, so an agent whose own shell found a different, older copy first on its `PATH` ran that copy instead; a copy without `inbox fetch` failed, the message stayed waiting and the deck kept ringing until it reported the task as not delivered. The reply command in a message from an agent outside the team names the deck the same way, as the `work-done` and `delegate` commands in tasks already did.

To have agents use a different copy, start the deck from that copy. `DOT_AGENT_DECK_BIN` still chooses the binary agents' hooks, the OpenCode plugin and the Pi extension run, and does not change the commands the deck writes for agents. See [A deck prompt waits while you have an unsent draft](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#a-deck-prompt-waits-while-you-have-an-unsent-draft).
