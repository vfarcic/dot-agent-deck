## Claude Code confirms each deck message it takes, and the deck, the desktop app and Claude Code's hooks must be upgraded together

The deck now knows when Claude Code has taken a deck message into a prompt, as it already did for OpenCode and Pi. With this release's hooks, a message waiting behind a long Claude Code turn waits for the turn to end instead of being reported not delivered meanwhile. One that may have been lost is sent again, at most twice, marked as a possible repeat. When that still does not settle it, the TUI card and the desktop tile show `✉ delivery uncertain` with **Retry** and **Cancel**, and an orchestrator whose task it is gets `task delivery uncertain`.

This release changes how the deck's parts talk to each other, so a deck or desktop app from 0.47 and a daemon from this release refuse to connect to each other, in either direction, and say which versions they are. Upgrade the deck, the desktop app and the daemon together. On a remote host, upgrade the remote deck before connecting to it from a newer desktop app.

Claude Code's hooks and the daemon must come from the same release:

- **Hooks older than the daemon.** Once the deck knows the agent is Claude Code, its card or tile says `this agent's deck hooks run a dot-agent-deck too old for its messages` and names the command to run, usually `dot-agent-deck hooks install --agent claude-code`. Run it, then restart the agent; its messages wait until then. A Claude Code agent started from a plain command, before its hooks have reported it as Claude Code, gets its messages the older way, with no notice.
- **Hooks newer than the daemon.** Claude Code shows an error from the deck's hook saying the daemon did not answer in time, or did not confirm that it serves message receipts, and the messages wait. Restart the daemon on the hooks' release, or run `hooks install` with the release the daemon runs, then restart the agent.

`hooks install` rewrites all of Claude Code's deck hooks together; restarting the agent alone does not change them. Claude Code's hook errors also cover a busy daemon that answers late, a connection lost while the daemon stops or restarts, and a deck socket that refuses the hooks access; each says what to do. Until the hooks and the daemon match, `dot-agent-deck inbox fetch` can read some waiting messages, and others need the updated hooks.

`dot-agent-deck ack <id>` now answers `unknown`, and does not mark the message delivered, when the deck has recorded that none of its current hand-overs of that message reached the agent. This applies to Claude Code, OpenCode and Pi. Acknowledge a message only after taking it through the agent's integration or `inbox fetch`.

See [Installation → When the deck, the app and the hooks are on different releases](https://agent-deck.devopstoolkit.ai/docs/installation.md#when-the-deck-the-app-and-the-hooks-are-on-different-releases) and [Troubleshooting → Claude Code shows an error from the deck's hook](https://agent-deck.devopstoolkit.ai/docs/troubleshooting.md#claude-code-shows-an-error-from-the-decks-hook).
