## Claude Code takes deck messages with receipts, and older decks and daemons refuse each other again

Claude Code now takes each deck message with a receipt: the deck knows whether a message reached Claude, a message that may have been lost is handed over again marked as a possible repeat, and one the deck cannot confirm is shown as uncertain rather than silently re-sent.

A deck or desktop app from 0.47.0 and a daemon from this release refuse to connect to each other, in either direction, and say which versions they are. Upgrade the deck, the desktop app and the daemon together; on a remote host, upgrade the remote deck before connecting to it from a newer desktop app.

Claude Code's hooks must come from the same release as the daemon. If they are older, the agent's card says its hooks are out of date and names the `dot-agent-deck hooks install --agent claude-code` command to run before restarting the agent. If they are newer than the running daemon, Claude Code shows an error from the deck's hook, takes no message, and leaves the messages waiting: restart the daemon on the newer release, or run `hooks install` with the release the daemon runs. `hooks install` rewrites the waiter and the prompt hook together; restarting the agent alone does not change them.

Until then, `dot-agent-deck inbox fetch` can read a message the deck has not yet given to any of the agent's receivers. It cannot read one the deck has already given to Claude Code's waiter or prompt hook.

`dot-agent-deck ack <id>` now answers `unknown` for a message that was never handed to the agent, for Claude Code, OpenCode and Pi alike, instead of marking it delivered. Acknowledge a message only after taking it with a receiver or `inbox fetch`.
