## Claude Code takes deck messages with receipts, and older decks and daemons refuse each other again

Claude Code now takes each deck message with a receipt, which records whether the deck's waiter or prompt hook passed the message on to Claude Code (not whether Claude read it). A message that may have been lost is handed over again marked as a possible repeat, and one whose hand-over the deck cannot confirm is shown as uncertain rather than silently re-sent.

A deck or desktop app from 0.47.0 and a daemon from this release refuse to connect to each other, in either direction, and say which versions they are. Upgrade the deck, the desktop app and the daemon together; on a remote host, upgrade the remote deck before connecting to it from a newer desktop app.

Claude Code's hooks and the daemon must both handle receipts. If the hooks are too old and the deck has recognised the agent as Claude Code, the agent's card says its hooks are out of date and names the `dot-agent-deck hooks install --agent claude-code` command to run before restarting the agent; until it does, they are served the old way with no notice. If they are newer than the running daemon, Claude Code shows an error from the deck's hook, takes no message, and leaves the messages waiting: restart the daemon on the newer release, or run `hooks install` with the release the daemon runs. `hooks install` rewrites the waiter and the prompt hook together; restarting the agent alone does not change them. An older prompt hook beside a newer waiter still confirms messages, by id rather than with a receipt.

Until then, `dot-agent-deck inbox fetch` can read a waiting message the deck is not handling through Claude Code's receipts. Some messages it is handling that way, including some that never reached Claude Code, need the updated waiter or prompt hook instead.

`dot-agent-deck ack <id>` now answers `unknown` instead of marking a message delivered when the deck has recorded that none of its current hand-overs of that message reached the agent, for Claude Code, OpenCode and Pi alike. Acknowledge a message only after taking it with a receiver or `inbox fetch`.
