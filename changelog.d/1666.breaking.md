## Messages to agents go through a per-agent inbox, and older decks and daemons refuse each other

The deck no longer types messages into an agent's pane. A task from an orchestrator, a worker's report, a dispatch result, a notice from the deck and the prompt a pane starts with now wait in that agent's inbox until the agent takes them, and the deck records whether each one was delivered. An agent the deck cannot wake directly gets one short line in its pane saying a message is waiting, never the message itself.

Because of this, a deck or desktop app from an earlier release and a daemon from this release refuse to connect to each other, in either direction, and say which versions they are. Upgrade the deck, the desktop app and the daemon together; on a remote host, upgrade the remote deck before connecting to it from a newer desktop app.

An agent whose deck hooks, plugin or extension come from an earlier release gets the one-line notice instead of the message, and reads the message with `dot-agent-deck inbox fetch`.

Deck-message prompts against an older daemon no longer show the raw message as the card's prompt. Upgrade the deck, desktop app and daemon together to see the concise `✉ <subject>` prompt.

After `dot-agent-deck hooks install` and an agent restart, Claude Code's pane labels native messages `✉ dot-agent-deck message` instead of `Stop hook feedback`. Messages and `inbox fetch` output show a `Sent by:` line identifying their source.

Desktop tiles now label an error `error` instead of `failed`, matching **Error** on TUI cards. Dashboard overview counts still group these agents under **FAILED**.

Automatic messages wait in the inbox while you have an unsent draft; the deck does not force their submission after a timeout. The former readiness, retry, no-event, draft-cap and seed-fallback environment settings no longer have an effect; a daemon started with one set logs a warning. Remove those settings from your launch environment.

An acknowledgement using an old `d-...` delivery id now answers `unknown`. Use the inbox message id supplied with the task. Older clients using the retired automatic prompt submission interfaces must be upgraded with the daemon.
