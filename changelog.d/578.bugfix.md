## Worktree paths in `worktree reclaim` no longer render two directories as one line

`dot-agent-deck worktree reclaim` lists the worktrees it would remove so you can decide before running it with `--yes`. That list rendered each path with a lossy conversion, which replaces every byte that is not valid UTF-8 with `U+FFFD` — so two directories whose names differed only in such a byte printed as the same line, while the removal acted on the distinct real paths. The list could not answer the one question it exists to answer.

Paths in `worktree reclaim` and `worktree list` are now rendered with an escape that is reversible, so no two directories can ever print alike: a byte that is not valid UTF-8 appears as `\xNN`, and a literal backslash appears as `\\` (without which a directory genuinely named `candidate-\xFF` would simply take over the collision from the one holding raw byte `0xFF`). Paths are shown in quotes, which also makes leading and trailing whitespace in a name visible at the point of deciding to delete it. Ordinary paths are unchanged apart from the quotes.

The `path` field of `worktree list --json` is deliberately unchanged — it is a versioned machine surface, `reclaim` has no `--json`, and a consumer needing byte-exact paths wants the bytes rather than a human escape.
