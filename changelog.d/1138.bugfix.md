## The TUI exits when its terminal hangs up

Closing a terminal that was running the deck left the process alive, spinning at 100% of a core until it was killed by hand. The deck now notices the hangup and ends within about half a second.

This only bit when the deck was not the session leader — `ssh -t host task run`, or a tmux pane whose command is `task`, where an intermediate process catches SIGHUP and forwards nothing, so the kernel's hangup signal never reached the deck. It could not notice for itself either: crossterm's Unix event source keeps reading a hung-up terminal forever, so the event loop was wedged inside a library and no check placed in the loop could run. A watchdog thread now polls the terminal the event loop reads — without consuming input, so it cannot steal a keystroke — and ends the process when that terminal goes away.

Agents keep running across this, exactly as they do across an ordinary detach: the daemon reads the dropped attach sockets as a detach and the panes are still there on the next launch.
