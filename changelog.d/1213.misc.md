## Old `/tmp` socket paths are no longer served

On a host without `XDG_RUNTIME_DIR` (an ordinary ssh session, a container, macOS), the daemon no longer also listens on `/tmp/dot-agent-deck-<uid>.sock` and `/tmp/dot-agent-deck-attach-<uid>.sock`. Since 0.41.1 it listened there as well as in its own `dot-agent-deck-<uid>` directory, so that a `dot-agent-deck` binary from an older release would find it. That was announced as temporary, and its two-release window has passed.

This matters only if an old copy of `dot-agent-deck` is still around: v0.41.0 or older, or v0.41.1 to v0.42.x on a host where another user owns the usual socket directory. Such a binary no longer finds the running deck and can start a second daemon beside it. It already could not attach to a daemon of this release, so upgrade it or remove it. Check what `command -v dot-agent-deck` points to, including in non-interactive ssh sessions. Any other release from v0.41.1 on still finds the daemon.
