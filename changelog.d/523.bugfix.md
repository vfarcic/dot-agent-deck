## One Orchestrator However the Orchestration Is Opened

An orchestration now seats the same orchestrator whether you open it from the New Agent form (`Ctrl+n`), a schedule, or `dot-agent-deck dispatch`. Previously the three decided it differently. For a config whose orchestrator is named `orchestrator` but sets no `start = true`, a `Ctrl+n` tab focused whichever role came first, delivered the orchestrator prompt there, and refused the named orchestrator's own `delegate` with a message contradicting itself. A dispatched run of the same config worked.

The rule is now one rule everywhere: the role with `start = true`, else the role named `orchestrator`, else the first role. It decides default focus, where the orchestrator prompt goes, which pane may `delegate`, which card `daemon status` marks `(orchestrator)`, what the orchestrator context lists as the available agents, and which role `pane spawn` refuses as the orchestrator. For every config `dot-agent-deck validate` accepts — exactly one `start = true` role — that is simply the flagged role. The one visible change for such a config is on the dispatched and scheduled path: when the flagged role sits beside a *different* role named `orchestrator`, the flagged role is now the orchestrator there too, as it already was on the `Ctrl+n` tab. `validate` no longer warns that such a role's seat "depends on how the tab is opened".

See [the `start` field](https://agent-deck.devopstoolkit.ai/docs/orchestration) in the orchestration reference.
