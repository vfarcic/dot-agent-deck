## Release notes now tell macOS users how to verify a download before how to get past Gatekeeper

The desktop alpha section appended to every release body used to present the two Gatekeeper override routes — System Settings > Privacy & Security > *Open Anyway*, then `xattr -dr com.apple.quarantine` — and only afterwards the `gh attestation verify` command. A reader following it top-down had therefore already bypassed the protection before reaching the check that would have justified doing so, which inverts Apple's own guidance: override Gatekeeper only once you have established that an app comes from a trustworthy source and has not been tampered with.

The order is load-bearing rather than cosmetic, because these bundles are deliberately unsigned and unnotarized — [#757](https://github.com/vfarcic/dot-agent-deck/issues/757) closed the paid path as out of scope, so the macOS warning is permanent rather than temporary and provenance verification is what tells a user where the file actually came from. Verification now leads the section and is framed as the prerequisite; the macOS routes follow, conditional on it having passed, with System Settings still ahead of the terminal command (Control-clicking to bypass stopped working on macOS Sequoia). Nothing was dropped: the `.deb` note about `dpkg -i` verifying no package signatures, the explanation of why provenance is a stronger claim than a checksum, the `checksums-desktop-alpha.txt` reference and the pointer to #757 all survive, the last reworded to say that signing was declined there rather than that it is still being tracked.

The verification command now also proves what the note says it proves. It used to be `gh attestation verify <file> --repo vfarcic/dot-agent-deck`, and `--repo` pins the repository but not the workflow, so an attestation minted by any workflow in this repository satisfied it while the sentence above it promised "this repository's release workflow". It now adds `--signer-workflow vfarcic/dot-agent-deck/.github/workflows/release.yml`, the form the landing page already gives, which accepts v0.41.0's `.dmg` and `.deb` and rejects the same files when told to expect `ci.yml`. A static assertion now holds both the order and the pinned workflow.

One claim was narrowed on the way past. The provenance sentence said "Every asset on this release carries build provenance", and the two checksum manifests do not — `attest`'s subject globs match `dot-agent-deck-*` and `dot-agent-deck-desktop-alpha-*`, which `checksums.txt` and `checksums-desktop-alpha.txt` miss. Rather than promote a false absolute into the section's opening paragraph, it now reads "the binaries and desktop packages". Closing the gap itself is [#1152](https://github.com/vfarcic/dot-agent-deck/issues/1152).
