## Telemetry Names Every Command in a Chained or Wrapped Shell Line

An `agent.operation` span no longer credits a whole chained line to its first command. Agents often run `cargo fmt && cargo xtask affected-checks --run` or `timeout 600 cargo test` as one shell command, and until now the span said only `cargo fmt` or `timeout`, so "where does shell time go" put minutes of tests under formatting.

The span now carries `deck.operation.commands`, every command in the line in order (`cargo fmt,cargo xtask`), and, when the first command is a known wrapper (`timeout`, `nohup`, `docker exec`, `kubectl exec`, `nix develop`, `nix shell` or `devbox run`), `deck.operation.wrapped.program` and `deck.operation.wrapped.word` for the command it runs. Group by `deck.operation.commands` to keep `cargo fmt && cargo test` apart from a plain `cargo fmt`. `deck.operation.program` and `deck.operation.word` are unchanged, so existing queries keep working. Each command is read under the same privacy rules as before: at most its program and first argument, and the list stops at the first command that uses other shell syntax. For Codex, which does not report where each argument ends, a span still names one program at most. `deck.telemetry.schema_version` is now `2`.

If you drop `deck.operation.word` in a Collector to keep commands' first arguments out of your backend, drop `deck.operation.commands` and `deck.operation.wrapped.word` as well: both carry first arguments too.

See [Telemetry](https://agent-deck.devopstoolkit.ai/docs/telemetry) for the attributes, the wrapper list and how to drop the new attributes in a Collector.
