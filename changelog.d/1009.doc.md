## No linkage-check rule polices the e2e tier's file counts, and five stale counts the #900 sweep missed are gone

Issue #1009 asked whether a `linkage-check` rule should keep the e2e tier's file counts honest after #900 reworded most of them away. **It decided against building one, in either shape, and the reasoning now lives in `docs/develop/e2e-lanes.md`** beside the commands that recount the tier.

A rule asserting that the dated tier counts still match the tree would have been out of date within eleven hours of #900's fix merging, and the tree held 85 files by 2026-09-16 against the 79 they record. Keeping it green means un-dating them, so every PR that adds a `tests/e2e_*.rs` file would also have to edit `CLAUDE.md` rule 2 — and because `main` does not require a branch to be up to date before it merges, two such PRs from the same base make an identical edit that merges cleanly and leaves `main` red. A rule that scans prose fails the other way: on this tree, a scan wide enough to find the stale counts that were really there returned 47 hits to find five.

Those five were the finding that mattered. The #900 sweep had missed `.claude/skills/verify-pr/SKILL.md`, two comments in `.claude/skills/verify-pr/checks.sh` whose number and noun sat on different lines, the orchestrator prompt in `.dot-agent-deck.toml` ("all 71 files") and `docs/develop/windows-cross-check.md` ("the 71 targets … the other 47"). All five were written before that sweep ran — no sweep for #1009 found a count written after it — and all are now worded so they cannot rot. `CLAUDE.md` rule 2's dated count and the dated measurements in `docs/develop/e2e-lanes.md` are unchanged.
