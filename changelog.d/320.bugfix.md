## A Respawned Agent Keeps Its Card When the Old One Reports Late

After a pane's agent was replaced, most visibly by a `clear = true` delegation respawning a worker, a report still in flight from the outgoing agent could reach the dashboard after the new agent had taken over. A late `SessionStart` from the old agent, or a late status report whose clock read newer, replaced the live agent's card with the dead one's, so the pane showed an agent that was no longer running.

The dashboard now decides which agent a pane belongs to by asking the daemon, which knows each pane's current agent and which agents it replaced there. It no longer relies on the event type or on a timestamp the reporting agent supplies. A late report from a replaced agent changes nothing on the dashboard, and the new agent's first report takes the pane over even if its clock reads earlier than the old card's last activity. This covers the agents the deck launches itself, Pi included, which reports no `SessionStart`. The fix applies when the dashboard and the daemon are both on this release. A dashboard attached to an older daemon keeps the previous behaviour.
