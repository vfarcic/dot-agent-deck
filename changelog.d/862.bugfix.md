## Shell-Activity Signal Survives a Loaded Machine

A pane's `Working` badge stopped updating during heavy multi-agent builds, and the daemon log filled with warnings saying so — 1716 in one day on a box running load average 24-28 with saturated disk I/O. The process-table sample the signal is built on took 19-20 seconds under that load, far past its 2-second deadline, so the daemon correctly declined to classify against a stale table and left every pane's status alone. The signal was not wrong; it was absent, for as long as the load lasted.

The cause was one column of the sample. Asking `ps` for the `args` column made it read `/proc/<pid>/cmdline` **and** `/proc/<pid>/environ` for every process on the machine — 372 of each on a 382-process box, measured with `strace` — and both of those go through a kernel path that takes the target process's memory-map lock. So the sample's duration became the sum of every unrelated process's lock wait, including processes wedged in uninterruptible sleep on saturated I/O. Reading a contended process's `cmdline` was measured at up to 40 ms against 5 ms for the `stat` file that supplies the process ids, and `ps` walks the whole table serially.

The sample now runs in two phases. The first asks only for the process and parent ids and the terminal, which reads neither of those two files for any process. The second reads a command line only where the deck's own panes have started a new session — the shell each agent detaches to run a command in, and not the build tree underneath it, which could be hundreds of processes and is not where a shell-tool signature lives. That is nothing at all on an idle deck, and one command line per command in flight on a busy one. Per-tick exposure to an unrelated process's memory-map lock goes from 744 reads spanning the whole machine to none. Under the heaviest load reproducible on a 16-core box (load 18, 13-17 processes in uninterruptible sleep), the sample now takes 15-19 ms where the old one took 60-78 ms.

Separately, a sample that still cannot produce a usable table no longer retries twice a second and narrates every attempt. The next sample is held off for an exponentially growing interval, capped at 8 seconds and reset the moment a good sample lands, and the warnings are coalesced into an episode: one line on entry naming the cause, one every 5 minutes while it persists carrying running counts, and one on recovery. The poll cadence itself is unchanged at 500 ms — the measurement confirmed it was never the cost.
