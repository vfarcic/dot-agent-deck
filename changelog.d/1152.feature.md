## Build provenance now covers the checksum manifests

`gh attestation verify` works on `checksums.txt` and `checksums-desktop-alpha.txt`, not only on the binaries and desktop packages. A full release publishes eight assets, and until now the two that were attested by nothing were the manifests — which is the worst pair to miss, because a manifest is a list of hashes you lean on to validate everything else, so an unattested one is exactly the file worth swapping.

Verify a manifest the same way you verify a binary, and the same way you always could:

```sh
gh attestation verify checksums.txt --repo vfarcic/dot-agent-deck \
  --signer-workflow vfarcic/dot-agent-deck/.github/workflows/release.yml
```

Each manifest is attested as the exact bytes the release carries: the job that publishes it hands the file to the attesting job as an artifact, rather than the hashes being recomputed somewhere else. The one thing on a release page that still carries no attestation is GitHub's auto-generated **Source code** archive, which GitHub synthesizes from the tag rather than the release workflow uploading it.

The release notes and the landing page said "the binaries and desktop packages", narrowed in [#1021](https://github.com/vfarcic/dot-agent-deck/issues/1021) to stay truthful while the gap was open. Both now say all eight assets, and name the source-archive exception.
