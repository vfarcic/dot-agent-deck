## A dispatched unit can send an update to its report

A dispatched unit whose report turns out to be wrong or stale can now run `work-done --done` again with a corrected report. The dispatcher receives it as a separate turn that opens `dispatch: a unit you dispatched sent an update to its report` and says which update it is, wrapped in the same untrusted-report markers as the report. The first report is not replaced, and the deck keeps a saved copy of each one. Running `work-done --done` again with the same report still sends nothing new. A unit can send up to three updates; a fourth different report is refused with `report_updates_exhausted`. Units and orchestrators are told they can send an update when their report turns out wrong.

A daemon from an earlier release refuses a different second report, as before. This changes what the daemon does with a request whose shape has not changed, so a desktop app from this release refuses an older daemon and says which versions they are. Upgrade the deck, the desktop app and the daemon together.
