## One Set of Agent Hooks per Machine, and No Rewrites When Nothing Changed

When more than one copy of dot-agent-deck is installed (for example Homebrew's and one in `~/.local/bin`, or the desktop app's bundled copy and a CLI), each copy used to add its own set of agent hooks, so every hook event reached the deck once per copy and Codex asked you to review the extra hooks before it would start. The deck now keeps one entry of its own per hook event, for Claude Code, Codex and Devin alike, and leaves your own hooks where they are. Starting any copy of the deck keeps the hooks calling the installed copy they already call, so two copies no longer take turns rewriting them; they move to another copy only when that one is deleted, or when you run `dot-agent-deck hooks install` from the copy you prefer, which also tidies up a file that already has several entries. The OpenCode plugin follows the same rule.

Starting the TUI, the daemon or a Codex pane no longer rewrites an agent's configuration when the deck's hooks there are already current, so an unchanged Codex `hooks.json`, Claude Code `settings.json`, Devin config or OpenCode plugin keeps its formatting and modification time. When a startup does change one of those files, the deck's log names the file and the binary the hooks now call.

A build left in a custom cargo target directory is no longer mistaken for an installed copy of the deck, so it can no longer replace your installed binary's path in agent hooks.

Stopping a daemon that has agents running with `dot-agent-deck daemon stop --force` now names, in the daemon log, every agent and orchestration role it stops, as the other ways of stopping the daemon already did.
