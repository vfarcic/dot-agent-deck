## Lane-1 e2e tests no longer race the terminal repaint

The e2e harness located on-screen targets with `find_in_grid`, which reads the terminal grid exactly once. Ratatui flushes a frame as a byte stream and the harness reader thread consumes it in chunks, so under PTY contention one frame's bytes split across reads and a single-shot lookup lands mid-repaint — seeing a transiently cleared region, aborting the test, and reddening the `e2e-deterministic` job for no real defect. `form_002` failed this way on a PR that changed nothing near it, and it never reproduced solo however loaded, because a lone deck has no competing writer to fragment the flush.

Thirty-nine lookups that follow an input event now go through `TuiDeck::wait_for_in_grid`, which re-reads until the target appears and dumps the grid on timeout. The ten lookups whose preceding wait already proved the same target are left alone, as are the ones where a missing needle is the point — an absence assertion, or an `if let` with a real else-branch — since waiting for something that should be absent would simply hang. The scan and the polling around it are now separable functions with harness unit tests over a scripted two-frame repaint, so the difference between reading once and re-reading is pinned rather than argued.

This removes one of the failure families behind the intermittent `e2e-deterministic` lane (`form_002`, `form_006`, `manager_016`, the `inline_001` group). The contention and starvation families tracked in [#818](https://github.com/vfarcic/dot-agent-deck/issues/818), [#351](https://github.com/vfarcic/dot-agent-deck/issues/351) and [#415](https://github.com/vfarcic/dot-agent-deck/issues/415) are a different mechanism and are untouched.
