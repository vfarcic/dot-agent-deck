## The focused client now decides an agent's terminal size, so an older TUI can be handed a grid larger than its pane

Since v0.40.0 the daemon sized each agent's terminal to the smallest rows and the smallest columns among the clients attached to it, and told every attached client the size it applied. So a client was never handed a grid larger than the size it had reported for its own pane, and a smaller client only ever saw padding in a larger one. That guarantee is what this release gives up.

The daemon now records which client last claimed focus. The desktop app claims when its window gains focus, and a `dot-agent-deck` TUI claims when its terminal reports focus or when it receives keyboard or mouse input. Every agent that client is showing takes the size of that client's own pane, and every other client showing the same agent is handed that size too — including where it is larger than their pane, in which case they show the agent cut off at the right and bottom. The smallest-pane rule still applies while no client has claimed focus, and for any agent the focused client is not showing.

**Why this is marked breaking.** The requests an older client sends and the responses and frames it reads are unchanged: the client identity a current client adds to its attach is an optional field an older daemon ignores, and the new focus request is sent only to a daemon that advertises it. What changed is what the size in those answers means. A client from v0.40.x reported its pane's size and could rely on being given no more; a current daemon can now give it more.

**Who is affected: a v0.40.x TUI attached to a current daemon, beside a current client that holds focus on the same agent.** The older TUI never claims focus, so it can never take the size back. It shows that agent cut off for as long as the focused client keeps a view of it, and only another current client claiming focus, or the focused client's view of that agent closing, gives it the smallest-pane size again. Upgrading the TUI restores switching. An older TUI with no current client beside it sees no change, and neither does a current client attached to an older daemon: that daemon does not advertise the focus request, so the client never sends it and sizing stays the smallest-pane rule.
