## Waiting: an agent whose turn ended while its command still runs

An agent that ends its turn while a command it started in that turn is still running, such as a build or a server it ran in the background, now shows **Waiting** instead of **Idle**, in the TUI and the desktop app alike. Its work is not finished, but nothing needs you. The `Background:` line under it still says what is running and for how long, and the card turns **Idle** when the command ends. A command left over from an earlier turn keeps today's **Idle** with the `Background:` line, so a server the agent started reads **Waiting** only until it exits or the agent finishes another turn.

A Waiting agent can still take a prompt or a deck message, as an Idle one can. In the TUI its status dot does not blink and the terminal bell does not ring until it turns Idle, and `dot-agent-deck close` refuses it as busy unless you add `--force`. The desktop Dashboard's status filter offers **Waiting**, and saying "show only the agents that are waiting" filters to it by voice, while "waiting for input" and "needs input" still mean **Needs input**; "show only busy agents" shows Working, Thinking and Waiting agents. Telemetry reports the status as `deck.status` = `awaiting_command`; `waiting` keeps meaning Needs input. A TUI or desktop app older than this release shows a Waiting agent as Idle with its `Background:` line.

See [Work left running after a turn](https://agent-deck.devopstoolkit.ai/docs/session-management.md#work-left-running-after-a-turn).
