## Desktop settings footer no longer names a file it is not using

The desktop app's Settings footer used to read "Stored in <path>" even when the app had refused that location, for example when `DOT_AGENT_DECK_DESKTOP_CONFIG` pointed at a relative path or a directory, or when the `desktop.toml` there could not be read. In both cases the app runs on default settings and saves nothing to that path, so the footer was wrong.

The footer now shows the reason the settings location cannot be used in place of the path — the same explanation the settings panel gives when nothing has been saved yet. Once a save succeeds, which the app allows only when the location is usable, the footer names the file again.
