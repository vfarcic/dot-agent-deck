## The TUI no longer attaches to a daemon it cannot understand

After an upgrade that changed the attach protocol (the wire the TUI and the daemon speak), a TUI could attach to a daemon on the other protocol version. The dashboard looked normal while every event it could not decode was silently dropped. This happened when you declined the restart prompt to keep your running agents. The TUI now reads the daemon's protocol version before anything else, and refuses to attach across a difference. The desktop app already required an exact match, and the TUI now uses the same rule.

With no agents running, nothing changes for you: the old daemon is restarted silently onto the new version, as with any upgrade. With agents running, the restart prompt says the new binary cannot attach, and declining exits instead of attaching:

```text
error: daemon speaks attach protocol v11, but this binary speaks v10
```

Nothing is stopped. The daemon and its agents keep running, and the message names the agents it can list and gives the two ways on: relaunch with the build the daemon came from to keep working with those agents, or run `dot-agent-deck daemon stop` (which stops them) and relaunch to move onto the new binary. Without a terminal, the same message goes to stderr. See [Upgrading](https://agent-deck.devopstoolkit.ai/docs/installation#upgrading).
