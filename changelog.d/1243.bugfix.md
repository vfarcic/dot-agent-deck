## Delegated Tasks No Longer Sit Unsubmitted in a Busy Worker's Input Box

On a loaded machine, a delegated task could be typed into the worker's input box and never submitted: the line sat there with an empty line under it, the worker looked healthy and idle, and the orchestrator waited for a `work-done` that never came. The worker had not finished taking the text in when Enter arrived, so it treated the two as one paste and the Enter as a newline.

The deck now presses Enter only once the task's line has appeared on the worker's screen, waiting up to 2 seconds for it before pressing Enter anyway. On a machine that keeps up nothing changes. Measured against Claude Code with three busy processes per CPU, the old fixed pause left 3 of 30 tasks unsubmitted; waiting for the line to appear left none of 50.

If a task does end up sitting in the input box, each re-send now presses Enter a second time after a few seconds when the task is still on screen, because an agent in that state ignores the first Enter. The re-send still never types the task again when it is visible.

See [A lost task is re-sent into the same worker](https://agent-deck.devopstoolkit.ai/docs/orchestration#a-lost-task-is-re-sent-into-the-same-worker).
