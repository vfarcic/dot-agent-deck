## The deck now says when a role's launcher hides its agent

A role whose `command` goes through a launcher, such as `devbox run codex-big`, `mise exec -- opencode` or `./run-pi.sh`, hides from the deck which agent it starts. Unless the role also declares it with `agent = "…"`, the deck cannot use that agent's own way of telling when a restarted worker is ready. It watches a Codex terminal, hands a Pi worker its task natively, and gives OpenCode a fixed wait sized for its start-up. Without those it waits up to 30 seconds for the agent to announce itself. Claude does announce itself, so a Claude role behind a launcher delivers promptly. Codex, Pi and OpenCode do not announce themselves before their first task, so every `clear = true` delegation to one of them paid the full 30 seconds, and nothing above the daemon's debug log said why. One day of measurement found 29 such delegations, and not one avoided the wait.

`dot-agent-deck validate` now warns about each role whose agent it cannot identify, quoting the command and listing the names `agent` accepts. The daemon log records a warning, naming the fix, each time a delegation pays that wait. Adding the declaration next to the command removes the wait:

```toml
[[orchestrations.roles]]
name = "tester"
command = "devbox run codex-big"
agent = "codex"
```

A variant orchestration that `extends` another and restates only `command` inherits the parent's `agent`, so change the two together. See [Declaring the agent behind a launcher command](https://agent-deck.devopstoolkit.ai/docs/orchestration#declaring-the-agent-behind-a-launcher-command).
