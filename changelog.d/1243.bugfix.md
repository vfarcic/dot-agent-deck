## Messages the Deck Sends to Agents No Longer Sit Unsent in the Input Box on a Busy Machine

On a heavily loaded machine, a message the deck typed into an agent could land in the agent's input box and never be sent. That included a delegated task, a worker's report reaching the orchestrator, a scheduled prompt, or a new agent's first prompt. The agent then sat idle, and an orchestrator waited for a task or a report it had never received. The deck now waits a moment for the message to show up in the agent's input box before pressing Enter; on a machine that keeps up, nothing changes that you can see. If a delegated task still ends up sitting unsent, the deck presses Enter for it again rather than typing it a second time.

See [A lost task is re-sent into the same worker](https://agent-deck.devopstoolkit.ai/docs/orchestration#a-lost-task-is-re-sent-into-the-same-worker).
