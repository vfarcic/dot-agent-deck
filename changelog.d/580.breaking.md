## A delegate to a worker that has not finished its last task is refused instead of accepted silently

The orchestrator's standing rule has always been "never send a new task to a worker that is still working on a previous one", but only the orchestrator's own discipline enforced it. The daemon accepted the second delegate and typed it into the busy worker's pane, and `delegate` reported success because the write genuinely happened — leaving the orchestrator unable to tell the two tasks' completions apart.

The daemon now refuses a delegate to a worker that still owes a `work-done` for an earlier delegation. `dot-agent-deck delegate` exits non-zero with `this delegate was NOT sent`, naming the worker, how many delegations it still owes and how long ago the oldest was issued. When a delegate names several `--to` roles, the free ones still get the task and the command prints a warning naming the refused ones, exiting 0 as it does for a role that resolves to no pane. The decision comes from the daemon's own record of what it has delegated, not from the worker's reported status, which can be wrong for hours.

When the earlier task is genuinely abandoned, `dot-agent-deck delegate --supersede` dispatches anyway and says it superseded; `dot-agent-deck pane restart <role>` replaces the worker and drops what it owed, so a plain delegate to it is accepted again; and a delegation stops counting seven days after it was issued.

**Why this is marked breaking.** Nothing on the wire moved — `--supersede` and the reply's new `busy` and `superseded` lists are optional fields an older build ignores, so `PROTOCOL_VERSION` is unchanged. What changed is what a delegate that used to be dispatched now does: it is refused. An orchestrator prompt that re-delegates to a worker before its `work-done` arrives now gets a refusal it has to act on. A `delegate --supersede` sent to an older daemon is dispatched as every delegate was before.

See [One task per worker at a time](https://agent-deck.devopstoolkit.ai/docs/orchestration#one-task-per-worker-at-a-time).
