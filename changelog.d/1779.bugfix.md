## Pull requests opened from your own fork are recognised

When your checkout's `origin` is the upstream repository and you push your branch to your fork and open the pull request from there, `dot-agent-deck worktree list` reported the branch as having no pull request, so `worktree reclaim` kept its worktree after the pull request merged, and the agent's card showed no pull request badge. A pull request from the fork your branch is pushed to now counts as that branch's: once it merges, a clean worktree the deck created is reclaimed like any other, and the badge shows its state, CI and review.

The fork is the one `git push` uses for the branch (`branch.<name>.pushRemote`, then `remote.pushDefault`, then the branch's upstream remote). A pull request from anyone else's fork whose branch happens to share your branch's name still does not count, and when the deck cannot tell which fork your branch is pushed to, it keeps the worktree as before.
