## A product landing page at agent-deck.devopstoolkit.ai, and one look across the whole site

`agent-deck.devopstoolkit.ai` used to open on a Docusaurus docs home. It now opens on a product landing page: what Agent Deck is, what it looks like running, how to install it, and where to go next. The page was chosen from four candidate directions built with real content, and the three that lost were removed. It is laid out for phone width and for both light and dark themes.

**It leads with what the product does today.** The story the page tells is an escalation rather than a tour: open a pane — which can be a single agent, a full multi-agent orchestration, a dispatcher, or a scheduled task — watch every agent on its own live card, let one agent run the others, and send whole lines of work off into their own copies of the repository. Dispatching had no presence on the site's front door at all and now closes the story, with its own link in the closing band; orchestration is no longer buried behind a single mention. Workspace modes are on their way out ([#1199](https://github.com/vfarcic/dot-agent-deck/issues/1199)) and no longer appear on the page.

**It talks about what Agent Deck does for you, not how it is built.** The old page's "auto-installed hooks" and "native embedded terminal panes" are gone. Where an implementation detail is the reason a reader cares — that it is a single binary, the Rust version a source build needs, the command that verifies a download — it stays.

**Four claims that were wrong or dated are corrected.** "Running five at once" read as a ceiling that nothing in the product imposes; it now says many at the same time. "The agents write the code" left out that they also run the tests, watch the pipelines and answer the review comments. "One dashboard, every agent visible at a glance" predated tabs, orchestrations and dispatched units, and now says what the product holds today. And "No buttons" was false — the dashboard has a clickable button bar that names each command and its key — so that principle now reads "Keyboard first".

**`/` and `/docs` are one product now.** The landing page's colours used to be its own; they are now the site's, so the background, the text, the hairlines and the link colour stay put when you click through from the landing page into the documentation. The most visible part is dark mode, which moves from Docusaurus's default grey to the landing page's deeper near-black across every docs page, and in which the table of contents and other secondary text now recede to a soft grey instead of matching the body copy. Only colours moved: the documentation's type, layout and components are untouched, and none of the landing page's gradients or device frames follow it in.

**Links and active-state text in the docs meet WCAG AA in light mode.** The docs' link colour measured 1.93:1 against a white background, below the AA minimum of 4.5:1, on every page. Links now measure 5.07:1, and four more pieces of coloured text in the chrome were also below 2:1 and now clear AA: the selected sidebar item (1.73:1 to 4.53:1), the active navbar item (1.80:1 to 4.72:1), the active breadcrumb (1.73:1 to 4.53:1) and the highlighted table-of-contents entry (1.93:1 to 5.07:1). In dark mode the accent stays the same teal, `#4ecdc4`.

**The page says what the product actually ships.** The desktop app was missing from the landing page entirely and now has its own section; it is described as an alpha with unsigned bundles for macOS and Linux and no Windows bundle yet, alongside the build provenance that does ship with the release. The agent list named two agents and now names all five the product supports — Claude Code, OpenCode, Pi, Codex and Devin. The Windows install tab used to link a closed issue; it now says plainly that native Windows is not there yet, names WSL as the route that works today, and leaves the tracking issue to the installation guide. The Linux install no longer hedges with "Homebrew (if available)", because the Homebrew formula covers both Linux architectures.

**The screenshots are current.** Ten product images dated May or earlier were refreshed or removed. Two of the story's four frames are now captures of a real deck at work: one running four different agent clients side by side, and one showing a dispatcher with two units up at once. Two of the old images showed a maintainer's home directory path, and one of those also showed an unrelated project's internal orchestration config; that image is deleted and the other recaptured. The New Agent dialog image now shows the dialog as it looks today. A screenshot on the orchestration page, the Generate `.dot-agent-deck.toml` dialog, was returning a 404 on the published site and now loads, and the session-management page gains a picture of the Quit dialog beside an explanation of Detach versus Stop. The folder the site serves its images from also went from 3.8 MB to 1.4 MB in total.

See the [Getting Started guide](https://agent-deck.devopstoolkit.ai/docs/getting-started) for the install paths the landing page links to.
