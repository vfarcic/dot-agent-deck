## `manager_016` no longer races the dialog's own repaint

`scheduler/manager/016` sampled the side pane's visible scrollback with a single-shot `snapshot_grid()` read taken the instant the Scheduled Tasks dialog's `NEXT FIRE` **header** appeared — before the overlay's interior had painted. That dialog paints over the side pane and occludes marker rows, so a half-painted overlay yields a marker set the settled frame does not have, and comparing it against a settled post-wheel sample failed the assertion with no defect present. This is the same repaint race as [#807](https://github.com/vfarcic/dot-agent-deck/issues/807)/[#395](https://github.com/vfarcic/dot-agent-deck/issues/395) reaching a raw grid comparison rather than a `find_in_grid`, so #872's sweep of `find_in_grid` call sites does not cover it — its only change inside this test is the `[Submit]` lookup, which runs before the dialog opens.

The marker set is now sampled only once two consecutive reads agree, on both sides of the comparison, and the test waits for the initial selection marker as well as the header. The assertion is unweakened: a genuine wheel leak still moves the settled after-state, verified by inducing one. Failure messages now also carry the settled baseline grid, so the next occurrence is decidable from the log alone.

The observed failure was diagnosed by band width rather than guessed at — a real leak shifts every marker and keeps the occluded band 11 rows wide, while the CI failure kept its band start fixed and grew the band from 9 to 11, which only the overlay's painted extent can do. `manager_016` had reddened `e2e-deterministic` on four unrelated branches in a 28-run window, one of them a pnpm bump carrying no Rust.
