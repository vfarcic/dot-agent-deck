## The orchestrator is told when a delegated worker is waiting for input

A worker that stops and waits for input no longer stalls an orchestration until a person happens to look at its pane or the two-hour idle-worker report fires. When a worker that still owes a `work-done` reports that it is waiting — for a Claude Code worker, a permission prompt — and stays that way for 30 seconds, the daemon submits one self-describing report into the pane of the orchestrator that delegated to it. The report names the worker's role and quotes what its pane is showing, both marked as untrusted text, so an unattended orchestrator can take a turn on it: notify you, answer a question the worker asked, or keep waiting.

A wait that clears within the 30 seconds produces nothing, a worker that owes no `work-done` is never reported, each wait is reported once, and the same worker is reported at most once every two minutes. Like the other orchestrator reports, it is delivered only to the orchestrator agent that made the delegation, and it is information only: it grants, cancels and reroutes nothing. A Claude Code worker that asks its question in prose ends its turn and reports idle instead, so it is not covered by this report. Set `DOT_AGENT_DECK_WAITING_NOTICE_DEBOUNCE_MS` to change the 30 seconds, or to `0` to turn the report off.

See [Idle Workers & Notifications](https://agent-deck.devopstoolkit.ai/docs/idle-workers-and-notifications) for the full wording and behaviour.
