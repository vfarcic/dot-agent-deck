## Codex moved with `/cd` or `/worktree` is no longer checked with the wrong keys

When you moved Codex into another project with `/cd` or `/worktree`, the deck went on checking its input box with the key settings of the project Codex started in. If the new project's `.codex/config.toml` gave `Ctrl+G` another action, the deck's check ran that action instead, for example changing Codex's approval mode, and you had to restart the pane to avoid it.

The deck now reads the folder on Codex's status line, under its input box, before each check. Once that line names another folder than the one Codex started in, the deck stops checking that Codex's box and types nothing more into it until Codex restarts, and the TUI card and the desktop tile say `the deck can't check this agent's input box. Check its pane.` Send the agent a prompt to have it take its messages, or start Codex again in the new folder. The same happens to `/resume` when Codex shows the resumed conversation's folder on that line. The deck also holds the check, with the same words, while it can't read the folder on that line: a status line set up without the current folder, a pane too narrow for the whole folder name, or a folder name with a character two columns wide.

See [How the deck checks Codex's input box](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#how-the-deck-checks-codexs-input-box).
