## A launch naming an orchestration the project declares twice is refused

When a project's `.dot-agent-deck.toml` declares two orchestrations with roles under the same name, a launch naming it from the desktop's New agent dialog or Runs screen used to start the first declaration's roles, whichever one you meant. The New agent dialog already refused this when it could see the duplicate before launching, but a config edited between that check and the launch still reached the first declaration. The daemon now refuses the launch itself, before it writes the coordinator's brief or starts anything. The New agent dialog shows its usual "rename one to launch it here" message for it; the Runs screen shows the daemon's refusal. A declaration with no roles still does not count as a duplicate.

This is a compatibility change between builds: a launch an older daemon accepted can now be refused. Against an older daemon the New agent dialog keeps its own check, which covers every case except a config edited in the moment between the check and the launch; any launch that gets past it is prepared from the first declaration, as before. `dispatch --orchestration` still starts the first declaration; that is tracked separately.
