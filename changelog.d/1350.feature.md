## One Deck List for the CLI and the Desktop App

The desktop app and the CLI now share one deck list, `~/.config/dot-agent-deck/remotes.toml`. A deck added with `dot-agent-deck remote add` appears in the desktop app's deck settings, and a deck added in the desktop app appears in `remote list` and opens with `connect <name>`. Either client can edit or remove any deck, and `DOT_AGENT_DECK_REMOTES` moves the file for both. The two clients take a lock file, `.remotes.toml.lock`, beside the list while they save, so a save in the app and a `remote add` in a terminal at the same moment both keep their change.

Existing desktop decks move out of `desktop.toml` into `remotes.toml` the first time the new desktop build starts; a deck already present in both is not listed twice, and the selected deck stays selected. A deck added in the desktop app has no binary installed by the CLI, so `remote list` shows `version = "unmanaged"` for it until `dot-agent-deck remote upgrade <name>` installs one. Both clients refuse a host, login, port, jump host or socket path that ssh could misread — a leading `-`, whitespace, control characters or shell metacharacters — before writing it.

Mixing versions has two costs. An older CLI that re-saves the file (`remote add`, `remote remove`, `remote upgrade`, or `connect` when a session ends) drops the new optional fields `id`, `user`, `jump_host` and `socket` from every entry, and an older desktop build shows no remote decks once a newer one has moved them. Upgrade every machine that shares the file. `connect` does not route through a deck's `jump_host` yet; add a `ProxyJump` line for that host to `~/.ssh/config` instead.

See [Remote environments](https://agent-deck.devopstoolkit.ai/docs/remote-environments) for details.
