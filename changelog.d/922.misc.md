## OpenCode real-agent tests run on a cheap metered model, and an unreachable model now skips instead of looking like a product bug

The OpenCode real-agent tests defaulted to `openai/gpt-5.4-mini`, chosen because it resolves against a ChatGPT-subscription login and so costs nothing per call. On a box whose subscription quota was exhausted, the model answered "The usage limit has been reached" — which satisfies no assertion, so the test died on a missing answer token and read as a defect in the deck's own auto-submit path. It was nothing of the kind, and the test failed for anyone who did not already know to override the default.

The default is now `anthropic/claude-haiku-4-5-20251001`, the cheap model this project's real-agent coverage asks for and the one the sibling Claude test already runs on. The old id was re-probed and still works, so this is not a retirement — what condemned it is the shape of its failure when the credential runs out. A metered key has no quota cliff to fall off mid-turn, and it is also the only provider the test harness can authorise by itself: an ambient `ANTHROPIC_API_KEY` is the one credential that crosses into a spawned deck, so a host holding just that key can now run this coverage where it previously skipped. A subscription host keeps the old behaviour by exporting `DOT_AGENT_DECK_OPENCODE_TEST_MODEL=openai/gpt-5.4-mini`. Nothing OpenCode-specific is lost by the provider move: what these tests assert is OpenCode's own surface — its composer paint, its auto-submit, its `session.prompt` event — none of which varies by which vendor answers the turn.

The availability check now ends in one bounded, minimal turn against whichever model is configured, closing an asymmetry its own comments had flagged as a known gap. A credential file on disk says nothing about whether the configured model is reachable through it, and the three ordinary ways it is not — a login for another provider, a retired id, an exhausted quota — all used to arrive as an assertion failure deep inside a PTY wait that never mentioned the model. They now surface as a skip that names the model and says what the probe observed, which `DOT_AGENT_DECK_REQUIRE_REAL_E2E=1` still turns back into a hard failure like any other skip.

Detecting the quota reply mid-test was considered and deliberately not done. It is the same defect class as the drifted readiness marker fixed alongside this — a hardcoded literal matched against another program's prose, drifting on its own schedule — it would have to abort a half-executed test in order to skip, and a false positive would silently delete real coverage. Whether this host can reach the model is a preflight question, and it is now answered in the preflight.
