## Desktop: upgrade the CLI from the Local daemon section

In the desktop app, the newer-release banner at the top of the Dashboard and the rail's upgrade button are now about the app alone. When the `dot-agent-deck` CLI on this machine is behind, the **Local daemon** section of the Dashboard offers **Upgrade** instead, as a remote daemon's section does, so a notice for the CLI no longer reads as if the daemon were out of date.

Pressing **Upgrade** on the Local daemon section shows the CLI's plan and upgrades it with its own install method (`brew upgrade`, a checked download, or the command to run where the app cannot do it). When the daemon on this machine is also older than the app, it is then restarted onto the app's version; with agents or orchestration roles running, it lists what would stop and defaults to **Keep current daemon**, so you can upgrade the CLI and leave the running daemon and its agents alone.

Every client now names the copy it means: `dot-agent-deck CLI: update available: …` and `Agent Deck (desktop app): update available: …`, in the TUI's footer, the upgrade dialogs and `dot-agent-deck upgrade`. In the TUI and `dot-agent-deck upgrade`, the CLI's plan also says that upgrading does not restart the daemon on this machine, and that the next TUI you start restarts it onto the new version, asking first when agents are running.

See [Upgrade the CLI and the daemon on this machine](https://agent-deck.devopstoolkit.ai/docs/desktop/daemons.md#upgrade-the-cli-and-the-daemon-on-this-machine).
