## The desktop settings log no longer echoes your settings file

Hand-editing `desktop.toml` into a state the app cannot read used to print the offending line of your own file — twice — into the app's stderr and the deck log, because that diagnostic passed the TOML parser's error through verbatim and its rendered form quotes the value it choked on. A log is a file people paste into bug reports, so a value that had no business leaving the document left it.

The diagnostic now names the file and the position — `line 3, column 9 could not be read as settings` — and carries nothing from the document itself. You lose the parser's `expected u32` half of the message and keep the half that acts: the line is the line to open, where the offending text is already in front of you.
