## `delegate` names the worker that received the task

A successful `dot-agent-deck delegate` now prints a `Delegated …` line naming, for each role, the pane of the worker that received the task and the task id the deck gave it. Before, a delegate accepted for every role printed nothing, so when several orchestrations with the same role names ran on one deck, the orchestrator could not see which worker it had reached, and a task that reached an unexpected worker went unnoticed until its report looked wrong. The pane is the one `dot-agent-deck roles` lists beside the worker's orchestration, and the task id is the one the worker's report names when it arrives as `<role> completed task <id>`. A delegate accepted for only some roles prints the same line for those roles after its warning. Against a daemon older than the `dot-agent-deck` binary, `delegate` names no pane and prints nothing for a task accepted for every role, as before. See [Orchestration](https://agent-deck.devopstoolkit.ai/docs/orchestration.md).
