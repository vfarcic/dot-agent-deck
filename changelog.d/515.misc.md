## The docs-publish workflow verifies its `yq` download instead of trusting it

`.github/workflows/docs-publish.yml` installed `yq` with `sudo wget -qO /usr/local/bin/yq …` followed by `sudo chmod +x`, which pins a version *tag* and nothing else. A GitHub release asset is mutable — a tag can be re-pointed and the binary re-uploaded — so the URL guaranteed only where the bytes came from, never which bytes arrived. The step it feeds runs after the checkout and two steps before `git push origin main`, in a job that holds the `RELEASE_TOKEN` admin PAT, so the blast radius of a substituted binary was a commit of the attacker's choosing on a ruleset-protected branch under an admin identity. `-q` compounded it by suppressing the reason for a failed transfer, leaving a truncated body or an HTML error page to surface later as a confusing `yq -i` failure rather than as a download failure.

The download is now content-pinned against a SHA-256 committed next to the version, checked with `sha256sum --check --strict` before the binary is ever marked executable. The digest lives in the workflow rather than being fetched from the release's own `checksums` asset — that file ships from the same mutable release and is signed by nothing, so downloading it would verify the transfer but not the content, since whoever can re-upload the binary can re-upload its checksum alongside it. Only a digest committed to this repository pins the bytes. A comment at the step records that the version and the digest must move together by hand, that nothing bumps either today (Renovate has no manager that reads a URL out of a `run:` block), and that a regex manager taught to bump only the version would produce a PR that fails the check.

`sudo` is gone from the step entirely. `curl --fail --location --silent --show-error` writes to a job-local temp file, the digest is verified, and only then is the binary installed into a directory placed on `PATH` via `$GITHUB_PATH` — so an unverified download never reaches a root-owned system path, and a failed one is loud: a 404 now exits non-zero with the reason printed and leaves no output file at all. The explicit `--retry` preserves rather than adds behaviour — `wget` retries by default and bare `curl` does not, and this step runs after the docs image is already pushed, where a transient failure would strand the job with the image in GHCR and `main`'s chart pointer stale.

What the workflow produces is unchanged. It still runs the same `yq` version against the same three expressions — `.image.tag`, `.version`, `.appVersion` — and those are surgical single-line edits that preserve the surrounding formatting and quoting exactly, so the resulting chart commit is byte-identical.
