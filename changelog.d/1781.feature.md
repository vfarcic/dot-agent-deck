## Pull request badge: CI status beside the review

An agent's pull request badge now shows whether the pull request's CI passes, beside its review, on the same line it already had, so you can tell whether a pull request is green and approved without opening it.

The CI mark is GitHub's overall check result, as GitHub's pull request list shows it: a green check when every check passed, a red cross when one failed (a check that is not required for merging included), an amber dot while checks run, and no mark when the pull request has no checks. The review now sits in a filled mark, so an approval and passing CI, both a check, are easy to tell apart. In the desktop app the badge uses GitHub's own icons and colours, and its tooltip says how many checks are in each result, for example `Pull request #1234: open, review required; CI: 1 failing, 24 passing`. In the TUI the card's bottom border reads, for example, `#1234 ⊙ ✓ ◉`, with the review drawn as a filled cell; changes requested is now `±` and review required `◉`. On a narrow card the badge drops the review first, then CI, then the state, and keeps the number. The CI result refreshes with the rest of the badge, within about a minute.

See [Pull request badge](https://agent-deck.devopstoolkit.ai/docs/session-management.md#pull-request-badge) and [Dashboard → Pull requests](https://agent-deck.devopstoolkit.ai/docs/desktop/dashboard.md#pull-requests).
