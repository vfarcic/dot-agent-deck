## The cannot-scroll notice no longer fires on a pane that is merely on the alternate screen

Selecting a pane and pressing `PageUp` could overlay `Nothing to scroll — this pane has no scrollback to move through` on a pane that had plenty of scrollback. Pressing `Enter` and trying again appeared to fix it. Both halves are now explained, and the first is fixed.

`vt100` keeps two grids per screen, and it builds the alternate one with a scrollback capacity of **zero** (`vt100-0.16.2/src/screen.rs:76`). Every scrollback read and write dispatches on the current mode, so while an agent sits on the alternate screen — a picker, a permission dialog, an editor — the deck's depth probe reads `0` however much that pane has produced. `bytes_since_spawn` meanwhile counts straight across the switch. The notice's trigger is exactly *(depth == 0) ∧ (≥ 8 screenfuls)*, so it was satisfied by **any** mature pane that had merely entered alternate mode, and the deck told the user their history was gone while the normal grid still held every line of it. Measured on the regression test: identical bytes leave **258 retained lines** on the normal screen and report a depth of `0` on the alternate one.

`pane_has_nothing_to_scroll` now carries a third term and stays quiet on an alternate-screen pane. Unreachable is not absent, and the notice claims only what the deck can actually observe — the same reasoning PRD #611's review finding 3 applied to the parser-rebuild path, where the comment already says that left counting, the next scroll would explain Agent Deck's own history loss as a property of the agent. It is still not an agent check: this reads a terminal mode any agent can enter and leave, so PRD #611's "detect the condition, not the agent name" is unchanged, and **codex behaviour is untouched** — codex does not use the alternate screen, so its original case still arms exactly as before.

`mode/scroll/006` pins it, and pins it as a round trip rather than a single state: the control measures real depth on the normal screen, the alternate-screen case must stay quiet while still clearing the maturity bar, and switching back must restore the control's exact depth — which is what makes "unreachable, not absent" a measurement instead of a claim.

`docs/keyboard-shortcuts.md` carried a false absolute that this report falsified in practice. It said Agent Deck has nothing to scroll for a terminal-managed agent *"by wheel or by key, in any mode"* with *"no alternative chord that reaches further back"*, while a paragraph ten lines earlier explained that in a focused pane those keys go to the agent as `ESC[5~` / `ESC[6~` and the agent's own scrollback answers them. The claim is now scoped to command mode and to the deck's own scrollback, and the alternate-screen state is documented alongside the two agent camps.
