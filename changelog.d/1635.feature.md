## Upgrade the CLI and the desktop app in place

The desktop app now notices a newer release, as the TUI's footer notice already did, and both can be upgraded without going back to the install instructions. Previously each copy had to be upgraded by hand, through whatever it was installed with, and the CLI and the desktop app were kept on the same release by hand.

`dot-agent-deck upgrade` shows what upgrading this machine's copies would do and asks before each one; `--check` only reports, and `--yes` upgrades without asking. Ctrl+C while it upgrades a copy stops the command it is running, such as `brew upgrade`, or the download, and upgrades nothing further. Each copy is upgraded the way it was installed: `brew upgrade` for Homebrew, a checked download that replaces a downloaded binary in place, or, in a directory you cannot write, the exact `sudo` command to run. Nix, source builds and other system packages are told what to do instead and left alone. Every download's checksum is checked against the release before anything is replaced, and its build provenance too when the GitHub CLI is installed and logged in; the plan says before you confirm whether it will be. A CLI on the `dot-agent-deck-beta` formula is offered the next pre-release and, when a stable release is newer, the command that switches it to the stable formula.

The desktop app checks at start and every 6 hours, and shows an upgrade button at the bottom of its rail and a banner on the Dashboard while this machine's app or CLI is behind. Its upgrade dialog upgrades the app and the CLI one at a time after you press **Upgrade**: a `.dmg` app is replaced in place and offers **Relaunch**, and a `.deb` app is installed after your system's password prompt and offers **Relaunch** too, or with the `sudo apt install` command it shows when there is no prompt or you dismiss it. In the TUI, the footer's update notice now uses the desktop app's wording and names a key: press `u` in command mode (remappable as `open_upgrade`), or click the notice, to open an upgrade dialog with the same plans and the same one-copy-at-a-time questions, defaulting to **Cancel**. After the TUI's own copy is upgraded, it says to quit and start the TUI again. The TUI now also checks every 6 hours while it runs, not only when it starts. Upgrading from either client finds the other copy on the machine and offers to upgrade it too, through that copy's own install method. Upgrading does not stop the daemon or its agents.

See [Installation → Upgrading](https://agent-deck.devopstoolkit.ai/docs/installation.md#upgrading), [Installation → Upgrade from the TUI](https://agent-deck.devopstoolkit.ai/docs/installation.md#upgrade-from-the-tui) and [Desktop App → Upgrade the app](https://agent-deck.devopstoolkit.ai/docs/desktop/index.md#upgrade-the-app).
