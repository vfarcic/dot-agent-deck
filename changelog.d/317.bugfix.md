## Close confirmation no longer acts on a replacement agent

A close confirmation now applies to the agent generation you armed it against, not merely to the session id. Previously, confirming a close could tear down a *different* agent than the one you pointed at — the replacement that had taken over the pane while the dialog was open.

The reason it could happen is that not every session id goes stale. Pi's agent reports arrive under a producer key derived from the pane (`{pane_id}-session`), and that key is deliberately stable across respawns, so it keeps resolving after the pane changes hands. A confirmation armed on the id alone therefore stayed valid across a respawn and landed on whichever generation currently occupied the pane. The close confirmation exists precisely to stop that class of surprise, and a target keyed on a session id could not see this particular way through it.

Confirming after a respawn now reports `Nothing closed — what this confirmation was armed against is gone` and leaves both the card and the running agent untouched, exactly as it already did for a session that genuinely disappeared. Nothing changes for the ordinary case: a confirmation armed against the agent still in the pane closes it as before, and a card that simply learns its agent identity while the dialog is open is not mistaken for a replacement.
