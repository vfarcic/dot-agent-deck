## Agents no longer start somewhere other than the directory you asked for

Starting an agent in a directory that does not exist, or in a path that is a file, used to start it in your home directory instead, while the deck went on showing the directory you asked for. The deck now refuses the start and says the working directory is not a directory, and nothing is started. `pane restart` of a role whose directory was deleted is refused the same way, and the running agent is left alone.

A role started from a prepared launch (the desktop's New agent dialog or Runs screen) is now restarted only in the project directory that launch checked. If that directory has since been moved away and another one put at the same path, `pane restart` is refused and the running agent is left alone, rather than the role starting in the other directory. If the directory was deleted and nothing took its place, the restart gets the not-a-directory refusal, as any other role does.

`dispatch --orchestration <name>`, and a schedule with `shape = "orchestration:<name>"`, now refuse a name that the project's `.dot-agent-deck.toml` declares for more than one orchestration with roles, instead of starting the first one. Rename one of them to dispatch it. A declaration with no roles does not count as a duplicate. Desktop launches already refused this case.

This is a compatibility change between builds: a start or a dispatch that an older daemon accepted can now be refused.
