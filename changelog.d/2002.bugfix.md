## Two Codex panes no longer report as one

Two Codex panes could share Codex's background server, and the second one then reported through the first: its status, prompts and tools showed on the other pane's card, and what it sent the deck was counted for that pane. A Codex pane the deck starts with a direct `codex` command now reports as itself, in the TUI and the desktop app alike. The deck starts Codex without the shared server, so Codex may show a one-line notice saying so when it starts; that is expected.

That is a command that runs `codex` by name or by path. If you start Codex through a launcher, script or alias such as `devbox run codex-big`, make the command it finally runs start Codex the same way: add `--no-daemon` (Codex 0.156.0 or later), or put `-c 'shell_environment_policy.set={}'` before Codex's other arguments, which Codex 0.155.0 also accepts. Sessions using `--remote` or Codex's agents overview still share a server on purpose. Codex panes that were already running when you upgraded, and a pane a scheduled task reuses, keep the mode they started in until the agent restarts; a shared server that is already running keeps running, but direct Codex panes the deck starts from now on do not use it.

See [Two Codex panes report as one](https://agent-deck.devopstoolkit.ai/docs/troubleshooting.md#two-codex-panes-report-as-one).
