## Telemetry Times Orchestration Hand-offs and Reports the Daemon's Health

Each task an orchestrator delegates now becomes an `agent.handoff` span in the orchestrator's trace, from when the task reaches the worker's inbox to when the worker's report arrives, with a `deck.handoff.taken` event when the worker takes it and a `deck.handoff.reported` event when its report arrives. When the orchestrator acknowledges the report, an `agent.handoff.read` span under the hand-off records how long the report waited to be read. So you can see how long tasks wait for a worker, how long the work takes and how long the orchestrator takes to read the result, per role. `deck.handoff.outcome` says how it ended (`reported`, `undeliverable` with a reason such as `agent_exited`, `superseded`, `unknown` or `daemon_shutdown`), and `deck.handoff.worker.run.id` joins it to the worker's run. Reports sent with `work-done` but without `--task-id` are counted on the receiving run as `deck.handoffs.uncorrelated.count`. Only ids, the role and the outcome are sent, never the task or the report.

The daemon also sends a `daemon.health` span about once a minute with its memory use (Linux), the number of open agent runs, how long agents' status reports took to reach it (count, median, 95th percentile and slowest) and how many spans it could not send. `DOT_AGENT_DECK_TELEMETRY_HEALTH_INTERVAL_MS` changes how often. See [Telemetry](https://agent-deck.devopstoolkit.ai/docs/telemetry.md).
