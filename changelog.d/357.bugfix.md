## A card title with CJK, emoji or accented characters is now shortened with an `…` instead of being clipped by the terminal

A session card's top title — the card number, the coloured agent-type badge and the display name or session id — was fitted to the card by counting **characters**, while the space it is drawn into is measured in terminal **columns**. Those are the same number only for plain ASCII. A display name like `项目目录管理` is six characters but twelve columns wide, so the deck measured the title as fitting, handed the whole thing to the renderer, and the terminal chopped whatever ran past the card's right edge — taking the trailing characters and the border fill with it, and leaving no `…` to say anything had been dropped. The card simply showed a name that was wrong, with nothing to distinguish it from a short one. Emoji in a name did the same thing.

The same miscount ran the other way for combining marks: `e` followed by a combining acute accent is two characters but one column, so a name written that way was shortened — and marked with an `…` — when it would have fitted whole.

Titles are now fitted by display width, the same rule the card's `Dir:` and `Prmt:` lines have used since they were converted. Each piece of the title keeps its own styling, so the agent-type badge holds its registry colour right up to the cut, and the `…` is paid for out of the budget, so a title that exactly fills the card is still shown whole. When the budget runs out part way through a double-width glyph the glyph is dropped rather than half-drawn, so the title comes in one column short instead of overrunning.

Plain-ASCII titles — the common case — are unchanged, character for character.

One limitation is carried over from the `Dir:` line's fix: the cut is made between characters, not between grapheme *clusters*, so an emoji ZWJ sequence or a base character carrying combining marks can still be split at the cut point, and is measured a little wider than it draws. Measuring clusters would need a Unicode segmentation dependency the deck deliberately does not carry. The total width stays correct either way, so the worst case is an odd-looking final glyph or an ellipsis one character early — never a title that overruns its card again.
