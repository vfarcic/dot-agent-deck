## The deck starts when another user has taken its temp-dir endpoint directory

On a host where `XDG_RUNTIME_DIR` is unset, such as an ordinary ssh session or a container, the deck puts its endpoints in `<temp dir>/dot-agent-deck-{uid}`. That name is predictable. Until now, a local user who created it first, before your first launch or after a `/tmp` cleaner removed it, stopped your deck from starting until they or root removed the entry, or until you set both socket overrides yourself.

The deck now starts anyway. It still never puts your sockets inside a directory someone else owns. Instead it binds them in a sibling directory it creates itself, named `dot-agent-deck-{uid}.` followed by 16 random hex digits, at mode `0700`. Nobody can create that name in advance, and once it exists it is yours. The TUI, hooks, `daemon status`, `daemon stop` and `daemon endpoint` all find the relocated daemon again without configuration, and later starts reuse the same directory. The daemon logs a warning naming both directories, and removing the foreign entry returns the next start to the usual location. Hosts where nobody took the name are unaffected: the endpoints stay exactly where they were.

See [Daemon socket security](https://agent-deck.devopstoolkit.ai/docs/remote-requirements#daemon-socket-security) for what the fallback directory does and does not protect.
