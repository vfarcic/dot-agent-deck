## An agent whose provider quota or credits run out now shows as Blocked instead of still working

A worker whose provider stopped serving it because a usage limit or credit pool was exhausted used to keep its last status. A Claude Code or Codex worker kept showing `Thinking`, and an OpenCode worker showed `Error` or `Idle`. Nothing said it had stopped, so an orchestration could wait hours for a worker that would never answer.

The deck now takes this from what the agent itself reports: Claude Code's `StopFailure` hook, Codex's session log, and the structured fields of OpenCode's error events. The card turns a red **Blocked**, and a reason line says which limit was hit and, when the provider says, when it resets. The TUI and the desktop app both show it. It stays until the agent works again or its pane restarts. There is no timer, because a spent credit pool does not reset on its own. Pi and Devin report no such signal, so they are not covered. While OpenCode is still retrying a refused request its card shows `Thinking`, and it turns Blocked once OpenCode reports the error.

A Claude Code turn that ends on any other API error (for example the provider being overloaded) now shows `Error` instead of staying `Thinking`.

`dot-agent-deck delegate` to a blocked worker still delivers the task and still exits 0, but it now warns that the worker appears blocked and suggests reassigning the task. When a worker that owes a `work-done` becomes blocked, the orchestrator gets a one-time notice in its pane. The delegation stays outstanding.

The new Claude Code hook and OpenCode plugin are installed the next time the TUI starts, and an agent that was already running may need a restart to pick them up. The Claude Code hook is installed only for Claude Code 2.1.78 or newer, because the older releases we tested ignore every hook in the settings file when it is present. Desktop-only setups and remote hosts need `dot-agent-deck hooks install` (and `hooks install --agent opencode`) run once.
