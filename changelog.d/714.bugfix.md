## An agent whose provider quota or credits run out now shows as Blocked instead of still working

A worker whose provider stopped serving it because a usage limit or credit pool was exhausted used to keep its last status. A Codex worker kept showing `Thinking`, and an OpenCode worker showed `Idle`. Nothing said it had stopped, so an orchestration could wait hours for a worker that would never answer.

The deck now reads the agent's own screen. If a Codex or OpenCode pane stops at its provider's usage-limit or credit error (Codex's `You’ve hit your usage limit…`, OpenCode's `The usage limit has been reached` or `You exceeded your current quota`), the card switches to a red **Blocked** status after about 20 seconds of quiet. A reason line says which limit was hit. The TUI and the desktop app both show it. The status stays until the agent does work again, or until the agent prints more output that pushes the error off the bottom of its screen and then goes quiet, which covers agents that report no tool or prompt activity of their own. A trailing idle or error report does not clear it, and there is no timer, because a spent credit pool does not reset on its own.

`dot-agent-deck delegate` to a blocked worker still delivers the task and still exits 0, but it now warns that the worker appears blocked and suggests reassigning the task. When a worker that owes a `work-done` becomes blocked, the orchestrator gets a one-time notice in its pane. The delegation stays outstanding.

The check is deliberately conservative, so it can miss a block. That leaves the card as it was before this change. It matches only the exact provider wording, at the start of a line among the pane's last rows, only for the agent type that prints it, and only once the pane has gone quiet. Any tool use or new prompt in the meantime cancels it. Claude Code's own limit messages are not recognised yet.
