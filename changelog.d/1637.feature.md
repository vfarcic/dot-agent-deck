## Agent hooks follow the newest installed copy, and the deck says when they do not

When more than one copy of `dot-agent-deck` is installed, for example a Homebrew CLI next to a copy in `~/.local/bin`, upgrading one of them used to leave the agents' hooks calling the other, older copy, so agent status and replies could stop arriving with nothing on screen to say why. Starting an installed copy of a newer release now switches the hooks to it, in place, still one set of hooks per agent. Starting an older copy, another copy of the same release, or a copy from a temporary directory, a disk image or a build directory leaves them alone. After a switch, Codex may ask you once to review the changed hooks.

When an agent's hooks still call an older copy, both clients tell you which agents, which copy, both versions and the fix. The TUI shows a line at the bottom of the dashboard, for example `⚠ Claude Code, Codex hooks run dot-agent-deck 0.45.1 (/opt/homebrew/bin/dot-agent-deck); this deck is 0.46.0 — Run: brew upgrade dot-agent-deck`. The desktop app shows the same words in a strip under that daemon's header, with a **Copy** button when the fix is a command. The notice goes away once the hooks run a current copy.

On macOS, the desktop app opened straight from its disk image, or from the temporary location macOS runs an app from before it has been moved, with no other copy of `dot-agent-deck` installed, no longer pins its own path into the agents' hooks. That path stops working when the image is ejected or the app is reopened, so it installs no hooks and both clients say `Move Agent Deck to /Applications and reopen it to turn agent hooks on.` (#1157).

See [Installation → When hooks run an older copy](https://agent-deck.devopstoolkit.ai/docs/installation.md#when-hooks-run-an-older-copy) and [Troubleshooting → The deck says an agent's hooks run an older dot-agent-deck](https://agent-deck.devopstoolkit.ai/docs/troubleshooting.md#the-deck-says-an-agents-hooks-run-an-older-dot-agent-deck).
