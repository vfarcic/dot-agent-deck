## Desktop workflow launch: optional task prompt and a run name

The desktop app's **Workflows** launch now works like the TUI's `Ctrl+n` dialog. Until now it refused to start without a task prompt, which neither the deck nor the TUI requires, and it had no way to name the run. Launching the same workflow twice in one project from the desktop therefore gave you two tabs with the same label.

**Task prompt** is now optional. Leave it empty and the workflow still starts: the coordinator reads its role and team, then waits for you to type the task into its pane. The confirmation dialog tells you this instead of promising to send a prompt.

The new **Run name** field names the run's tabs and cards. When the sheet opens it suggests the next free `<folder>-orchestrator-N` on the selected deck. It stops re-suggesting once you edit it, and every time you open the sheet you get a fresh suggestion. If you empty it, the run takes the workflow's own name. If the project directory already runs an orchestration on that deck, a warning says the two will share its role files and working tree, but you can still launch. If the name is already used by a live orchestration on that deck, **Launch live loop** is disabled until you change it, the same way the TUI refuses its submit.

The Workflows editor is behind the desktop's `experimental` flag. Start the app with `DOT_AGENT_DECK_EXPERIMENTAL=1` in its environment to show it.
