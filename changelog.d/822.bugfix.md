## The blocked-terminal notice is readable in light mode, and its contrast is now a decision on the record

`--status-error` was `#d0685f`, which put the terminal's own delivery notice — `Terminal input unavailable …`, 9px text on the dark instrument chrome — at **4.08:1** in light mode and at exactly **4.50:1** in dark. Light failed WCAG AA outright; dark met it to two decimal places and no further, and nothing anywhere recorded that anyone had looked at that number. The instrument chrome is one shade lighter in light mode than in dark, which is why the same pair scores differently in the two appearances.

It is now `#d57971` — the same hue and saturation one lightness step up — which reads **4.76:1** on the light instrument chrome and **5.25:1** on the dark one. The three live-status colours stay identical in both appearances, as they were designed to be, so this is one value changed in all three palette blocks rather than a light value and a dark one.

**What it costs is written down beside the token rather than left to be rediscovered.** The connection lamp uses this same token as a *fill*, and three of its four positions — the top bar, the deck selector and a deck's group header — are light chrome in light mode. No value can be light enough for 4.5:1 as text on the instrument chrome and still hold 3:1 as a fill against light paper: the two windows do not overlap at any value, so that figure was going below 3:1 the moment the text case was fixed at all. It is 2.86:1, from 3.33:1. The lamp keeps its WCAG 1.4.11 standing from the 2px ring the base rule already draws round it — the ring is what identifies the lamp against the page, and the fill only has to be told apart from the ring, which it clears at 4.37:1.
