## A report too long to inline is saved in full, and the message says where

When a worker's or a dispatched unit's report reaches another pane inline, it is cut at 4000 characters. Past that point the rest of the report was stored nowhere. The message said "the worker still holds the rest" or "the unit still holds the rest in its own worktree", but neither was true: a worker following its delivery instructions deletes its report file once it has signalled. Dispatch-completion reports, which regularly run past 4000 characters, lost their endings this way. So did a report from a worker a person tasked directly.

The deck now saves the whole report — every line, formatting intact — to a new file in that worktree's `.dot-agent-deck/` directory, and the cut message ends by naming the file. For a dispatched unit that is `.dot-agent-deck/full-report-dispatch-<timestamp>-<n>.md` in the unit's worktree, so it is removed along with the worktree. For an orchestration worker it is `.dot-agent-deck/full-report-work-done-<role>-<timestamp>-<n>.md`. Every report gets a file of its own, created fresh, so one report never overwrites another or a file an agent left there. If the file cannot be written, the message says so instead of promising the text is somewhere else.
