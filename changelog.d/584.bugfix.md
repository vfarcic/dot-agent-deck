## A `clear = true` delegate no longer discards the task when its replacement worker never comes up

Delegating to a `clear = true` worker role kills the current worker and spawns a fresh one before writing the task pointer. When that replacement failed to come up — it died during boot, or something else took the pane — the daemon waited out the full 30-second readiness window, wrote into a pane with no agent on it, had the write refused, and then dropped the task with a single line in the daemon log. The `delegate` command had already exited 0, so the orchestrator was told nothing was wrong and waited indefinitely for a completion that could never arrive. Dispatched orchestrations hit this most often, because the delegate's respawn is the only place their worker roles are ever relaunched.

The readiness wait now ends the moment the replacement's terminal reaches end-of-file, instead of always running to its deadline, so a dead replacement is noticed in the second it happens rather than half a minute later. A replacement that is not the pane's live agent is then reported into the orchestrator's own pane — "delegated worker never came up … the task pointer was NOT delivered and no work-done can arrive for it" — and its outstanding-completion record is released, so a later unsolicited report from that pane is still labelled as one. The role, command and underlying error stay in the daemon log, which the notice points at.
