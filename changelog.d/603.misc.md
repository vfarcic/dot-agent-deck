## Repository triage can classify new work and learn from maintainer corrections

New issues and same-repository pull requests can be classified by a guarded GitHub Agentic Workflow using the repository's explicit type, area, priority, and size taxonomy. Authority and lifecycle decisions remain human-owned, fork pull requests cannot reach the credentialed classifier, and automatic runs stay disabled behind `ISSUE_LABELER_ENABLED` until maintainers accept a read-only sample.

The **Issue labeler batch** workflow previews up to 20 issues or pull requests without applying labels or changing learning memory, then offers an explicit apply mode. Live predictions and human corrections persist on a dedicated memory branch, including abstentions so a label added after a complete false negative becomes a usable example.

See [Adaptive issue and pull request labeling](https://github.com/vfarcic/dot-agent-deck/blob/main/docs/develop/issue-labeling.md) for the taxonomy, activation procedure, security boundaries, and maintenance commands.
