## Restore an agent with its conversation after a restart (experimental)

An agent a deck restart stopped can now come back with its conversation instead of as a blank agent. From the **Interrupted work** list, press `s` (the TUI and the desktop app use the same key; the desktop dialog also has a **Restore** button) and choose **Restore and continue**, which lets the agent check what already happened and carry on where it stopped, or **Restore only**, which brings it back to wait until you tell it to continue (`c` and `o` in the question). The deck starts the agent with the command it was started with, in the folder it was working in, and sends it one message saying the deck restarted and resumed its session. An agent that cannot be restored with its conversation is offered **Start over in this worktree** (`w`), which starts its command again in the same folder, with a dispatched unit's saved task as its first message. By voice, say "restore the agent" or "bring back fix-login" to open the question, and choose on screen. From a shell, use `dot-agent-deck interrupted restore <id> --continue` or `--only` (with `--agent`, `--dry-run` and `--yes`), and `dot-agent-deck interrupted start-over <id> --agent <attempt>`.

Claude Code agents are restored. Codex, OpenCode, Pi, Devin and Antigravity agents cannot be restored yet and are offered Start over; the docs say what is missing for each. Restore and Start over check the item again when they act and start one agent per conversation, even from two clients or two decks. Start over refuses a Claude Code, Codex, OpenCode, Pi or Devin agent when its command, or the options its program on `PATH` is started with, would reopen an earlier conversation, and Claude Code is started over only once it reports the new conversation the deck chose for it; a script of your own named after Codex, OpenCode, Pi or Devin that picks a conversation itself is not checked, and Antigravity and plain shells are started over unchecked. Orchestrations come back in a later version. A restored dispatched unit does not report to its dispatcher, and a restored Claude Code agent may ask for permissions it did not ask for before. With the feature on, the TUI no longer restarts a restorable agent's saved pane blank when it recreates your workspace, so the agent does not come back twice.

Restoring is behind the experimental flag: set `experimental = true` under `[features]` in `.dot-agent-deck.toml`, or `DOT_AGENT_DECK_EXPERIMENTAL=1`, and use a daemon from this release.

See [Interrupted Work → Restore an agent](https://agent-deck.devopstoolkit.ai/docs/interrupted-work).
