## Start an agent from the desktop overview

The desktop app can now start agents, not only watch them. Press **New agent** on the overview — or `Ctrl+N` (`Cmd+N` on macOS), or the button on a connected deck's header — and the app walks you through what the TUI's `Ctrl+n` does, with one step in front because the desktop drives several decks: choose the deck, browse to a directory on that deck, fill in the form, and press Start. The new agent's pane opens as soon as the deck lists it. This closes [#1041](https://github.com/vfarcic/dot-agent-deck/issues/1041).

**What the TUI's form starts, the desktop now starts too**: a plain agent in a directory you browse to, an orchestration in a project directory (no task prompt, and the Name becomes the run's title), and the `schedule`, `schedule: issues` and `dispatcher` authoring agents, which receive the same seed prompt the TUI types into them. `schedule: issues` is offered where the deck's own experimental flag is on. The one exception is workspace modes, which are not offered because they are being removed.

**The agent lands on the deck you chose.** With **All Decks** selected it starts on the deck you picked in the first step, not on the local deck: the flow names its deck on every request, and if that deck goes away halfway through, the dialog says so instead of starting the agent somewhere else. The directory browser reads the chosen deck's filesystem, so on a remote deck you browse the remote machine rather than your own. The form is prefilled the way the TUI's is — the deck's configured default command, then the command you last started there from this app during this session — and a refused start keeps the dialog open with the error beside the values you entered.

**A deck can name where agent creation starts browsing.** `dot-agent-deck config set default_dir <absolute path>` sets it in the deck's own config file, beside `default_command`. The desktop's directory browser opens there instead of your home directory, and the TUI's `Ctrl+n` picker and the Scheduled Tasks manager's Add open there instead of the directory you launched the TUI from. It is a starting point, not a limit, and a value that is unset or cannot be opened is ignored silently.

**Older decks still work, with less.** A deck from before this release cannot list directories, so you type the directory's absolute path instead; it cannot report its default command, so Command is prefilled from what you last started there from this app; and it cannot compose the authoring prompts or start orchestration roles from here, so those choices are left out with the reason shown. A plain agent can be started on any connected deck.

Demo reel for PRD #1223: https://youtu.be/X_QDS_j15zY. Watch before merging. It shows a real interactive Haiku agent started end to end through the desktop New agent flow — deck chosen, directory browsed to on that deck, form filled, Start pressed — working live in its own pane and reporting back a unique sentinel filename it could only have found by listing the directory it was actually started in.
