## Start an agent from the desktop overview

The desktop app can now start agents, not only watch them. Press **New agent** on the overview — or `Ctrl+N` (`Cmd+N` on macOS), or the button on a connected deck's header — and one dialog does what the TUI's `Ctrl+n` does, with a Deck field in front because the desktop drives several decks: choose the deck, browse to a directory on that deck, set Mode, Name and Command, and press Start. The new agent's pane opens as soon as the deck lists it. This closes [#1041](https://github.com/vfarcic/dot-agent-deck/issues/1041).

**What the TUI's form starts, the desktop now starts too**: a plain agent in a directory you browse to, an orchestration in a project directory (no task prompt, and the Name becomes the run's title), and the `schedule`, `schedule: issues` and `dispatcher` authoring agents, which receive the same seed prompt the TUI types into them. `schedule: issues` is offered where the deck's own experimental flag is on. The one exception is workspace modes, which are not offered because they are being removed.

**The agent lands on the deck you chose.** With **All Decks** selected it starts on the deck in the Deck field, not on the local deck: the dialog names its deck on every request, and if that deck goes away while the dialog is open, it says so instead of starting the agent somewhere else. The directory browser reads the chosen deck's filesystem, so on a remote deck you browse the remote machine rather than your own. Command is prefilled the way the TUI's is — the deck's configured default command, then the command you last started there from this app during this session — and a refused start keeps the dialog open with the error beside the values you entered.

**Agents and orchestrations can be closed from the overview too.** Each agent's row has a stop control, and an orchestration's card has a **Close** that stops every role; both ask for confirmation first, and a role whose stop could not be confirmed is named. An agent started or stopped from the desktop now appears in, or leaves, an attached TUI straight away — an orchestration with its tab — instead of when that TUI is next touched.

**The Agent field is gone from the New Agent form, in the TUI and the desktop.** It only copied an agent's default command into Command, which you can type directly.

**A deck can name where agent creation starts browsing.** `dot-agent-deck config set default_dir <absolute path>` sets it in the deck's own config file, beside `default_command`. Both clients honour it: the desktop's directory browser opens there instead of your home directory, and the TUI's `Ctrl+n` picker and the Scheduled Tasks manager's Add open there instead of the directory you launched the TUI from. It is a starting point, not a limit, and a value that is unset or cannot be opened is ignored silently.

**A deck from before this release cannot be chosen.** It cannot list its directories, so the Deck field shows it disabled with that reason; start agents on it from the TUI on its host, or upgrade it.

**By voice, end to end.** Say "new agent" (or "spawn an agent", "I want another agent") to open the dialog, naming a deck to preselect it — the reply always says which deck is preselected, so a wrong guess is heard before anything starts, and a deck the dialog shows disabled is never the one preselected: naming it gets the reason the dialog shows ("cannot take a new agent, so none is preselected: No deck is listening on the configured socket") — then name directories on screen to browse, choose a mode, say "use claude" to set Command to that agent's default command, name the agent, and say "start it" — which starts at once, with no second confirmation, because the form you are looking at already shows what will run. "Start the new agent" with the dialog closed opens it. The buttons' own words work as spoken commands too: say what the Start button reads — "Start agent", or "Start orchestration" once an orchestration is chosen — and it starts; read a Mode chip ("No mode", "dispatcher") to choose it, or "Close new agent" to close the dialog. The orchestration card's bare "Close" is the exception by design: said alone it stops nothing, and closing a run by voice needs it named — "close the review orchestration". "Cancel" or "never mind" closes the dialog. Command itself is never dictated. You do not have to say a name exactly as the screen shows it, or hope the transcriber spells it that way: "stop the orchestration 1" reaches `dot-agent-deck-orchestrator-1`, "close the orchestration" reaches the one on screen, and "open the billing folder" opens `billing-service`. Stopping keeps its confirmation, and it names what will stop: "stop the tester" and "close the review orchestration" each ask before anything stops, and "close the agent" only closes the agent's view — it never stops the agent.
