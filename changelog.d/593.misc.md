## The release assembler now runs on macOS's bash, instead of dying on its first line of work

`scripts/assemble-changelog.sh` opened by building its type-to-heading map as an associative array — `declare -A TYPE_HEADERS=([added]="Added" …)`. Associative arrays are bash 4. macOS ships `/bin/bash` 3.2.57, where `declare -A` does not merely go unsupported: the assignment degrades to an ordinary *indexed* array assignment, so `[added]` is evaluated as an **arithmetic** subscript, `added` is read as an unset variable, and the script's own `set -u` kills it on that line. The whole run was one message — `assemble-changelog.sh: line 12: added: unbound variable` — and nothing below line 12 had ever executed on bash 3.2.

It never broke a release, because `release.yml` runs the assembler on `ubuntu-latest` and nothing else invokes it. What it did cost was the first maintainer to run the assembler locally on a Mac, who would have hit a hard failure whose message names a variable that appears nowhere in the script; and it is what forced [#582](https://github.com/vfarcic/dot-agent-deck/issues/582)'s new tests to be scoped to Linux, since they turned `build-macos` red with four identical copies of that message.

The map is now a `type_header()` `case`, which needs no bash 4 and no feature detection — the dependency is removed rather than diagnosed, so there is no version to check and no second code path to keep working. Behaviour is unchanged on bash 4+: the same nine types map to the same six headings, and the same aliasing (`feature` under Added, `breaking` under Changed, `bugfix` under Fixed) still collapses into one section each. A type listed in `TYPES` with no matching arm now aborts with an error that names the type and says what to add, rather than the previous bare `unbound variable`; both fail loudly, which is the property that mattered. `.claude/skills/verify-pr/scan.sh` was moved off `declare -A` for this same reason under [#521](https://github.com/vfarcic/dot-agent-deck/issues/521), and this is the same fix in the one other place that needed it.

`tests/assemble_changelog.rs` is back to `#![cfg(unix)]`, so `build-macos` proves this rather than leaving it resting on review, and two tests now cover the mapping the existing four never touched beyond `feature` and `bugfix`. Both read the script's `TYPES` array and `type_header()` arms out of the script itself rather than mirroring them: one checks statically that the two agree in both directions, the other feeds the assembler a fragment of every declared type and checks each renders under the heading the script's own arms map it to, with aliases still collapsing into one section. Deriving the lists is what makes the lockstep real — a mirrored copy would never feed a newly added type, so the mapping would go untested while the test still reported success, and the failure would surface as a release shipping short a section. The defect was reproduced under a real bash 3.2.57 before anything was changed, all four pre-existing cases failing at `line 12` exactly as `build-macos` had; the fix was then reverted to confirm they go red again.

The sweep the issue asked for turned up one more instance of the same class, and it is fixed here too: `.claude/skills/demo-reel-adapter/build.sh` built its clip list with `mapfile -t`, which is also bash 4 — on bash 3.2 `mapfile` is not a builtin at all, so `build.sh reel` died with `mapfile: command not found` and exit 127 before selecting anything. It is now an `IFS= read -r` loop, which is safe because the id producer newline-terminates every line, so no unterminated final line can be dropped. Checked differentially rather than by inspection: across empty, single, multi, embedded-space, embedded-blank-line and embedded-tab inputs the loop builds a byte-identical array to `mapfile -t` on bash 5, and the same array again on bash 3.2. That was the only other bash-4 construct in the file, so the whole script is now 3.2-clean.

One instance is knowingly left: `.claude/skills/dot-ai-tag-release/cleanup.sh` uses `declare -A` twice, but it is a `dot-ai-`prefixed synced mirror that gets overwritten wholesale by upstream syncs, so a fix here would be reverted rather than kept. It needs an upstream request instead.

Release tooling and local skills only; no change to the shipped binary.
