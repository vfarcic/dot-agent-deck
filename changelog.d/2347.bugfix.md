## Blocked Claude Code Prompts No Longer Leave the Agent Looking Busy

When another `UserPromptSubmit` hook blocks a Claude Code prompt, Claude runs no turn, but the deck's card used to keep showing the agent working until its next turn ended. While it did, the doorbell did not ring, so a deck message whose prompt was blocked waited until you typed something yourself.

The deck now notices that Claude dropped the prompt and shows the agent idle again, in the TUI and in the desktop app. Claude Code puts the blocked prompt back in its input box, which the deck does not type over, so the card now says the waiting message is not yet taken instead of showing the agent busy; press Enter in the agent's pane to send that prompt again, and the message is handed over. This works when Claude Code keeps a session transcript, as it does by default.
