The card overlay is gone: clicking an agent's card, its name or anywhere else on it, now opens the agent's pane with a **Card** panel beside the terminal (above it in a narrow window). The panel shows what the deck checked (the status, the pull requests and issues the agent reported, what you sent from the card) and what the agent says (its summary and status, why it needs you, its fields and its questions with their answers as buttons), then the agent's actions as the same icons as on the card. It opens on its own when you open the agent from its card or when the agent needs you, otherwise it stays as you last left it, and it never opens or closes while you watch the pane; the **Card** button in the pane's header shows or hides it. The header also moves to the previous agent, the next one and the next one that needs you, with `[`, `]` and `n` while you are not typing in the terminal. The overlay's reply box is gone: type your reply into the agent's terminal, or say "open the coder" and then "tell it …". **Show card** in a table row's menu opens the pane with the panel, and the menu's action for the agent opens the pane under a small review that shows what it sends. An action that asks first, closing an agent, and an action whose text the agent wrote open that review, from the card, the panel or voice, and nothing is sent until you press **Send**. By voice, "show the coder's card" opens its pane with the panel, "show the card" and "close the card" show and hide the panel, and "next agent", "previous agent" and "next one that needs me" move between panes; "reply to the coder …" is no longer a command.

Agent cards in the desktop app can send one action to many agents at once. Every card on a daemon that supports batches has a checkbox; ticking one shows a bar at the bottom of the Dashboard with the number of cards selected, an icon for each action they offer and **Clear**, and ticking a closed card selects every agent under it. Every batch opens a confirmation first that lists each agent that gets the action and the agents that are skipped; text several agents get is shown once, above the agents that get it, and an agent with different text keeps its own quotation. A long list of agents shows the first few names and **+N more**, and the skipped agents are one line counting them by reason, such as "214 skipped: 180 don't offer Go ahead, 34 aren't running", which you press to list them grouped by reason. After **Send** it shows what happened for each agent, and one agent failing does not stop the others. Each delivery is recorded on that agent's own card. By voice, "go ahead on everything under the dispatcher" opens the same confirmation, and "select the coder's card" followed by "go ahead on the selected agents" opens it for a selection built by voice; "clear the selection" unticks them all.

A card now shows an icon for each action its agent offers, in a row at the bottom of the card: hover it, or reach it with `Tab`, to see the action's label and the exact text it sends, just below or above the icon; an icon under the pointer is drawn filled and outlined, and one reached with `Tab` has a ring. An action that asks first still asks, and one whose text the hover cannot show whole, too long or with more lines than the window holds, opens the review to show all of it first; saying the action by voice sends as before. A card shows up to three icons, with **+N** opening the agent's Card panel for the rest. The icons sit together in a tinted box with a border, and the batch buttons are icons in the same box.

The new **Card actions** editor, opened from the Cards toolbar, adds, changes, hides and removes card actions without editing a file: each action shows where it came from, and its form has the exact text, **Tell agents when to offer it** (which agents read and the card does not show), an icon picked from a searchable grid, whether it shows on the card or only in the Card panel, and whether it asks first or is offered on every card. It edits the catalog of the daemon that runs the agents, on that daemon's machine, keeps the file's other settings and comments, and applies at once. A save is refused when the action changed in the file since the editor showed it, or when the daemon sees the file change while it saves; it waits for `dot-agent-deck config set` rather than saving over it, and **Refresh** reads the list again. Card fields are still changed in the file, and so are actions from the TUI, which has no cards view. By voice, "open the card actions editor", "add a card action", "edit the ship it action" and "remove the ship it action" open the editor, its forms and a removal's confirmation, and voice also picks the daemon, refreshes the list and sets the form's icon, checkboxes and placement; saving, removing, hiding and restoring are pressed by hand. These need a daemon from this release; a daemon from an earlier release is shown read-only. `dot-agent-deck config set` and the editor wait briefly for each other's saves; if the other keeps them waiting, or the lock file beside the configuration file is not safe to use, they save nothing and say why, and you can try again.
