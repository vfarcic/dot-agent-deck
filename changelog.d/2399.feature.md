Agent cards in the desktop app can send one action to many agents at once: from a card with agents under it (it reaches every agent under that card) or from a selection of cards, where selecting a closed card selects everything under it. Every batch opens a confirmation first that lists each agent that gets the action and each agent that is skipped and why; text several agents get is shown once, above the agents that get it, and an agent with different text keeps its own quotation. After **Send** it shows what happened for each agent, and one agent failing does not stop the others. Each delivery is recorded on that agent's own card. By voice, "go ahead on everything under the dispatcher" opens the same confirmation, and "select the coder's card" followed by "go ahead on the selected agents" opens it for a selection built by voice.

A card now shows an icon for each action its agent offers, in a row at the bottom of the card: hover it, or reach it with `Tab`, to see the action's label and the exact text it sends, and press it as you would the action in the card's overlay (an action that asks first still asks, and one whose text the hover cannot show whole, too long or with more lines than the window holds, opens the card to show all of it first; saying the action by voice sends as before). A card shows up to three icons, with **+N** opening the overlay for the rest. The batch buttons are icons too.

The new **Card actions** editor, opened from the Cards toolbar, adds, changes, hides and removes card actions without editing a file: each action shows where it came from, and its form has the exact text, when agents should offer it, an icon picked from a searchable grid, whether it shows on the card or only in the overlay, and whether it asks first or is offered on every card. It edits the catalog of the daemon that runs the agents, on that daemon's machine, keeps the file's other settings and comments, and applies at once. A save is refused when the action changed in the file since the editor showed it, or when the daemon sees the file change while it saves; it waits for `dot-agent-deck config set` rather than saving over it, and **Refresh** reads the list again. Card fields are still changed in the file, and so are actions from the TUI, which has no cards view. By voice, "open the card actions editor", "add a card action", "edit the ship it action" and "remove the ship it action" open the editor, its forms and a removal's confirmation, and voice also picks the daemon, refreshes the list and sets the form's icon, checkboxes and placement; saving, removing, hiding and restoring are pressed by hand. These need a daemon from this release; a daemon from an earlier release is shown read-only.
