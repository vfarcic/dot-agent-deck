## A wrapped agent no longer survives its own wrapper as an unkillable process

`dot-agent-deck wrap` opened the inner pseudo-terminal for the agent it wraps and then let the agent inherit the terminal's **master** descriptor alongside the slave it actually needs. Because the agent itself held that master, the terminal's reference count could never fall to zero: when everything above the agent died the slave never hung up, the agent's `read` never returned, and it kept running with a working directory that had already been deleted. Nothing could recover it — the agent is `setsid`'d into its own session at spawn, so no process group kill from the deck, the daemon or a shell can reach it. A census of one development machine found 221 such processes, the oldest alive 9.4 days, each one holding an e2e temp directory against `cargo xtask clean-e2e-tmp`, which never reaps a directory whose owning process is still alive.

The master is now marked close-on-exec the moment it is created, so the wrapped agent gets the slave and nothing else — the same hygiene `portable_pty` already applies to every unwrapped pane, which is why the leak was wrapper-shaped. The visible change is that an agent whose wrapper is ended uncatchably (the deck's own SIGKILL escalation past the terminate grace, an OOM kill, a crashed wrapper) now exits with its terminal within a moment instead of surviving it. Nothing about a normally running wrapper changes: the agent keeps its terminal, its controlling terminal, and its line discipline, and `wrap` still reaps it on every ordinary exit path.

This is the second half of the same defect as the previous release's wrapped-child lifetime backstop. That backstop bounds an agent no hangup can reach — one that ignores SIGHUP and reads nothing — and it stays; it is armed only under the test harness. This fix needs no such gate, so it holds on a Ctrl-C'd run, a panic, or a timeout just as well.
