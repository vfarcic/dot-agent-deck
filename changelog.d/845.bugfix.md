## Desktop: an explicit Light/Dark choice is on the first painted frame

Choosing Dark on a light machine — or Light on a dark one — used to show the operating system's palette for a moment at every launch, before the window flipped to the choice that was actually stored. The choice lives in `desktop.toml` and only arrived once an async read had answered, by which time the window had already painted; until then the document looked exactly like "follow the OS", because that is what an unset theme means.

The desktop app now reads the stored mode before the window exists and puts it on the document root through an initialization script, which the webview runs before it parses the page. The first painted frame is the chosen one, with no blank frame in front of it. Following the OS is untouched: a user who has made no explicit choice still gets the machine's palette, live and in both directions, and a choice made in the settings sheet still applies with no restart — including one made while the initial read is still in flight.
