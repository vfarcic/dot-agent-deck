## Codex Hook Trust Problems at Startup Are Reported

When the deck starts, it installs its Codex hooks and marks them as trusted so Codex runs them. If that ended with none of its hooks trusted, the deck said nothing at the default log level, so Codex sessions could run without reporting status through those hooks and nothing showed why. The deck log now records this as a warning naming the directory the deck checked from, and records how many hooks it trusted when it succeeds.

Starting the deck, or running `dot-agent-deck hooks install --agent codex`, from a directory that has since been deleted no longer fails to trust the Codex hooks.
