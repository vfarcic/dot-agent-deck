## Per-run CPU and memory that count detached work (Linux)

When the deck's daemon runs as the service `dot-agent-deck daemon install` sets up, it now starts each agent in a cgroup of its own, and `dot-agent-deck-collector` reads it. Until now the collector counted only work that stayed among a run's processes, so a command that detached from the agent and finished between two samples was mostly lost, and one that also cleared its environment almost entirely.

A run in its own cgroup gets two more metrics, `deck.run.cgroup.cpu.time` and `deck.run.cgroup.memory` (with `deck.memory.kind` `current` and `anon`). They count everything the run started, wherever it went. The existing `deck.run.cpu.time`, `deck.run.memory.pss` and `deck.run.processes` are sent for every run as before, so use the `cgroup` metrics where a run has them. `deck.collector.schema_version` is now `2`. Each run's cgroup is named `run-<deck.run.id>`, so a tool that groups by cgroup can read it as well. Stopping or restarting the service still stops all of its agents.

A daemon that the TUI or the desktop app started on its own works as before, and so do a host without systemd or cgroup v2, and macOS. A service installed by an earlier release does not get this until you run `dot-agent-deck daemon install` again and restart the service once its agents' work is done (restarting stops them). To turn it off, set `DOT_AGENT_DECK_RUN_CGROUPS=0` for the service.

See [Telemetry](https://agent-deck.devopstoolkit.ai/docs/telemetry.md) and [Run the Daemon as a Service](https://agent-deck.devopstoolkit.ai/docs/daemon-service.md).
