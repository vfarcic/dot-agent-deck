## `dispatch_020`'s user-input fixture no longer uses a fixed sleep as a synchronisation primitive

`dispatch_020_payload_guards_are_scoped_to_one_delivery` hard-red the **required** `build` job on PR #843 — a Renovate no-op whose diff was byte-identical to `main`, so no dependency change could explain it. The panic was at a *precondition*, not the property under test: "the production-shaped bracketed multiline paste must physically reach the PTY". `src/spawn.rs`'s `type_user_bytes` wrote a user draft to a real PTY, flushed, and then slept a fixed 75 ms; nothing waited for the bytes to become observable, so every caller's "must physically reach the PTY" assertion was a bet on a PTY round trip beating that constant. The fast tier sets `retries = 0` and neither `dispatch_020` nor `dispatch_018` is covered by a `.config/nextest.toml` override, so losing that bet once reddens a blocking check.

Reproduced before fixing, because the issue was filed from a code read and one CI log. Under 3x and 4x CPU oversubscription the unmodified test passed 45/45 runs — the race is real but rare, which is why luck was not the route. Shortening the sleep to 0 ms and re-running under 4x oversubscription failed **15/15**, with the dominant panic at `src/spawn.rs:4186` carrying the exact CI message. That pins the causal chain rather than inferring it.

The fix has **two halves, and the second is easy to mistake for tidiness.** The sleep is replaced by a content-keyed bounded poll: each maximal printable run of the written bytes must appear in `registry.snapshot(agent_id)`, twice for a run whose line the write completed (once from the line discipline's echo, once from `/bin/cat` copying the finished line back) and once for a run left unterminated — the same "exactly TWO line terminators per write" arithmetic `completed_lines` already documents, counted by content instead of by clock. A bare newline control frame (`Ctrl+J` is `\n`, `Alt+Enter` is `ESC \r`, plain `Enter` is `\r`) carries no printable byte, so `type_user_frame` waits instead for the second appearance of the draft whose line it completes, and `type_user_bytes` now *asserts* rather than silently no-ops when handed a payload it cannot observe.

The second half is that the pane must be **drained before** the write, which surfaced only because the first half turned a silent 75 ms bet into a loud 8 s diagnostic. `/bin/cat` and the echo are two independent writers into one PTY output queue and the kernel commits echo in batches, so a pending `cat` copy can land *in the middle* of the write's echo:

```text
"automatic payload before plain Enter\r\n"   <- echo of the earlier line
"user"                                       <- this write's echo, cut off
"automatic payload before plain Enter\r\n"   <- cat's copy, interleaved
" turn completed with plain Enter"           <- the rest of this write
```

The scrollback is append-only, so that split is permanent — no amount of waiting reassembles the draft, and every `windows(draft.len())` search in the file, the tests' own preconditions included, then fails for good. Each `type_user_draft` call site now states how many input lines precede it, and `wait_for_drained_lines` (the existing `wait_for_detached_delivery_attempt` poll, renamed to the vocabulary of a caller counting writes) drains them first, leaving `cat` with nothing to copy until the write terminates a line.

Measured, all at 4x CPU oversubscription on 16 cores: 0 failures in 50 runs with both halves; **2 failures in 30** with the drain alone disabled, at the final exact-equality assertion rather than the precondition. So neither half is redundant, and the fix is a wait rather than a wider constant — CLAUDE.md rule 5 records for #818 why moving the threshold is not a fix.

Scope is deliberate. `src/spawn.rs` holds 29 `sleep` calls, of which **25 were in the test module and 4 are production timers** outside it; this change converts the two on the observed path and leaves the rest, 12 of which are correct negative-observation windows that must stay and one of which is a fixture input rather than a wait. Six others are the same defect on unobserved paths and are reported for follow-up. No shipped behaviour changes — every hunk is inside `#[cfg(test)] mod tests`.
