## Orchestrator remit re-asserted after compaction and /clear

The orchestrator's role prompt — the pointer telling an orchestration tab to read its context file and adopt the orchestrator role, available agents, and delegation protocol — used to be delivered only once at spawn. On a long-running orchestration, once the start-role pane's context compacted, or once the user cleared it, that context was gone with nothing to bring it back — the user had to retype the pointer instruction by hand.

The remit pointer is now retyped automatically in both cases: the moment the start-role pane's status is observed compacting, and the moment it reports a `/clear` (a `SessionStart` event from Claude Code), the same bounded retry-and-confirmation delivery used at spawn re-runs and re-delivers the pointer. Only the orchestrator's own start-role pane is affected — a worker/delegate pane is never touched — and the `/clear` trigger applies to Claude Code start roles.

No configuration is needed; this is on by default for every orchestration tab.
