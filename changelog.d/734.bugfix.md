## Windows Codex Hook Commands Are Now Runnable

Hook commands written into a Codex `hooks.json` are quoted for the shell that will actually run them, so a Windows user finally gets a command line `cmd.exe` can execute. The deck previously quoted every hook command for a POSIX shell on every platform, which wrapped the Windows path in single quotes — `'C:\Users\...\dot-agent-deck.exe' hook --agent codex`. `cmd.exe` does not implement `'` as quoting at all: it reads the quote as an ordinary character and looks for a file whose name begins with one, so every deck hook silently failed to fire and the dashboard cards for that session never updated.

The dialect now follows the interpreter rather than the compile target. Codex hands the whole command string to `%COMSPEC%` (else `cmd.exe`) with `/C` on Windows and to `$SHELL` (else `/bin/sh`) with `-lc` elsewhere, so a Windows path is emitted verbatim when it needs no quoting and double-quoted when it contains a space — `"C:\Program Files\dot-agent-deck\dot-agent-deck.exe" hook --agent codex`. POSIX hosts are byte-for-byte unchanged, as is the `bash`-fenced command word the deck writes into delegate and work-done instructions, which deliberately targets a POSIX shell on every platform.

This is only reachable on Windows through `$CODEX_HOME`, which Codex honours on every platform (the deck otherwise skips Codex hook installation there because `$HOME` is normally unset). Nothing needs to be migrated by hand: the next hook install recognises the old rule by its `hook --agent codex` signature, removes it, and writes the runnable spelling in its place. Devin's installer is Unix-only and is unaffected.
