## Desktop GUI, published as an unsigned alpha

Every release now carries the desktop GUI as an installable bundle: a `.dmg` for macOS on Apple Silicon, and a `.deb` for Linux x86_64. Until now the only way to run it was to clone the repository, install Tauri's system prerequisites, build a matching daemon from the same checkout and launch `pnpm tauri dev` — a maintainer's workflow that nobody was actually using, which meant anything that only broke in a packaged build went unnoticed.

The assets arrive on the release as `dot-agent-deck-desktop-alpha-<platform>.<ext>`, with their own `checksums-desktop-alpha.txt`. Each bundle carries a matching `dot-agent-deck` daemon inside it, stamped with the same version, so an installed GUI can start its own daemon without a Rust toolchain on the machine.

**These builds are unsigned and labelled alpha, and both words are meant.** Your OS will warn you on first launch. On macOS, move the app to `/Applications` and then clear the quarantine flag with `xattr -dr com.apple.quarantine "/Applications/Agent Deck.app"`; the release notes repeat the exact command next to the downloads. Signing and notarization are tracked separately in [#757](https://github.com/vfarcic/dot-agent-deck/issues/757). There is no user-facing installation page yet — that is deliberate while the GUI is alpha, and [#765](https://github.com/vfarcic/dot-agent-deck/issues/765) writes one when it stops being.

Nothing about the CLI release changes. The bundles are built beside the existing binary matrix rather than in front of it, and the job that creates the GitHub Release does not wait on them, so a bundler that fails or is skipped cannot delay a tag or block one — it turns the workflow run red while the release itself stays green and complete. A `skip_desktop` input exists for deliberately cutting a release without the GUI when the bundler is known-broken.

Windows is not included. A bundle carries the daemon as a sidecar and no Windows daemon binary is published today, and a Windows GUI cannot connect to a Linux daemon instead, because the two speak different local transports — a named pipe on Windows, a Unix socket everywhere else. That makes Windows packaging dependent on [#741](https://github.com/vfarcic/dot-agent-deck/issues/741) rather than on Windows bundling itself; the sidecar staging script now handles Windows executable naming so the groundwork is in place.
