## The Test Harness's Own Unit Tests Run Once Instead of Once Per Binary

The 108 pure-function unit tests that cover `tests/common/mod.rs` — temp-root containment and name parsing, credential collection and env-var trimming, the redaction range arithmetic and the wrapped-credential matcher — used to execute once for every test binary that linked the harness, because `cfg(test)` is true in every integration-test target rather than only in the one being tested. They now live in `tests/common/harness_unit_tests.rs`, compiled by a single dedicated binary (`tests/harness_unit.rs`), so each runs exactly once per tier.

Measured on this machine, before and after, with `cargo nextest list --workspace --exclude dot-agent-deck-desktop`: `cargo test-fast` drops from 3939 selected tests to 2211, `cargo test-e2e` (lane 1, what CI runs on every PR) from 9309 to 2397, and `cargo test-e2e-live` (lane 1 + lane 2) from 11962 to 2458. The same 108 test names are selected before and after, and every non-harness test in all three tiers is untouched — this removes duplicate executions, not coverage.

The duplication was multiplicative rather than additive, so it also removes a standing disincentive: each unit test added to the harness previously cost 65 executions in every lane-1 run, on a module the project deliberately keeps well tested.
