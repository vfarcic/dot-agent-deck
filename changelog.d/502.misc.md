## The deterministic e2e tier runs in CI; the real-agent half runs on your machine and nowhere else

The end-to-end tier now runs in CI. Until this change no workflow ran it at all: `tests/e2e_*.rs` was type-checked by the `build` job's clippy step and executed by nothing anywhere, which is how [#460](https://github.com/vfarcic/dot-agent-deck/issues/460) stayed broken on `main` across twelve commits. In its place a contributor was expected to run all 71 files locally before every pull request — an obligation that got worse the more the project leaned on parallel agents, because every dispatched unit ran the whole tier and N of them meant N copies competing for one machine ([#415](https://github.com/vfarcic/dot-agent-deck/issues/415) measured 6-7 of 40 files failing in parallel against 40 of 40 at `-j 1`).

A third cargo feature, `e2e-live`, splits the suite by whether a test **reaches a real agent**. The 24 such files open with `#![cfg(all(feature = "e2e", feature = "e2e-live"))]`; the other 47 open with `#![cfg(feature = "e2e")]`. (Three files in each group add a `unix` term to that attribute.) `cargo test-e2e` is lane 1 — the deterministic files, which need no credential and now run on every pull request in a new `e2e-deterministic` job. `cargo test-e2e-live` is lane 2, a *superset* run of all 71 files, and it runs **only on a developer's machine**. The new CI job is deliberately advisory rather than a required check, and the required set is unchanged.

**No e2e test reaches a real agent in CI, and no test credential is registered on this repository.** Read that narrowly: it is a statement about the test tier, not about the repository holding no secret at all. The Codex issue-labeler is a separately credentialed workflow — it passes the repository secret `OPENAI_API_KEY` into a `codex exec` step and genuinely reaches a real agent — decided on its own terms and documented in `docs/develop/issue-labeling.md`, and out of scope here. An earlier revision of this work built a credentialed `e2e-live` workflow — API keys on a `live-e2e` GitHub Environment with a required reviewer, running per-merge on `main` and on a labelled pull request. It was removed before anything was ever registered, for two reasons. Running a credentialed job *less often* reduces the number of exposures, not the existence of the vulnerability: once a key is a secret on a public repository it is reachable by whatever makes that workflow run, and pre-merge validation exists precisely so that branch code — workflow definitions included — executes with it. And the boundary that matters is not "tests that read a key" but "tests that reach a real agent by any route", because a developer's agent CLIs are already authenticated, so a test that spawns `claude` and never touches `ANTHROPIC_API_KEY` still spends a credential. The `e2e-live` feature draws exactly that wider line, which is why the feature, the alias and the classification stay while the workflow went. The `run-live-e2e` label is deleted too; git history holds the workflow if the decision is ever revisited.

**What replaces the removed obligation is three tiers rather than none.** `cargo test-fast` stays the per-task gate. On top of it, run **the tests covering what you touched** — any tier, credentialed included — found through `tests/CATALOG.md`, the `#[spec]` annotations or `cargo xtask list-tests`, and named in the report. Lane 1 in full is CI's job: read its run rather than reproducing it, which is what `/verify-pr` now does instead of spending tens of minutes of PTY time on a result less trustworthy than CI's. Nothing can *enforce* the credentialed half — the only mechanism that could is CI, and CI has no credentials by design — so that is recorded as an accepted trade with its cost stated: real-agent regressions surface when someone runs them, not on a schedule.

The clippy gate grows the new feature — `cargo clippy --workspace --all-targets --features e2e,e2e-live -- -D warnings` — because under `--features e2e` alone the 24 re-gated files compile to empty crates, the same hole class closed by [#407](https://github.com/vfarcic/dot-agent-deck/issues/407), [#436](https://github.com/vfarcic/dot-agent-deck/issues/436) and [#489](https://github.com/vfarcic/dot-agent-deck/issues/489). With the credentialed lane gone that flag carries the whole weight: it is now the **only** thing in CI that compiles a third of the e2e tier.

**A real agent's rendered credential has to stay out of the artifacts a local run leaves behind, and that is a sharper problem than CI ever posed.** The harness already redacted every *persisted* recording — `final-grid.txt`, its SVG, `fixture.toml`, and the cross-event `full-stream.cast`. It did not redact **captured test output**, which is the sink the same failure reaches first: the condition that renders an API key's 20-character approval suffix on screen is the same condition that hangs the agent on the prompt, and the resulting harness timeout interpolates that grid straight into a panic message. A process-global redacting panic hook ([#785](https://github.com/vfarcic/dot-agent-deck/issues/785)) now closes that at the output seam — raw snapshots stay raw so assertions keep matching, and every harness entry that can obtain terminal content or handle a credential installs the hook first, which also covers the in-process daemon tests that have no `TuiDeck` and so could never have had a per-deck redaction object. Two of the four credential importers registered nothing from the documents they copy and now both do: the Codex one, whose `~/.codex/auth.json` can be *produced* from a raw `OPENAI_API_KEY` on a key-only host, and the Claude one, which was excused on the ground that its credential set "is never rendered" — a convention rather than a structural property, and the route most demo-reel clips actually take.

Where those artifacts go is the reason this matters. A `.cast` from a real-agent run is what the demo reel stitches into a video, uploads to YouTube, and links from the pull request *and* the changelog — which is to say from the public release notes (PRD #180/#20). Reel eligibility requires a real agent spinning up, so the recordings that pipeline selects are exactly the credentialed ones, and there is no environment gate and no secret masking anywhere along it. **So the reel upload is now PRIVATE by default** rather than unlisted: unlisted means anyone with the link can watch, and that link is published automatically, so a credential-bearing recording reached a publicly-reachable URL with no human in between. Private keeps the automation exactly as it was — the channel owner can always watch their own private videos, so an agent still uploads unattended and the link still goes in the PR — and turns the human review into a **publication** gate: flipping the video before a release is a deliberate step, and the video id survives the flip so the link already posted starts working with no re-upload. `upload.sh --privacy unlisted|public` is the explicit escape hatch, and the engine never passes it.

The JUnit report a failing local run writes carries failed and retried tests' stdout and stderr for the same reason; `scripts/junit-strip-output.py` rebuilds it from an attribute whitelist so it cannot carry free text at all — but nothing invokes it for you, so `docs/develop/e2e-lanes.md` now carries an inventory of local credential-bearing state classified by what actually protects each row, including the three that surprise people (nextest's live console output and the scrollback it lands in, the headless `daemon-stderr.log`, which is never redacted, and the isolated HOME, which holds working credential state by design) and the plain statement that the raw report is unprotected unless a human remembers.

**The redaction is best-effort, and the docs say so rather than implying completeness.** It is a blocklist: it removes values the harness registered, and two leaks remain reproduced in the matcher itself — a registered value that begins inside an earlier match, and a decoy continuation that suppresses a real one and leaves the text untouched. Both are [#810](https://github.com/vfarcic/dot-agent-deck/issues/810), which specifies the replacement (an all-match search over deduplicated continuation states, exact occurrences from an overlap-preserving multi-pattern scan, and a cost budget that fails closed) rather than a fifth point fix — the four before it each closed a real leak and each was followed by another of the same shape. What the matcher does guarantee was verified: every range it produces reproduces registered credential bytes exactly, so it over-redacts rather than mis-redacts.

**A stale recording is much harder to publish, though "no longer stale" would be too strong.** `TuiDeck` writes its artifacts only from `Drop`, so a `SIGKILL`, a nextest timeout, a Ctrl-C, a runtime skip before launch or a failed re-recording used to leave the *previous* run's `full-stream.cast` on disk — and the demo-reel adapter selects a cast on path existence alone, so a recording made before these redaction fixes could still be stitched into the published video. The harness now discards those artifacts before it spawns the deck and before either outcome of a runtime skip, and a deletion that fails for any reason other than "not there" fails the test instead of printing a warning and carrying on. Two routes remain, and both need provenance rather than another discard: a **filtered** run never selects the test at all, so an unselected test's older cast is untouched; and the **preflight is evaluated before the skip-path discard**, so a kill inside a `check_*_available` or an importer it calls lands earlier than any clearing. The adapter checking *provenance* — run identity, commit, redaction version and that the test actually passed — rather than existence is [#808](https://github.com/vfarcic/dot-agent-deck/issues/808).

**Two things about the redaction had to be measured rather than reasoned about, and both were wrong.** It matched bytes *contiguously*, and a terminal does not render a long value contiguously: an Anthropic key is 108 characters, the harness renders at 120 columns, and an `ANTHROPIC_API_KEY=` line therefore breaks the key **102 / 6** and its 20-character approval suffix **14 / 6**. Neither registered pattern matched either piece, so the whole credential was reconstructable out of a panic grid while the redaction reported nothing to do. The matcher now bridges row transitions, requiring eight exact bytes per hop so that bridging cannot degenerate into a subsequence search, and leaving the bytes between fragments in place so a grid keeps its border and a `.cast` keeps its escapes. Then the fix itself proved incomplete: it skipped the bytes a fragmented match had *preserved*, and those bytes can hold the other registered value — the response id is a suffix of the key, so a coincidental chain stepped over fourteen characters of it and left the complete derivative in the artifact. The scan now resumes at the end of a match's first fragment rather than past its last, and every place a hop could have resumed is redacted rather than only the first. Then registering the Claude credential document found a third: it holds an `accessToken` and a `refreshToken` that share their first eight bytes, the scan kept only one match per position, and the tie-break took the one whose chain bridged forward to its own real occurrence — leaving 120 of the other token's 128 characters unexamined behind a redaction placeholder that looked correct. Every match at a position now contributes its ranges and the scan resumes at the smallest first-fragment end among them.

**One local-billing behaviour was measured rather than assumed.** The API-key approval the harness seeds into each isolated `~/.claude.json` is asymmetric on purpose, and the rule behind it is that the harness never silently moves a run onto metered API billing. Measured on claude 2.1.252: with a usable OAuth credential set present *and* the key exported, an `approved` entry for that key renders `Haiku 4.5 · API Usage Billing` while a `rejected` one renders `Haiku 4.5 · Claude Team` — so an approved key beats a usable OAuth file, and a developer whose host config approved that key for their own interactive sessions would newly have been billed for local test runs. The isolated HOME now revokes that inherited approval. In the other direction, a stored *rejection* on a key-only host is respected rather than dropped, and overridden only under `DOT_AGENT_DECK_REQUIRE_REAL_E2E` — which is the flag that turns a runtime skip into a failure, and therefore an explicit statement that this run must reach a real agent.

Contributors: `CONTRIBUTING.md` has the lanes, and `docs/develop/e2e-lanes.md` is the operational page — how to run lane 2, why a green run can still mean almost nothing, and the whole credential-artifact story.
