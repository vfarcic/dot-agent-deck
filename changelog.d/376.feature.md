## Devbox-native CI entrypoints and a Semaphore pipeline spike

Every CI cargo step now has a matching `task` entrypoint, so it runs identically from a local devbox shell and in CI: `task ci-fmt`, `ci-clippy`, `ci-build`, `ci-build-debug`, `ci-test`, `ci-linkage-check`, `ci-audit`, plus an aggregate `task ci` covering the Linux build and security steps together.

`cargo-audit` now comes pinned from `devbox.json` instead of being compiled from source on every CI run — previously the slowest single step in the pipeline.

A new Semaphore pipeline spike lives under `.semaphore/`. It is not wired as a required check and has never executed against a real Semaphore project — it exists to be measured against the GitHub Actions baseline in a follow-up, and the retrofit decision is deliberately not made until those numbers exist.

See the new [`docs/develop/ci-entrypoints.md`](docs/develop/ci-entrypoints.md) for how to run any CI step locally.
