## Close a dispatched unit and keep its worktree

You can now stop a dispatched unit, or a whole orchestration, and keep its worktree on disk, clean or not, so you can start it again in the same directory later, for example after upgrading the deck in the middle of a long orchestration. Before, closing a unit whose worktree had no uncommitted changes always removed it, and with it the files git ignores there, such as the unit's `.dot-agent-deck/` and its build cache.

In the TUI, the `Ctrl+W` close confirmation offers **Close, keep worktree** for a dispatched unit, next to **Cancel** and **Close**; the status line then reads `Worktree kept on request:` and the directory. In the desktop app, the agent and orchestration close confirmations offer **Close agent, keep worktree** and **Close all N roles, keep worktree**, followed by a notice with the same words. From a shell, add `--keep-worktree` to `dot-agent-deck close`; it works with every selector and with `--dry-run`, and the report marks the worktree `kept on request`. Closing an agent you later start in that directory does not remove it; find it and remove it when you are done with `dot-agent-deck worktree list` and `dot-agent-deck worktree reclaim`, run from the repository it belongs to.

The choice needs a daemon of this version: the TUI and the desktop app do not offer it against an older daemon, and `close --keep-worktree` refuses and closes nothing. Restart the daemon after upgrading to get it. See [Closing Agents → Keep a worktree on purpose](https://agent-deck.devopstoolkit.ai/docs/closing-agents.md#keep-a-worktree-on-purpose).
