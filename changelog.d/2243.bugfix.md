## The input-box check holds up on a busy machine

On a heavily loaded Linux machine, the deck's check that an agent's input box is empty could end uncertain even though the box was empty, and the agent's messages then waited instead of the deck ringing its doorbell. A Codex pane could also end up with its input box never checked. Both came from the deck looking at a program that was still starting. The deck now waits until the program has started before it decides whose it is, so on a busy machine the check of Claude Code started directly in its pane, and of Codex started directly or through a launcher, ends the way it does on an idle one.
