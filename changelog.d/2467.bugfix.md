## A Codex agent shown in the desktop app gets its delegated tasks

A Codex agent that the desktop app was showing while it started could sit at its prompt with its messages queued and never receive them, while its card said `waiting for the agent to fetch it. Send it a prompt.` An orchestration worker with `clear = true` starts a new Codex for every task, so a worker you were watching could stop getting tasks altogether. The desktop app's terminal answers a question Codex asks about where its cursor is, and the deck took that answer for your typing. When the deck then couldn't check the input box, it held the messages for as long as that agent ran.

The deck no longer takes that answer for your typing, unless the agent's cursor was in the top row of its pane, past the first column, when it asked, so these messages are delivered whether or not the desktop app is showing the agent. That fixes a Claude Code agent too, if the desktop app answered such a question for it.

The deck also cleans up after itself better. On Linux it keeps a copy of itself under its state directory or `$XDG_RUNTIME_DIR` to check agents' input boxes, and copies left by daemons that had stopped could pile up there until that directory was full. On machines where one of your processes can't be inspected, such as `systemd --user` or an SSH session, those copies were never removed. Copies from stopped daemons are now removed unless a running program might still use one, and a daemon that couldn't make its copy tries again a minute later instead of going without one until it restarts.
