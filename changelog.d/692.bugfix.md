## A hung `gh` or `git` call no longer stalls an issue-dispatch schedule for good

Scheduled issue dispatch runs `gh` and `git` to clone the repository, list issues and pull requests, and create each worktree. None of those calls had a time limit, so a single `gh` that never returned kept that schedule's run open for as long as the daemon lived, and every later run of it was reported as skipped. Each call is now stopped after ten minutes and the run fails with an error naming the command that did not finish, so the schedule's next run starts normally.
