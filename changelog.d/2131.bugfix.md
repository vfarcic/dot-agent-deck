## Input-box check: Claude Code under a policy helper is no longer checked

When your organisation's managed settings for Claude Code name a policy helper (`policyHelper` or `policyHelpers`, a program Claude Code runs as it starts), that program can set `VISUAL` or `EDITOR` for Claude Code without any file showing it, so the deck's check of Claude Code's input box could open your own editor in the pane. The deck now reads that from `/etc/claude-code/managed-settings.json`, its `managed-settings.d` folder and the settings your organisation's server sends (`~/.claude/remote-settings.json`), and doesn't check the box of such a Claude Code: once anything is typed into it, its card says `the deck can't check this agent's input box. Check its pane.` until it restarts, and a prompt hands it its messages. The same happens when `CLAUDE_CODE_REMOTE_SETTINGS_PATH` is set for Claude Code, and the deck now also reads the settings Claude Code keeps for an organisation sign-in in `~/.claude/state/hybrid-settings.json`. The settings of a folder you add with `--add-dir` don't change Claude Code's editor and don't stop the check.

See [How the deck checks Claude Code's input box](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#how-the-deck-checks-claude-codes-input-box).
