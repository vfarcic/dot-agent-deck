## A worker's `work-done` now completes the task it names, and a report whose recipient has gone is kept

`dot-agent-deck work-done --task-id <id>` completes exactly the delegated task with that id: the worker's task instructions now include its id. A `work-done` without `--task-id` is delivered to the orchestrator as a note that completes no task, so it no longer marks the worker's latest task done, stops its delivery notices or frees the worker for a new delegate. A repeat of a report for the same task is answered with the first result while the deck still remembers the task, and is never delivered twice; a report naming another worker's task, an unknown task, or a task replaced with `delegate --supersede` is refused and changes nothing. `delegate --supersede` now ends the task it replaces, so the worker owes one `work-done`, for the new task.

`work-done` now says whether the deck kept the report. It is accepted only once the deck has saved it; if the orchestrator or the agent that dispatched the unit is no longer running, the report is saved for you to recover instead of being lost or handed to whoever took over its pane. When the deck cannot save it, `work-done` fails and says why; the task stays open while the worker is still running, and if the worker has already exited, its orchestrator is told the worker exited without reporting. A dispatched unit that ends without reporting now tells its caller so, and a `dispatch` is refused, before anything starts, when the deck cannot be sure of keeping its result. A dispatch result the deck could not save to disk is kept in memory until the deck restarts, and says so. When a worker's agent exits without reporting, the orchestrator's notice names the tasks it had not reported.

`work-done` from this release needs a deck daemon from this release: against an older daemon it sends nothing and says so. Against this daemon, a `work-done` from an older `dot-agent-deck` without `--done` is delivered as a note that completes no task; with `--done` it still completes its dispatched unit, but only when the deck can confirm which agent sent it. This changes what the daemon's requests mean, so a desktop app from this release refuses an older daemon and says which versions they are. Upgrade the deck, the desktop app and the daemon together.
