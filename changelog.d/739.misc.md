## Issues and pull requests are now labelled by which surface they belong to

The label taxonomy said what kind of change something was — `bug`, `feature`, `tests`, `ci-cd` — and what kind of file it touched, but never which of the project's shipped surfaces owned it. With a daemon, a TUI and now a desktop GUI in one repository, "is this a daemon problem or a client problem?" could only be answered by reading the issue.

`daemon`, `tui` and `desktop` are a new Component axis, orthogonal to the existing Area one: Area says what kind of file changed, Component says which surface it belongs to. Several at once is the normal case rather than the exception, since a protocol change is routinely the daemon plus every client that consumes it. The per-item cap moves from 5 to 6 to make room — at 5, a component label would have quietly displaced the priority or size an issue already carried instead of sitting alongside it.
