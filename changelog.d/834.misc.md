## Fixture git sandbox no longer inherits git's location discovery

`xtask/linkage-check`'s `repo_state` test sandbox switched off git's *configuration* discovery but left its *location* discovery ambient, so `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_NAMESPACE`, `GIT_DISCOVERY_ACROSS_FILESYSTEM` and `GIT_CEILING_DIRECTORIES` all outranked the working directory each fixture command passed. With one of those set in the parent process — mid-`git rebase --exec`, inside a pre-commit hook, under `git bisect run` — the fixtures read and wrote whatever it pointed at instead of their own temporary repositories, including the contributor's real checkout.

The eight discovery variables are now cleared for every fixture command, `GIT_CEILING_DIRECTORIES` is set so upward repository discovery cannot walk out of the sandbox root, and `GIT_DEFAULT_HASH`/`GIT_DEFAULT_REF_FORMAT` are cleared so fixture repositories keep the byte-identical format the surrounding tests assert against. Two regression tests cover it: one re-execs the test binary with all nine variables aimed at a victim repository and asserts the sandbox operated on its own fixture while the victim's history stayed untouched, and one places a sandbox inside another repository's working tree to prove the ceiling bounds the walk while discovery inside the sandbox still works.

No shipped behaviour changes — the affected code is test-only.
