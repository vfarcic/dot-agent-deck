## A Task Delegated to a Worker That Is Still Starting Arrives Whole

A task delegated to a `clear = false` worker that started moments earlier, because the orchestration had just opened or the role was restarted with `pane restart`, no longer reaches the worker cut short. A Codex worker in that state used to receive only the last few characters of the task line, such as `2b1b]`, ask what they meant, and sit idle while the orchestrator waited for it. The deck now waits until such a worker is ready before typing its task, the same wait it already applied after a `clear = true` restart. A worker that has been running for a while still gets its task immediately.

If a worker still starts a turn on only part of the task line, the deck no longer counts that as the task arriving. It types the task again into the same worker, Codex included, and if the re-sends run out, the orchestrator's went-quiet report says the worker received only part of its task.

See [What `clear` does to delivery](https://agent-deck.devopstoolkit.ai/docs/orchestration#what-clear-does-to-delivery).
