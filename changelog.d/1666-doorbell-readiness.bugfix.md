## The deck's doorbell no longer types into an agent that is still starting, and stops sooner for a message already taken

When a worker restarted for a new task, the deck could type its `message … waiting, run: dot-agent-deck inbox fetch` line into the new Claude Code before it had finished starting, where the line could be lost or land on a start-up screen. The doorbell now waits until the new agent shows it is ready for input: Claude Code once its input box is on screen after it starts, or once it ends a turn; Codex as soon as its empty input box is on screen; other agents once they report that they have started. If the deck does not recognise Claude Code's input box, no first doorbell comes and the message waits: type the agent's first prompt yourself, or press Enter in its empty input box.

Before each step of typing the line and pressing Enter, the deck now checks again that the message the line names is still waiting and that you have not started typing in the pane, and stops when either has changed, even while other messages are still waiting. A fetch or a keypress that arrives while a step is being typed takes effect from the next step.
