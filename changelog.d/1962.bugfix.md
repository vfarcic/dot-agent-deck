When the desktop app is behind and can upgrade itself, or was upgraded and waits for a relaunch, **Upgrade** on the Dashboard's **Local daemon** section now leads with the app's upgrade even when the CLI is current, and the button's name and hover text name the app while it is covered. Before, with the app behind, the CLI current and the daemon older than the app, it restarted the daemon straight onto the app's older build, which a TUI started from the newer CLI then moved again, leaving the old app talking to a newer daemon.
