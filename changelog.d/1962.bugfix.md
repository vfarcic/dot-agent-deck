## The Local daemon section's Upgrade leads with the app whenever the app can be upgraded

**Upgrade** on the Dashboard's **Local daemon** section now starts with the desktop app's own upgrade whenever the app can upgrade itself, or was upgraded and waits for a relaunch, not only when the CLI is behind too. Before, with the app behind and the CLI current, that **Upgrade** restarted the daemon onto the app's older version, which a TUI started from the newer CLI then offered to restart again onto its own — the same drift one upgrade is meant to avoid. Now the app is offered first, the dialog ends at **Relaunch**, and the relaunched app restarts an older daemon onto the new release, asking first when agents are running.

The button names everything it covers, for example `Upgrade Agent Deck and the daemon on this machine` or, with the CLI behind as well, `Upgrade Agent Deck, the CLI and the daemon on this machine`, and hovering it shows what is behind. An app that cannot be upgraded from here, such as one in a folder you cannot write, is still left to the banner's dialog, which says what to do instead.

See [Upgrade the CLI and the daemon on this machine](https://agent-deck.devopstoolkit.ai/docs/desktop/daemons.md#upgrade-the-cli-and-the-daemon-on-this-machine) and [Upgrade the app](https://agent-deck.devopstoolkit.ai/docs/desktop/index.md#upgrade-the-app).
