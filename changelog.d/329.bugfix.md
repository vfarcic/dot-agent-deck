## `.dot-agent-deck/` hygiene: owner-only files, a clone-local git exclude, and a retention window

Coordination files carry whatever you and your agents put in them — an issue body, a diff, a plan — and they were written with the ambient `umask`, which on a default Linux install left `worker-task-<role>.md` and `work-done-<role>.md` readable by every local account and writable by the owner's group. The deck now creates its coordination directory owner-only (`0700`) and writes every task and report file owner-only (`0600`), tightening a file an older deck left loose the next time it writes one.

`.dot-agent-deck/` is now added to the clone-local `.git/info/exclude` — per-clone and never committed — the first time a workflow publishes into a project, and by `dot-agent-deck init`, so coordination files never show up as untracked. Your own `.gitignore` is left alone.

The deck also tidies the directory after itself now: coordination files older than **14 days** are removed the next time a workflow publishes there. Both of these treat `.dot-agent-deck/` as what it is — the app's own working state, like a build or cache directory — rather than as project content. Set `DOT_AGENT_DECK_COORDINATION_RETENTION_DAYS` to change the window, or to `0` to turn the sweep off.
