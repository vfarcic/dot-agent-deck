## A failed Codex turn shows Error instead of staying Thinking

A Codex turn that the provider rejects for a reason other than a usage limit, for example an API error or a model the account cannot use, used to leave its card on `Thinking` indefinitely, so the agent looked busy when it had already stopped. The card now turns `Error` a few seconds after the failure, as Claude Code and OpenCode cards already do.

Codex runs no hook for a failed turn, so the deck reads the failure from Codex's session log, the same log it already reads for usage limits while a turn is running. A usage-limit refusal still shows **Blocked**, not `Error`. Nothing needs to be installed or configured beyond what Codex support already sets up.

See [Session Management](https://agent-deck.devopstoolkit.ai/docs/session-management) for which agents report which statuses.
