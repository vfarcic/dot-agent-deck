## Agent cards catch up after the deck reconnects to its daemon

When the deck briefly lost its live feed of agent activity — the daemon restarting, or the deck falling behind during a burst of activity — it reconnected and carried on as if nothing had happened, so a card could keep showing a status the agent had long since left, and the deck could keep tracking a conversation the agent had already ended.

The deck now refreshes every agent's card and current conversation from the daemon as soon as it reconnects. A prompt the deck had already typed into an agent before the feed dropped, and was still waiting to see the agent accept, is no longer retried after the reconnect, because the deck can no longer tell whether it went through or which conversation it reached; the status line says the prompt was not confirmed and not retried, rather than the deck sending it a second time.
