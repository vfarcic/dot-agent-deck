**The Telegram notification recipe now warns that its example server can outlive the agent that started it.** [Idle Workers & Notifications](https://agent-deck.devopstoolkit.ai/docs/idle-workers-and-notifications) pins `telegram-mcp-bot@1.1.0`, and that server does not exit when its parent dies uncleanly: its `uncaughtException` handler logs instead of exiting, nothing in it exits when its stdin closes, and its polling loop keeps it alive. The security requirements section now says so, including the measured worst case — an orphaned instance spinning a full CPU core for 36 hours and stopping only on `SIGKILL` — and how to find and kill a leftover. A single instance is enough to hit it.
