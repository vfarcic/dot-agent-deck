## What a successful `dispatch` does and does not tell you

`dot-agent-deck dispatch` exiting 0 now says what it means, everywhere it is described. At most, the exit status confirms that the deck accepted the request. An older deck, or one that does not answer in time, also yields 0 without confirming even that. The deck answers before the worktree is created or the unit is started, so exit 0 never meant that a unit is running or that it received its task.

`dispatch --help`, the dispatcher pane's built-in instructions and the Dispatcher Mode page now separate the three signals. The exit status means, at most, that the request was accepted. A turn in the dispatcher beginning `dispatch: spawned isolated` means the unit was started, and says where. The unit's completion report is the first sign that it actually received its task. Any other `dispatch:` turn is a failure and says why. The dispatcher agent is now told not to report a unit as started until that turn arrives, where before it was told that the command itself "reports what was started".

The page also covers what the dispatcher is never told. If a unit's agent never submits its task, the deck gives up after a minute and leaves a notice on that unit's own card, and nothing is sent back to the dispatcher. A unit that stays quiet for a long time is worth opening.

See [Dispatcher Mode](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode).
