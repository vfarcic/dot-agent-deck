## A re-created worker keeps its orchestration's run name

A `clear = true` worker that the deck has to re-create from scratch — because its pane was closing or its agent had already gone when a delegate arrived — now rejoins its tab under the tab's run name even when no other pane of that orchestration is still running. It used to borrow the name from a live sibling pane, so when the orchestrator had already exited, the worker came back without it, and after a detach and reattach the tab could fall back to the orchestration's bare config name. The same applies to a role restarted with `pane restart` or grown into a running orchestration with `pane spawn`, which used to be created with no run name at all.
