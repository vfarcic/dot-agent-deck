Agent messages now wait in an inbox until received: tasks, worker reports, dispatch results and scheduled prompts have recorded delivery. Claude Code 2.1.296 and newer, OpenCode's TUI and Pi receive native messages; Pi also queues follow-ups while busy. Codex receives messages through an idle doorbell and at turn end. When native wake is unavailable, a short doorbell line tells the agent to fetch its waiting messages.

TUI cards and desktop tiles show `✉N queued`, `✉ delivered` or an error with `not delivered: …`. The desktop handoff rail follows delegation, delivery and work-done. Use `dot-agent-deck inbox list` inside an agent's pane to inspect its messages, `inbox fetch` to read and acknowledge them, and `daemon status` to see the **INBOX** and **WAKE** columns.

Agents can publish announcements to subscribed roles and orchestrators can offer jobs to a pool of workers with `dot-agent-deck inbox publish`, `offer`, `complete` and `release`, configured with `subscribe` and `take_offers`.

A Codex, Pi or OpenCode worker behind a launcher the deck cannot see through, such as `devbox run …` with no `agent = "…"`, no longer waits 30 seconds before each task it is given, and `dot-agent-deck validate` no longer warns that it does. It still warns about such a role, because its card gets no agent from the config and a Codex agent behind it runs without the deck's wrapper; declare `agent` on the role to fix both.
