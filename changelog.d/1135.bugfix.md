## `DOT_AGENT_DECK_LOG=1` writes to a directory Windows actually has

The default debug-log location was the literal `/tmp/dot-agent-deck.log` on every platform. On Windows that is a rooted path with no drive letter, so it resolved against whichever drive happened to be current, as `\tmp\dot-agent-deck.log`. That directory usually does not exist, and the deck creates the log file but never its parent — so the open failed, no tracing subscriber was installed, and **nothing was logged at all**. The only sign was a single `Warning: failed to open log file …` line on stderr. Where a `\tmp` did happen to exist on that drive, the log was written to a location no documentation named.

On Windows the default is now `dot-agent-deck.log` in the system temp directory — the one `%TEMP%` points at. That is the scratch location Windows itself hands out, and unlike `%LOCALAPPDATA%\dot-agent-deck` it does not need creating first. macOS and Linux keep `/tmp/dot-agent-deck.log`, unchanged. Setting `DOT_AGENT_DECK_LOG` to any other value still uses that value verbatim as the log path, on every platform.

The [Configuration](https://agent-deck.devopstoolkit.ai/docs/configuration) and [Troubleshooting](https://agent-deck.devopstoolkit.ai/docs/troubleshooting) pages named only the Unix path, with no platform caveat; both now name the Windows one too.

Native Windows is not a supported platform yet ([#164](https://github.com/vfarcic/dot-agent-deck/issues/164)), so nothing released reaches this today.
