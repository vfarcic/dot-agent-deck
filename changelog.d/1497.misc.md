Agents' hooks honour `DOT_AGENT_DECK_BIN`: start an agent from an environment that sets it to the absolute path of a `dot-agent-deck` binary, and its hooks run that binary instead of the installed one, while every other agent keeps the installed one; a value that is not an absolute path is ignored. This works on macOS and Linux for Claude Code, Codex and Devin, and everywhere for the OpenCode plugin and the Pi extension; on Windows, Claude Code and Codex hooks keep running the installed binary. Existing hooks are refreshed automatically the next time the deck installs them. On macOS and Linux, Claude Code, Codex and Devin hooks are no longer installed for a `dot-agent-deck` at a path containing a backslash: the install reports an error naming the path and leaves the agent's configuration as it was, so install `dot-agent-deck` at a path without one and reinstall the hooks with `dot-agent-deck hooks install`. A hook entry another `dot-agent-deck` copy left that is not safe to run is fixed by the next install: replaced, rewritten, or, in a Codex or Devin hook event the deck no longer installs, removed. Only entries the deck recognises as its own are changed.
