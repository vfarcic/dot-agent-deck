Agents' hooks honour `DOT_AGENT_DECK_BIN`: start an agent from an environment that sets it to the absolute path of a `dot-agent-deck` binary, and its hooks run that binary instead of the installed one, while every other agent keeps the installed one; a value that is not an absolute path is ignored. On macOS and Linux the deck now writes Claude Code, Codex and Devin hook commands as `/bin/sh -c 'case "$DOT_AGENT_DECK_BIN" in /*) exec "$DOT_AGENT_DECK_BIN" "$@";; esac; exec "$0" "$@"' <installed path> hook --agent <agent>`, and rewrites an existing entry for the same binary in place the next time it installs hooks. The OpenCode plugin and the Pi extension read the same variable. On Windows, Claude Code and Codex hook commands are unchanged and do not honour it. On macOS and Linux, Claude Code, Codex and Devin hooks are no longer installed for a `dot-agent-deck` at a path containing a backslash: the install reports an error and leaves the existing entries as they were, so install `dot-agent-deck` at a path without one. The OpenCode plugin and the Pi extension are installed there as before. When the deck installs hooks, it replaces rather than keeps an entry another install wrote for such a path, in each hook event it installs, and for Codex and Devin it removes such an entry from hook events it no longer installs. In those events it also rewrites, in place, an entry another install wrote for a path that needs quoting without quoting it as the deck now does, quoting the path so that characters in it such as `;` or `$(` are no longer run as commands. An entry it keeps for another install is rewritten in place to the form above for that install's path.
