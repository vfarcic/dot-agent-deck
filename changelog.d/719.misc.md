## The dispatch queue skills spot-check whether a candidate is still true, not only whether it is already being worked

`/issue-queue` and `/prd-queue` both ran a careful three-way in-flight check — closing references, PR bodies, dispatch branches and worktrees — because a duplicate dispatch once cost an agent. Neither asked the other question: whether the candidate's central claim still holds. An issue implemented and never closed presented itself as available work indefinitely, and no step asked the question — the one-line scope read when the queue is printed might happen to surface it, but nothing required anyone to look. A backlog pass on 2026-08-26 found seven such issues out of roughly 180 open without looking for them, and the near-miss that motivates this was a PRD — #236 was selected for dispatch and presented as "a live data-loss bug" when the fix had shipped weeks earlier, caught only because the runner happened to ask what a phrase in it meant.

Both skills now carry a premise spot-check before the queue is shown — `/issue-queue` step 4b and `/prd-queue` step 3b, placed where the row is about to be offered. It classifies each candidate as `premise holds`, `premise looks stale — verify`, or `premise not mechanically checkable`, and the mark is printed on every row rather than only on suspect ones, so a skipped step is distinguishable from a clean one.

**It marks rows and never drops them, and that is the point rather than a caveat.** "Is this still true?" is not mechanically decidable: a premise can go stale because code was removed, renamed or refactored, or because behaviour changed while the symbols stayed. A check that silently drops a genuine issue fails invisibly, which is worse than the state it replaces. So the greps supply evidence and the classification stays a reading, and the skill text says so.

The step carries the calibration that makes it honest, measured against the 215 open issues on 2026-09-04. A naive symbol-absence sweep flags 65 of them — 30% of the backlog — and in a twelve-row sample none indicated a stale premise; the twelve fell into seven kinds of thing that merely looks like a symbol, including git SHAs, a label name, `libc` struct fields and GitHub Actions YAML keys. The largest kind is a symbol the issue *proposes creating*, absent precisely because the work is undone — which for a PRD points the wrong way entirely. Citing a file path that no longer exists flagged two issues and both were wrong, each naming a path inside a dependency crate. A later merged PR naming the issue covers 55% of the backlog, and narrowing to a resolving verb still flags 22%, dominated by references that say the opposite on reading.

`/pr-review-queue` gains the same discipline from the other end: each unit now checks that a PR's `Closes #N` references name issues the diff genuinely finishes. Merging closes those issues automatically, so a reference that over-reaches silently closes live work — a PR fixing one family of a multi-part issue should say `Refs #N`.
