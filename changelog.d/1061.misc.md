## Six `SKILL.md` files now parse under a spec-correct validator

Pi refused to load six of this repository's skills. Claude Code loads all six without complaint, which is why it went unnoticed — both validators read the same files and Pi is the stricter one. Two unrelated causes sat behind the one error banner. Nothing under `src/` is involved and no TUI↔daemon contract moves: this is `.claude/skills/` only, so `PROTOCOL_VERSION` is untouched and CLAUDE.md rule 12's cross-version check does not apply.

**Two project-local descriptions are now valid YAML.** `prd-queue` and `reproduce-first` each wrote `description:` as a plain scalar containing `": "`, which YAML does not permit there — Pi reported `Nested mappings are not allowed in compact mappings at line 2, column 14`. Both values are now single-quoted, and **the wording is byte-identical**. That is the point rather than a nicety: a skill's description is what the model matches a request against when deciding whether to invoke it, so rewriting the sentence to dodge the colon would have changed behaviour in order to fix a syntax error. Single quotes beat a `>-` block scalar here because neither description contains an apostrophe, so neither needs escaping, and `reproduce-first`'s two `"` characters pass through a single-quoted scalar untouched. Checked by parsing rather than by eye: every one of the 25 remaining `SKILL.md` frontmatter blocks loads under PyYAML, and both descriptions compare equal to their pre-change text.

**Thirteen unreferenced `dot-ai-*` mirrors are deleted:** `dot-ai-impact_analysis`, `dot-ai-projectSetup`, `dot-ai-remediate`, `dot-ai-recommend`, `dot-ai-operate`, `dot-ai-users`, `dot-ai-version`, `dot-ai-query`, `dot-ai-query-dot-ai`, `dot-ai-generate-cicd`, `dot-ai-generate-dockerfile`, `dot-ai-write-docs` and `dot-ai-process-feature-request`. Every one is a Kubernetes or MCP skill with no bearing on a Rust TUI and desktop app, and the first two are also two of the four whose names fail the spec's `^[a-z0-9-]+$`. All thirteen arrived with the original scaffold and were untouched since this repository's first commit.

**Deleting a mirror sticks, where editing one does not.** CLAUDE.md rule 13 warns that `.claude/skills/dot-ai-*` is synced from the `dot-ai` project and that local edits get clobbered — `04a3641` narrowed a mirrored skill and `e94388d` reverted it byte for byte five days later. That warning is about *editing*. Removal is a different operation and the history shows it holding: `dot-ai-prd-done` was touched by the 2026-06-19 sync and is absent from the tree today, and that sync commit touched exactly one file, so the sync is targeted rather than a wholesale directory restore. This is also why **renaming** the invalid-name mirrors is not the fix — a rename is an edit, and an edit is what comes back.

**Two name warnings survive this on purpose.** `dot-ai-manageKnowledge` and `dot-ai-manageOrgData` are the other two skills whose camelCase names fail the spec, and both are kept for their subject matter, so a spec-correct validator still reports them. That is a recorded decision rather than an oversight. `dot-ai-prds-get` and `dot-ai-prd-update-decisions` are likewise unreferenced but retained, because both belong to the PRD lifecycle this project actually runs.

One correction to the issue's own survey, worth recording because it was the thing most likely to make this change wrong: its claim that all thirteen are *referenced nowhere* holds for each full skill name but not for every bare `/slash` form. `dot-ai-generate-cicd` names `/generate-dockerfile`, which costs nothing because both are on the list and leave together. `dot-ai-request-dot-ai-feature` — retained, and named in rule 13 itself as the channel for sending changes upstream — names `/process-feature-request` when telling the user to open the **target** project and run it there, so the mention is cross-repository by construction; its sibling half, reading a `tmp/feature-response.md` that comes back here, needs no skill to `cat` a file. Deleting it anyway was a deliberate call rather than an unnoticed dangling reference.

**The class is now gated rather than just fixed.** Nothing compiles a `SKILL.md` and no CI job read one before this, so the defect's failure mode was silence: the permissive reader is the one contributors run all day, and a malformed description round-trips through it looking fine while breaking in a different harness weeks later. `xtask/linkage-check/src/skill_frontmatter.rs` adds seven tests to `cargo test-fast` — every frontmatter block parses under a spec-correct YAML parser and carries a string `name` and `description`, every name matches `^[a-z0-9-]+$` against an allowlist holding exactly the two retained camelCase mirrors, that allowlist may not outlive what it excuses, and each `name:` matches its directory. Two synthetic fixtures pin the parser's strictness in both directions: the original unquoted `": "` shape is rejected, and the single-quoted replacement parses with its wording byte-identical. Same argument CLAUDE.md rule 5 records for `clean_tmp.rs`, `junit_strip.rs` and `pin_lockstep.rs` — a property that exists only at run time, in repository files, guarded by a test because no compile step can see it. All seven run in 0.015s.

The seventh is there because `build-windows` caught the gate being wrong on its first outing: `.gitattributes` does not pin the working-tree line ending for `.md`, so a Windows checkout gets CRLF and the `---` fence never matched — every skill reported as unfenced, a platform-specific false alarm rather than a real finding. Reads are now normalised the way `issue_labeler_memory.rs` and `issue_labeler_policy.rs` already normalise theirs, and a fixture pins both directions: a CRLF block parses identically to its LF twin, and an un-normalised one still fails the fence, so the fixture cannot quietly stop testing anything.

It uses `yaml-rust2`, a fully YAML 1.2 compliant parser, as a **dev**-dependency of a `publish = false` xtask crate, so it reaches no shipped binary; `default-features = false` drops `encoding_rs`, leaving a three-crate closure. Hand-rolling a scan for `": "` was rejected on the grounds that a bespoke matcher would reproduce this bug's own cause — a lenient reader — inside the gate meant to catch it. Both halves were mutation-tested rather than assumed: reverting `reproduce-first` to its unquoted form turns the gate red naming that skill, and emptying the allowlist turns the name gate red naming both mirrors.

`.agents/skills` is a tracked symlink to `../.claude/skills`, so a directory removed under `.claude/skills/` is gone from both paths at once — which is also why Pi listed each offending file twice. There was no second copy to clean up and the symlink is unchanged.
