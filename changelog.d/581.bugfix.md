## A stuck agent no longer keeps the deck from stopping the others

Shutting the daemon down — `dot-agent-deck daemon stop`, a SIGTERM, or quitting the dashboard — asks every agent to exit, waits out a grace window, and then force-kills whatever is left. That last step used to kill one agent and wait for it to disappear before moving on to the next, which is fine right up until an agent cannot disappear: a process blocked in the kernel on unresponsive I/O (a hung network mount is the usual cause) does not die on a kill signal until that I/O finally completes. The shutdown parked there, and **every remaining agent was never signalled at all** — they stayed running after the deck reported a clean stop and exited, leaving orphaned agent processes behind with nothing in the log to say so.

The kill is now delivered to every agent first, and only then does the deck collect the results, so no agent's kill depends on how long a different agent takes to die. Collecting those results no longer blocks on one agent either, so an agent that is already gone is cleaned up immediately instead of queueing behind a stuck sibling. Nothing is given up in exchange: every agent is still waited for, so this trades no leaked process for a leaked one. A genuinely stuck agent still holds the deck's own exit until the kernel releases it — that part is not something a program can hurry — but it no longer takes the rest of your agents with it.
