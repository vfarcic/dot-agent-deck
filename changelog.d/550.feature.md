## An agent working in a worktree is told where the main checkout is

A delegated agent working in a linked worktree often needs the **root checkout** — to leave a report or an artifact that outlives the worktree, which is temporary: closing a dispatched unit's tab removes its copy, and `dot-agent-deck worktree reclaim` removes one whose branch has merged. The deck gave it no way to find that, so the path had to be hand-written into the task by whoever delegated, and forgetting produced a *stall* rather than an error — the agent has nothing to resolve and correctly declines to guess.

The deck now resolves the main checkout itself and **writes the path into the prompts it already composes**, as a literal:

- **The orchestrator context** gains a `## Durable output` section naming the path. The orchestrator is the agent that authors worker tasks, so it is the one that has to know; a worker only ever sees the path its task names.
- **A dispatched single unit's prompt** gains the same paragraph, since it gets no orchestrator context.

Both are emitted **only when the directory is a linked worktree**. In an ordinary checkout the main worktree is the directory the agent is already working in, so saying so would be prompt text every orchestration pays for and none of them needs.

**A path, not an environment variable, and that is the whole design.** The issue proposed exporting `DOT_AGENT_DECK_ROOT` into every spawned pane and having role prompts reference `$DOT_AGENT_DECK_ROOT/…`. Two things are wrong with it. An agent's file-writing tool does not go through a shell, so an agent told to write to `$DOT_AGENT_DECK_ROOT/findings.md` creates a *directory* called `$DOT_AGENT_DECK_ROOT` — the same class of failure the deck already avoids by interpolating `report_path` as a literal into the dispatch prompt. And an environment variable is inert until something tells the agent it exists, which means documenting it, which moves the burden from "remember the path" to "remember the variable" rather than removing it. Interpolating the resolved path removes it: nothing to learn, nothing to expand, nothing to look up.

**The resolver is not `dirname` of the git common dir**, which is how the issue proposed it and is wrong in two of six layouts. `worktree_owner::main_worktree_of` asks git whether the directory is already in a main worktree (`--git-dir` equals `--git-common-dir`) and takes `--show-toplevel` when it is — correct from a subdirectory, and correct for a repository whose store was relocated with `--separate-git-dir`, where the common dir's parent is not the checkout at all. When it is not, the main worktree is the directory *holding* the common dir, and that inference is proved rather than trusted: the candidate's own `--git-dir` has to be the common dir. A linked worktree of a relocated store and a linked worktree of a bare repository both fail that proof and yield nothing instead of a confident lie, as does a bare repository itself.

Everything fails closed to saying nothing. A wrong path is worse than a missing one here, because the agent writes into it and nobody notices.

**It ignores the ambient git environment.** `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR` and five siblings outrank the working directory a command is given, so a daemon lazy-spawned from inside a `rebase --exec`, a pre-commit hook or a `bisect run` would otherwise have every pane it started pointed at whatever repository that variable named. Measured with the scrub removed: the resolver returns the ambient repository rather than the pane's own. Every `git` invocation in `worktree_owner` now clears them, which also covers `git_dir_of` — and so the ownership gate and the reclaim path that *deletes* directories behind it, both exposed to the same override before this change.

**No TUI↔daemon contract change, checked rather than assumed** (CLAUDE.md rule 12). Nothing is added to or removed from `daemon_protocol.rs`, no field changes meaning, and `PROTOCOL_VERSION` is untouched. Both prompts are composed inside the daemon from a `cwd` the wire already carried, and the composed text was already being published and delivered; nothing new crosses the wire and no client parses the path.
