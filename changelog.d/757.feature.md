## Every release asset now carries verifiable build provenance

Downloads from a release page have only ever come with `checksums.txt`, and a checksum answers a narrower question than it looks like it does: it says a file matches a number printed on the same page that served the file. Every asset — the desktop `.dmg` and `.deb`, and all four CLI binaries — now also carries [build provenance](https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations), which says the exact bytes you hold were produced by this repository's release workflow from a named commit. Verify one with:

```sh
gh attestation verify <the-file-you-downloaded> --repo vfarcic/dot-agent-deck
```

On Linux this is not an extra: it is the only verification anybody makes. `dpkg` ships with per-package signature checking disabled, so `dpkg -i` on a downloaded `.deb` verifies no signature and issues no warning — signing the package would have produced a signature nothing looks at.

No key is involved anywhere, and that is the design rather than a shortcut. The signing certificate is short-lived and issued to the release workflow's own identity through OIDC, so this repository holds no private key to protect, rotate, or have revoked, and the record lands in a public transparency log. It cost nothing to add and costs nothing to keep.

What it does not do is worth saying plainly, because "signed" is the word people reach for: it does not remove the macOS Gatekeeper dialog or the Windows SmartScreen warning, which check Apple's and Microsoft's own certificate chains and know nothing about this. No operating system, package manager or installer checks provenance on your behalf — it is a check you choose to run. Removing the macOS dialog needs an Apple Developer ID certificate and notarization, which remains tracked in [#757](https://github.com/vfarcic/dot-agent-deck/issues/757).
