## Close Agents and Dispatched Units From the Command Line

`dot-agent-deck close` stops agents without opening a client. Name a dispatched unit by the name it was started under (`close fix-auth-bug`) or by the unit id a listing printed (`--unit-id`), close one agent with `--pane <id>`, or a whole orchestration with `--orchestration-of <id>`. `close --all` lists every unit you can close, with whether it has reported back, its worktree and its branch, and closes nothing; `close --all --yes` then closes exactly the units it listed. `--dry-run` shows what would happen, and `--json` prints the report for scripts.

A dispatcher agent can now close the units it started when you ask it to, for example *"close the units that have reported back"*. It can close only units it dispatched itself, never its own pane or team, and not the units those units started.

Because there is no confirmation dialog on the command line, `close` refuses a unit that has not reported back, an agent that is still busy, and a single role of a running orchestration; `--force` closes them anyway. Closing a unit removes its worktree when it has no uncommitted changes and keeps its branch, and `close` tells you which happened. The exit status says whether everything closed (0), something was refused or failed (1), the running daemon is too old for `close` (2), or no daemon is running (3).

`dispatch`'s success reply now names the unit's branch as well as its directory. A completion report from a dispatched unit that finished within moments of starting is no longer lost.

See [Closing Agents](https://agent-deck.devopstoolkit.ai/docs/closing-agents).
