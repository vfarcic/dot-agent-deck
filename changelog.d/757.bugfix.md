## The desktop preview's install note now gives macOS users a route that still exists

v0.39.3 was the first release to actually carry the desktop GUI bundles, and with them the note explaining how to open an unsigned app. That note offered exactly one macOS route — `xattr -dr com.apple.quarantine` against `/Applications` — and it was the wrong one to offer alone. macOS Sequoia removed the Control-click bypass, so a user who did not want to run a recursive terminal command against a system directory was given nothing at all, and everyone who did run it was being taught a habit that transfers to the next thing that asks for it. **System Settings > Privacy & Security > Open Anyway** is the route that works without a terminal, and it is now listed first, with the command kept underneath for anyone who prefers it.

The same note told `.deb` users that the assets "are unsigned, so your OS will warn you". That is false for Linux: `dpkg` ships with per-package signature verification disabled, so `dpkg -i` verifies no signature and issues no warning. Each platform now gets its own sentence, and the Linux one says the only verification actually available is checking the SHA-256 against `checksums-desktop-alpha.txt`.

Neither wording is left to taste from here. `release.yml` fires only on a tag, so nothing can execute it on a pull request; a static assertion in `xtask/linkage-check` now fails the build if the note ever offers the terminal command as its only macOS route, or stops speaking to the `.deb` on its own terms. Signing and notarization — the thing that would remove the macOS dialog rather than explain it — remain tracked in [#757](https://github.com/vfarcic/dot-agent-deck/issues/757).
