## An overview of the whole fleet in the desktop app — and terminals that attach only where one is shown

The desktop app gains a fleet-overview screen, reached from the Overview button in the left rail: every agent the daemon owns, grouped the way the daemon already groups them — standalone panes first, then one card per orchestration with its roles in role order and its coordinator marked, then one per mode tab — with status, agent type, working directory, active tool and tool count, and no terminals. It answers "what is running right now" at fifteen agents, which the existing control deck does not: that deck renders every agent with a live embedded terminal, so it degrades exactly when a fleet gets large enough to need an index. The deck is unchanged and is still the screen the app opens on.

The screen shows only what the daemon genuinely reports. Model, token, cost, context-window, git-branch, attempt-count and session-duration columns are deliberately absent rather than shown as `Unavailable`, because none of them exists anywhere in daemon state; a type-level projection makes reading one of those fields on this screen a compile error. Daemon-supplied text — display names, directories, tool details — is stripped of control and bidirectional formatting characters before rendering, so a name carrying a `U+202E` cannot visually reverse itself or swallow the markers beside it on a screen whose whole job is telling agents apart. An agent whose reported name is made entirely of invisible characters renders as `unnamed agent <id>` rather than as a blank cell.

**Terminals now attach where one is on screen, and nowhere else.** This is the substantive behavioural change underneath the new screen, and it applies to the whole app rather than only to it. The deck previously opened one daemon socket and replayed one full scrollback per agent from the initial connection, from every snapshot the daemon pushed, and from starting a local daemon — for every agent the daemon owned, whatever was actually displayed. A nine-agent fleet therefore cost nine sockets and nine replays before a single terminal was looked at. What is displayed is now the only thing that attaches. Leaving a terminal does not detach it — it stays attached in a small warm set, bounded at three and evicted least-recently-left first, so switching back and forth costs no replay — and when nothing at all is shown the warm set is released to zero, which is what makes the overview genuinely hold no terminal however you arrived at it.

Try it against your own daemon by opening the app and clicking Overview. The fixture preview still drives the same screens without a daemon: `pnpm dev`, then `?fixture=1&state=crowded` for a fifteen-agent fleet, or `state=empty`, `state=disconnected` and `state=error` for the first-run, unreachable-daemon and incompatible-daemon states.
