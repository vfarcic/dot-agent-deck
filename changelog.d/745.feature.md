## An overview of the whole fleet in the desktop app — and terminals that attach only where one is shown

The desktop app gains a fleet-overview screen, reached from the Overview button in the left rail: every agent the daemon owns, grouped the way the daemon already groups them — standalone panes first, then one card per orchestration with its roles in role order and its coordinator marked, then one per mode tab — with status, agent type, working directory, active tool and tool count, how long ago each agent last did anything, how long each has been running, the last prompt each agent was sent, the write lease the daemon holds for it, and no terminals. It answers "what is running right now" at fifteen agents, which the existing control deck does not: that deck renders every agent with a live embedded terminal, so it degrades exactly when a fleet gets large enough to need an index. The deck is still the screen the app opens on and its layout and contents are untouched — but two things about how it behaves did change, and both are described below.

The screen shows only what the daemon genuinely reports, and three things it has always reported now reach the app for the first time: the **last prompt** you sent each agent — the honest answer to what it was asked to do, which live mode previously had no way to show at all, falling back to a restatement of the active tool or to the words "Task metadata unavailable from daemon" — the **write lease**, so a session the daemon can replay but cannot type into says so, and an **orchestration's own working directory**, stated once in its group header so a role pane sitting somewhere else stands out as the difference it is. Model, token, cost, context-window, git-branch and attempt-count columns are deliberately absent rather than shown as `Unavailable`, because none of them exists anywhere in daemon state; a type-level projection makes reading one of those fields on this screen a compile error. Daemon-supplied text — display names, directories, tool details — is stripped of control and bidirectional formatting characters before rendering, so a name carrying a `U+202E` cannot visually reverse itself or swallow the markers beside it on a screen whose whole job is telling agents apart. An agent whose reported name is made entirely of invisible characters renders as `unnamed agent <id>` rather than as a blank cell.

**The overview also says when the daemon last saw each agent do anything** — `just now`, `34m ago`, `2h ago`, with the exact UTC instant on hover — which is the one column that needed the daemon itself to change. The daemon has always tracked a last-activity time per session and has always used it internally; it simply never sent it to anyone, so the fleet screen could not tell a busy agent from one that stopped an hour ago. It now travels alongside the rest of each agent's live state, as an epoch-millisecond instant rather than pre-formatted words, so how it reads stays the app's decision — and it is additive and optional in both directions, so **older and newer builds interoperate unchanged**: a new app against an older daemon simply shows an empty column, and an older app ignores the field entirely.

That column is honest about not knowing. The time is the newest event the daemon actually observed, never a value re-stamped when something reconnects, so an agent quiet for an hour reads as quiet for an hour. Where the daemon cannot vouch for it — most visibly right after a daemon restart, which leaves it with no session history at all — the cell is simply **empty** rather than resetting every agent to "just now". Ordinary clock skew between the machine that stamped the event and the app reads as `just now`; a time genuinely further ahead than skew explains renders as nothing at all, because a negative "3 minutes from now ago" is a bug and a cheerful "just now" for it is the same bug wearing a nicer label.

**And beside it, the overview now says how long each agent has been running** — `<1m`, `34m`, `2h`, `3d`, with the exact spawn instant on hover. This is the one column the screen originally refused, and it comes back because it found a source worth trusting. The rejected version was built on when an agent's *session* started, which the daemon only learns once that agent has reported something — so the agents it could say least about were exactly the ones you would most want it for. What ships instead is when the daemon **started the process**, which it knows because it did it. Restart a worker and its uptime restarts with it, since that is genuinely a new process; leave an orchestrator running for a day and it reads a day. Nothing is guessed: an agent the daemon did not start itself — which is every agent when the app is talking to an older daemon — shows an empty cell rather than an invented age, and this field is additive and optional in both directions exactly as the last-activity one is.

**Terminals now attach where one is on screen, and nowhere else.** This is the substantive behavioural change underneath the new screen, and it applies to the whole app rather than only to it. The deck previously opened one daemon socket and replayed one full scrollback per agent from the initial connection, from every snapshot the daemon pushed, and from starting a local daemon — for every agent the daemon owned, whatever was actually displayed. A nine-agent fleet therefore cost nine sockets and nine replays before a single terminal was looked at. What is displayed is now the only thing that attaches. Leaving a terminal does not detach it — it stays attached in a small warm set, bounded at three and evicted least-recently-left first, so switching back and forth costs no replay — and when nothing at all is shown the warm set is released to zero, which is what makes the overview genuinely hold no terminal however you arrived at it.

**The control deck also stops asserting two things it never knew.** Connected to a real daemon, every agent tile printed `ATT 01` and the top bar printed `ATTEMPT 01`, both read from a hardcoded `1` — no daemon tracks a retry count — and the branch line printed the literal `Unavailable` where a branch name belongs, because no daemon tracks a per-agent branch either. A fabricated value is worse than an absent one, since it looks like data: the attempt readouts now show the same em dash the deck already shows for anything it cannot report, and the branch chip is simply gone until something reports a branch. The deterministic fixture keeps its own attempt counts and branch, which are legitimately fixture data.

**You choose the columns, and the app remembers.** The overview opens on four — the agent's name, its status, the directory it is working in, and how long it has been running — which is what answers "what is running right now" without reading anything twice. Everything else the daemon reports is one click away in the **Columns** button at the top of the screen: last activity, agent type, active tool, tool count and the last prompt, each ticked on or off, and your choice is still there the next time you open the app. Only the name is permanent, because a row without one is not a shorter row, it is an anonymous one. The picker lists exactly what the daemon reports and nothing else — it cannot offer you a model, a cost or a token count, because there is no such thing to show. Choosing a column also means keeping it: the screen used to hide three columns on a narrow window and three more on a narrower one, and now it scrolls sideways instead, as one table, so the rows of every group stay lined up with each other however far across you go.

**And a bug fix that is separate from all of that: the two time columns were frozen.** `Last activity` and `Uptime` only moved when the daemon sent news about some agent, and an agent doing nothing sends none — so a genuinely idle agent sat at `3m ago` while the truth became half an hour, and the uptime of a long-running agent simply stopped counting. It failed backwards: a busy fleet hid it completely, because any other agent's activity redrew the screen, and the idle case — where "quiet for two hours" is the most useful thing on the page — was exactly where it went wrong. Both columns now keep counting on their own. It costs nothing on the wire: the screen re-reads its own clock every ten seconds and asks the daemon for nothing at all, and it stops while the window is in the background, catching up the moment you come back to it.

**Five things the screen was getting wrong, found by using it.** The **CLI** column named an internal identifier instead of a command: Claude Code read `claude_code` and OpenCode read `open_code`, neither of them something anybody types, and `codex` was right only by coincidence. It now names the binary each agent actually runs. The **Columns** menu only closed on `Escape`, so one opened by accident had to be dismissed from the keyboard — clicking anywhere else now closes it — and it gained a **Restore defaults** entry, because unticking your way down to almost nothing previously left you having to remember which four columns the screen started with. And the daemon's own header stopped saying two things it did not need to: the socket filename, which was there to keep a user id out of screenshots and on the default socket contained one, and the words `Daemon responding` next to a lamp that was already green. The full socket path is still one hover away, where it is genuinely useful, and every message that says something the lamp does not — a daemon that is unreachable, one this build cannot speak to, one you connected to anyway despite a build difference — is untouched.

Try it against your own daemon by opening the app and clicking Overview. The fixture preview still drives the same screens without a daemon: `pnpm dev`, then `?fixture=1&state=crowded` for a fifteen-agent fleet, or `state=empty`, `state=disconnected` and `state=error` for the first-run, unreachable-daemon and incompatible-daemon states.
