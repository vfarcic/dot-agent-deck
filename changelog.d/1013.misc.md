## `prompt/new-pane/016` runs its real Claude agent on Haiku instead of whatever the host picked

The `[reel]`-marked lane-2 test `prompt/new-pane/016` spawned a bare `claude` with no `--model`, so the dispatcher pane — and the unit it dispatches, which inherits the same `default_command` — ran on whatever the host's managed settings selected. Measured on the dev box while working [#1006](https://github.com/vfarcic/dot-agent-deck/issues/1006): **Opus 5 at xhigh reasoning effort**, for an agent whose whole job is to decompose one goal and call `dot-agent-deck dispatch`. CLAUDE.md rule 4 asks real-agent e2e tests to run on a cheap model, and the three other pins in this same file already do; 016 was the outlier rather than the pattern.

The launcher [#1006](https://github.com/vfarcic/dot-agent-deck/issues/1006) introduced made this a one-line decision: the `--model claude-haiku-4-5-20251001` pin now rides after the resolved binary path on the launcher's `exec` line. It is pinned at that call site rather than inside `real_claude_path`, which must keep returning the bare binary's absolute path so the `exec` cannot re-enter the launcher — itself named `claude` so `AgentType::from_command` resolves it as the deck resolves a production `default_command`. Nothing else moved: same launcher indirection, same three-second announcement delay, same tool set, so the ordering the test exists to exercise is untouched.

The cost of the old behaviour was **silent** — nothing in the test or in CI reported which model it picked, so the bill depended on whoever ran it. Lane 2 runs in no CI anywhere, so this was verified by hand: three `cargo test-e2e-live new_pane_016` runs against a real credential, all green (75.9 s, 80.6 s, 75.7 s). That the flag actually took effect was read off the recorded `full-stream.cast` rather than assumed — Claude Code's own banner in the pane reads `Haiku 4.5`, and `Opus` and `Sonnet` appear nowhere in the 353 KB stream.
