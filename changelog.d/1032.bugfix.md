## The Appearance setting's two columns hold up in the desktop app

The settings sheet lays every setting out as one row in two columns — a fixed label column, then the control beside it — so a panel of settings reads as two columns rather than a ragged stack. The Appearance row did not get that treatment in the packaged desktop app: its Light/System/Dark control landed in the label's own column, 148px left of every other control in the sheet.

It only misbehaved where it mattered. The row made its label a grid item by floating a `<legend>`, which Chromium honours and WebKit does not — and the desktop app runs on WebKit (WebKitGTK under Tauri on Linux, WKWebView on macOS), so the form that worked was the one only the Chromium tests saw. The row now names its group the way the Decks panel does, which lays out identically in both engines and keeps the same accessible group name for screen readers.

The convention is now measured rather than merely written down: the browser test tier walks every panel the settings registry offers, in both Chromium and WebKit, and holds each row to the same column geometry — so a panel added later inherits the guard instead of being free to diverge.
