## The deck no longer keeps `orchestrator-context.md`

Each orchestration's instructions are in its own `.dot-agent-deck/orchestrator-context-<id>.md`, which its orchestrator's first message names. The deck also used to keep a copy of the most recent one as `.dot-agent-deck/orchestrator-context.md`. It no longer writes or reads that file, and deletes one it finds there the next time it writes an orchestrator's instructions. A role command or prompt that reads `orchestrator-context.md` now finds nothing.

When an orchestrator's conversation is compacted or cleared, the TUI sends it its instructions again with the task it was started with. When the TUI cannot read the orchestration's own file, it now sends them without a task and its status line says so: `Orchestration 'team': instructions re-sent to its coordinator without a task (this tab does not know its context file)`. Before, it took the task from `orchestrator-context.md`, which could hold another orchestration's task. If the orchestrator was working on a task, give it the task again.

A TUI older than v0.44.0 is no longer supported against a daemon from this release: after a compaction or `/clear` it can re-send an orchestrator's instructions with an old task, or none. The desktop app from this release refuses an older daemon and says which versions they are. Upgrade the TUI, the desktop app and the daemon together.

See [Approving Project Commands](https://agent-deck.devopstoolkit.ai/docs/project-trust.md) and [Orchestration](https://agent-deck.devopstoolkit.ai/docs/orchestration.md).
