## `render_frame` no longer takes a pane layout it never reads

`render_frame` accepted a `pane_layout: PaneLayout` argument that **no arm of the function ever read**. The effective layout for a frame is resolved by reading it back out of `FrameContent::Cards` — deliberately, because re-deriving it in the render pass is what would let the geometry pass and the render pass disagree about which layout the frame is in (PRD #84 invariant 1). The argument was shadowed by that read on the `Cards` path, and on the `Mode` path the shadowing `match` returned the argument into a binding whose first read sits after the `Mode` branch has already `return`ed. So the value callers passed reached nothing, and eight of the nine call sites had settled on a hardcoded `PaneLayout::Stacked` that was equally inert.

The parameter is gone, and the layout is now bound in the **same destructure** as the `pane_rects` it has to agree with. Within `render_frame` that turns a convention into a compiler-enforced one: there is no longer a second `PaneLayout` in scope for the function to reach for by accident, and the layout it uses cannot come from anywhere but the struct the geometry pass filled in.

**The claim stops at `render_frame`'s own scope, and the wider version of it would be false.** Nothing here stops a future caller from constructing a `FrameContent::Cards` whose `pane_layout` and `pane_rects` disagree — that pairing is still held by convention, by the two sites inside `compute_frame_layout` that build the variant and derive both from the same local. What is removed is the one place the render pass could have picked up a layout that the geometry pass never used.

The fold into the existing `match` is structural rather than stylistic: the shadowing `match` ran **before** the `Mode` branch returned, so the dead arm could not simply be replaced with an `unreachable!()` — that would have panicked on every Mode tab render rather than documenting an impossibility. Moving the binding below the branch is what makes the `Mode` path genuinely carry no layout.

No behavioural change and nothing user-visible: a signature change, seven test call sites updated to match, and no assertion touched.
