## The TUI no longer leaves your shell receiving mouse reports and bracketed paste after an error exit

When the deck's terminal UI exits because something went wrong — the tty going away under it, an ssh link dropping, a failed read or write to the terminal — it left two terminal modes it had turned on still turned on. The shell you were dropped back into then received an escape sequence for every pointer move, click and scroll over that window, so moving the mouse typed garbage at the prompt, and every paste arrived wrapped in its bracketing markers, so those characters landed in the command line too. It persisted until the terminal was reset, and nothing in the exit said the terminal had been left modified — so it read as the shell being broken rather than as anything to do with `dot-agent-deck`.

Both modes are now owned by a guard that turns them off on **every return from the terminal UI's event loop**, not only the clean one. A crash was already covered; an ordinary error return was not, because the code that turns the modes off sits at the end of the event loop and an error return jumps past it.

This has been true of every release since `v0.14.0`, when mouse selection and bracketed paste were added. The clean exit was never affected: quitting the deck normally has always restored the terminal.

Nothing about the TUI↔daemon protocol moved — this is terminal state written by the TUI to its own terminal, which the daemon does not observe — so `PROTOCOL_VERSION` is untouched.
