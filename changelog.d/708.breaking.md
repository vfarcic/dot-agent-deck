## The "worker exited" and "worker never came up" reports are now turns the orchestrator answers, not lines in its scrollback (`PROTOCOL_VERSION` unchanged)

Two daemon reports tell the orchestrator that a delegation has definitively failed: `⚠ delegated worker exited without work-done`, when a worker's process ended before it ever reported, and `⚠ delegated worker never came up`, when a `clear = true` delegate's replacement worker died before it was ready, so the task was never delivered. Until now both were written into the orchestrator's pane and left there unsubmitted, so nothing happened until a human pressed Enter. In a dispatched unit there is no human, so the orchestrator went on waiting for a `work-done` that could never arrive. Both now arrive as submitted turns, through the same guarded write-and-submit path the "delegated worker went quiet" report moved to in the previous breaking release, and their wording asks the orchestrator to decide: re-delegate, reassign the task, or notify the user. The exited-worker report also says that the worker still counts as owing its task, so re-delegating to that role takes `dot-agent-deck pane restart <role>` or `delegate --supersede` first.

This is classified as a compatibility break even though nothing on the wire moved — no field added, removed or retyped, no new message, no handler signature change — because what changed is the *meaning* of an existing delivery: text that was inert daemon output is now model input that consumes a turn. Per this project's own rule (`docs/develop/versioning.md`) a semantic break behind a stable wire is versioned as breaking, which is why this drives a minor bump rather than a patch.

**What to expect if you upgrade.** An orchestrator that previously sat idle after one of these failures will now visibly wake up and act on it — that is the point, but it is a behavioural difference in an automated loop, and an orchestrator whose own instructions do not anticipate the report will improvise a response. Both reports are framed as daemon reports rather than messages from a person or an agent, and neither names a role or carries task text — the only value in them is the worker's pane id, which the deck has already restricted to letters, digits, `-` and `_`. Note *when* the switch takes effect: the behaviour changes when the **daemon** starts on the new build, not when the binary on disk is replaced, so if you upgrade while agents are running you keep the old daemon — and with it the old, unsubmitted reports — until it next restarts. One notice is deliberately left as it was: `⚠ respawn failed for role …`, for a `clear = true` respawn that could not start a replacement at all, is still written without an Enter; it is tracked separately.

**One consequence worth knowing before you upgrade.** Every automatic submission the deck makes shares a limitation: if the orchestrator's pane is holding an unsent draft you typed, the deck's text is appended to that draft and both are submitted together. That was already true of the idle-worker and went-quiet reports; it is now true of these two as well.

See [Idle Workers & Notifications](https://agent-deck.devopstoolkit.ai/docs/idle-workers-and-notifications) and [A delegated worker never came up](https://agent-deck.devopstoolkit.ai/docs/orchestration#a-delegated-worker-never-came-up).
