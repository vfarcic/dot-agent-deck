## A prompt the agent submitted twice no longer reads as a clean delivery in the log

When the deck writes an automatic prompt into a pane — a `dispatch` task, an issue-dispatch task, an orchestrator's role prompt, a mode's seed — it does not treat the write as a delivery. It waits for the agent to report the text back, and only then records the prompt as confirmed. Sometimes what comes back is the prompt twice: a submit that a still-booting agent turned into a newline instead of a send leaves the payload sitting in the input box, and the next attempt's send carries both copies as one turn. The deck stops retrying at that point, which is right — the agent is demonstrably already working, and typing a third copy of a task that deploys or deletes things is the worse direction — but it logged that outcome with the same line it logs a clean single delivery. The one case that did warn was a doubling with no separator between the copies, and only for a prompt under 200 bytes; a dispatch prompt is routinely longer than that, so in practice a duplicated turn was reported as an ordinary success.

The confirmation line now says which of the three shapes confirmed the delivery, and carries a `confirmation=` field so the shapes can be told apart without reading prose. A clean single copy logs exactly what it always did. A turn whose repetition is visible in what the agent reported now **warns**, names the copy count where the report carried the whole text, and says plainly that the turn states the task more than once — the same level as the separator-free doubling already used.

The third shape is the honest limit of what the deck can see, and it is reported as such rather than as either of the other two. Agents report a submitted prompt truncated at 200 bytes, and past that length one copy and any number of copies produce byte-for-byte the same report — so for a long prompt the question cannot be answered in either direction. That line stays at info level, because it is emitted for every long-prompt confirmation and warning on it would bury the cases that need attention; what it now says is that repetition is undecidable from the report, instead of claiming a clean delivery. Removing that blind spot entirely needs the full-prompt digest tracked in #526.

No delivery decision changed. Every one of the three shapes still confirms the delivery and still stops the retries, exactly as before — what changed is only what the log says happened.
