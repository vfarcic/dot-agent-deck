## Orchestration run names are enforced by the daemon

Two orchestrations can no longer run under the same name in the same directory. The new-pane form already refused a name a live orchestration held, but it decided from a snapshot taken when the form opened, so two people (or a TUI and the desktop) whose forms were open at the same time could both start one under the same name and end up with two tabs they could not tell apart. The daemon now makes that decision when the orchestration starts: a start whose run name — the typed name, or the orchestration's own name when none was typed — is already held by a live orchestration in the same directory is refused and nothing is started. A name whose orchestration has fully exited can be used again, the same name in a different project is not a collision, and every role of one orchestration tab shares its name without colliding with itself.

In the TUI a refused start brings the new-pane form back with the name you typed and the existing "already in use by a live orchestration" warning, so you only have to change the name. The desktop reports the daemon's refusal as it reports any other failed launch.

This is a compatibility change between builds: a start an older daemon accepted can now be refused. An older TUI attached to a newer daemon shows the refusal as a plain `Orchestration failed: …` status line instead of reopening the form, and a newer TUI attached to an older daemon gets only the form's own snapshot check, as before.
