## Voice control in the desktop app

The desktop app can now be driven by voice. Press **Voice**, say *"show me the overview"* or *"open the tester"* or *"go back"*, and the app does it — and says what it did. Typing the same words into the same box does the same thing, which matters more than it sounds: typed is the default, works with no credential of any kind, and is the path every install has out of the box.

**It works with nothing configured, on a machine that already has an agent CLI.** Turning a sentence into an action needs a model, and the default uses the `claude` CLI you are already signed in to rather than asking you for an API key or downloading anything. That costs latency — three to five seconds — so the app shows you the number rather than leaving you looking at a spinner wondering whether it hung. If you would rather have the speed, Settings → Voice switches to a keyed remote service that answers in about a second; you supply the key, and it goes to your operating system's keychain rather than into any settings file.

**Speaking, as opposed to typing, needs a key today.** Transcription starts **Off**, and the panel says so where you meet it instead of leaving an unresponsive microphone button to be read as a bug. Pick a speech backend in Settings → Voice and add a key, and the microphone button starts working: press once to start, press once to stop. Run the microphone for thirty seconds and the app stops listening and asks whether to send or discard what it captured — it will not spend a transcription call on a microphone you left open by accident.

**What it can do today is navigation, and only navigation.** Open one agent's pane, open the agent overview, go back to the deck, close an agent view, open settings. Nothing that starts an agent, stops one, or answers a permission prompt is reachable by voice, and that is deliberate rather than unfinished — those are the commands where a rare misfire is expensive, and they are waiting on a confirmation step of their own. "Close the agent view" closes the *view*; it does not stop the agent and does not close its terminal pane.

**Asking for something it cannot do gets you a useful answer rather than a shrug.** Ask to close an agent view when none is open and it tells you what it needs first, naming the prerequisite. Ask for something it has no command for and it says so and **shows you exactly what it heard**, so a mis-transcription is something you can correct instead of a mystery. Every sentence you see comes from the app, not from the model — the model picks an action from a fixed list and never writes prose you read. After a command that moved you somewhere, an **Undo** sits in the report for ten seconds.

**Nothing you say is written down by this app.** No transcript, utterance or audio buffer is logged or saved anywhere, and the recording is turned into text before it ever leaves the Rust side of the app. Two limits on that, stated because the unqualified version would be false: when the default backend hands your sentence to the `claude` CLI, it passes the flag that tells that program not to keep a session — so the guarantee there is one this app *asks for* from another program. And if you choose a keyed remote backend, your words go to that service, and what it keeps is its policy and not something this app can promise anything about.

**Known limits worth reading before you rely on it.** There is one activation mode — press to start, press to stop — with hold-to-talk and always-on still to come. Speech-to-text is a hosted service until local transcription lands, which is what would remove the key requirement entirely. And the **microphone permission prompt has not been exercised on a packaged build on any platform**: the app carries the macOS usage description it needs, but no automated test in this project can open a real microphone or drive the real app window, so the first time you press that button is genuinely the first time. Typed commands are unaffected by all of it.

The desktop app remains an unsigned alpha outside the CLI's support expectations. Maintainer notes — the pipeline, the command table and its three consumers, what adding a command actually costs, what the build-time guard does and does not see, and the manual checks that cover what no test does — are in `docs/develop/desktop-gui.md`, which is maintainer documentation and is not published to the docs site.
