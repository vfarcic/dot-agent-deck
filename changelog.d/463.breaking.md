## Orchestration agents from deck versions before v0.35.0 are refused

Deck versions before v0.35.0 are no longer supported against a current daemon. Every orchestration tab started since v0.35.0 carries its own identity, which is what keeps two tabs of the same orchestration in the same directory from receiving each other's `delegate` and `work-done` messages. An older deck sends none, and the daemon used to accept its orchestration agents anyway, routing them by orchestration name and directory, where two such tabs could still receive each other's messages. The daemon now refuses to start them, with an error that names v0.35.0, and starts nothing. Upgrade the deck to the daemon's version.

If you reattach to a daemon from an earlier release that is still running orchestration agents an older deck started, those agents now appear on the dashboard as plain panes rather than in an orchestration tab, and the deck shows one warning naming the orchestration.

This is a compatibility change between builds: an orchestration start that an older daemon accepted can now be refused.
