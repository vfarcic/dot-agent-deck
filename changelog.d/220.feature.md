## A dispatched unit now reports back to the pane that started it

Dispatcher mode could start work and then never tell you anything again. You asked a dispatcher pane to start something, it set up an isolated copy of your repository, put an agent or a whole team to work in it, told you where — and that was the last you heard. Finding out how any of it went meant going and looking, unit by unit, and remembering to.

When a unit finishes it now reports back into the conversation that dispatched it, as a turn reading `dispatch: unit 'fix-auth-bug' completed. Report:` followed by the unit's own account of what it did. It arrives as though you had typed it, so the dispatcher reads it and can act on it: tell that conversation what you want done with each result — collected, compared, or used to start the next thing — and it will.

This works for both shapes. A dispatched team's orchestrator was already told to signal completion; a **single dispatched agent** is now told the same thing in its own prompt, so the half of dispatch that had nothing to report with reports too. You do not have to ask for any of this in the task you write.

That is what makes the dispatcher worth staying in. Until now there was one way to work with dispatched units — open each one's tab and drive it yourself. There are now two, and they mix: start five things from one conversation and let five outcomes land there as they finish, or open the ones you want to work with directly.

**Delivery is to a live pane, and nothing is stored on the way.** If the dispatcher pane is no longer running when a unit finishes — you closed it, or stopped the daemon — the report is dropped and noted in the log, with nothing queuing it, re-sending it, or holding it in an inbox to read later. The unit's work is untouched by that: it is still committed on the unit's own branch, in the unit's own directory. What is lost is the summary. Closing the deck window is *not* one of these cases — that is a detach, your panes keep running, and a report that arrives while you are away is waiting in the dispatcher when you come back. Nor is a recycled pane: a report only ever goes to the agent that asked for the work, never to whatever took a closed pane's place.

[Dispatcher Mode](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode) has the whole flow, including what to expect when a report does not arrive.
