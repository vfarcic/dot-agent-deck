## Hostile agent names and tool names can no longer spoof a dashboard card

Two producer-supplied strings reached the rendered deck without being scrubbed, so an agent on the local hook socket — or a malformed daemon echoing a record back — could put terminal escape sequences or a Unicode right-to-left override into a card title or a card's tool line. On a stacked deck an override reorders the text that follows it, which is enough to make one card's title read as another's.

The card title is the more surprising of the two, because the sanitizing added in the previous fix was defending the wrong copy of it. `render_card_grid` prefers the display name the TUI hydrated from the daemon and only falls back to the one carried on the session, so the scrub that ran at hook ingest protected the title on exactly one of its two sources. Both writers of the preferred copy are now covered: the daemon's `list_agents` echo is scrubbed and clamped at the TUI's wire boundary, and a rename is refused outright when the name carries a bidi override — a case the daemon's own byte-level validity check could not see, since `U+202E` encodes as three UTF-8 bytes that are each well above the ASCII control range.

A tool name and tool detail arriving live on the hook socket are now scrubbed and length-clamped at ingest, matching what the same two strings already got when they arrived over the daemon's record echo instead.

Ordinary names are unaffected: accented Latin, Cyrillic, CJK, emoji and right-to-left script that needs no override character all still render and still pass a rename.
