## Dispatched Issues Are Claimed on GitHub

An issue-dispatch schedule now marks every issue it dispatches on GitHub, so anyone reading the repository's issue list can see that an agent is working on it, before a pull request exists.

Once an issue's agent has started, the deck adds the `agent-deck/claimed` label to the issue, creating the label in the repository first if it is missing, and posts one comment naming the schedule and the machine that dispatched it. Dispatching the same issue again from the same schedule and machine updates that comment instead of posting another one. An issue whose agent fails to start gets no claim.

Claiming needs the account `gh` is signed in with to have write access to the repository. When the claim cannot be written, for example with a read-only token, the daemon log gets one `claim failed for issue #<n>` line saying what happened to the label and to the comment, and the agent keeps working. The deck never removes the label or the comment, including when you close the issue's tab, so remove them by hand when you no longer want them. The claim does not yet stop another machine or schedule from dispatching the same issue.

See [Claims on GitHub](https://agent-deck.devopstoolkit.ai/docs/scheduled-tasks.md#claims-on-github).
