## An automatic prompt now waits out a slow agent's confirmation before it is typed in again

When the deck delivers a prompt automatically — a dispatch, a scheduled task, an orchestrator's role prompt or a mode seed — it waits for the agent to report having submitted it, and re-submits if that report does not come. The first re-submission fired **500 ms** after the write for every agent. A Codex confirmation has been measured arriving up to ~8.45 s after the prompt was delivered, so the deck re-submitted long before it, and the agent received the same prompt twice.

The wait before each re-submission is now floored at how long the agent's confirmation can plausibly take: **2 s** for Claude Code, whose confirmation arrives on the submit itself, and **10 s** for Codex and for the agents whose confirmation time has not been measured (OpenCode, Devin). A prompt the agent confirms promptly is unaffected. What changes is the case where a submit really was lost: the deck now takes that much longer to try again.
