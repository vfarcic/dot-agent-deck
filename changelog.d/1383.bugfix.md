## A Delegated Task Lost While Its Worker Was Starting Is Now Re-Sent

A task delegated to a worker that was still starting up could disappear without a trace: the worker looked healthy and idle while the orchestrator waited for a `work-done` that never came. OpenCode workers were the most affected. When a worker shows no sign of starting on its task, the deck now sends it again into the same worker, up to three more times with the default settings; the worker is never restarted to do it. A worker may therefore see a task pointer more than once, and its task file tells it that this is the same task. The went-quiet report to the orchestrator now arrives after the re-sends have run out, about three and a half minutes after the task was first sent, and says how many there were. Set `DOT_AGENT_DECK_DELEGATE_RETRY_SCHEDULE_MS` to change the timing, or `0` to turn the re-send off. A Codex worker is never sent a second copy of its task, and a role whose agent the deck cannot identify gets no re-send until you declare its agent.

**Upgrade note:** each task file now opens by asking the worker to run the deck's `ack` command. If a role's tool allowlist names `work-done`, such as `Bash(/home/you/.local/bin/dot-agent-deck work-done:*)`, allow `ack` in the same form (`Bash(/home/you/.local/bin/dot-agent-deck ack:*)`), or the worker stops at an approval prompt at the start of every task.

See [A lost task is re-sent into the same worker](https://agent-deck.devopstoolkit.ai/docs/orchestration#a-lost-task-is-re-sent-into-the-same-worker).
