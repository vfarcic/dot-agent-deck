## Delegated Tasks Lost to a Slow-Booting Worker Now Arrive

A delegated task typed into a worker that was still starting up could be swallowed without a trace, leaving a healthy-looking worker idle while the orchestrator waited for a `work-done` that never came. Agents that announce nothing before their first prompt, such as OpenCode, were the most exposed, because no fixed delay can prove they are ready.

The deck now waits for proof that the worker received its task — the agent starting a turn, a `work-done`, or an acknowledgement — and while none arrives it re-sends the task into the same worker process, never restarting it. Every delegation carries a short delivery id at the end of the line typed into the worker's pane (`… for your task. [delivery d-7f3a9c21]`), and the worker's task file now opens by asking it to run `dot-agent-deck ack d-7f3a9c21`, which stops the re-sending; it prints "Acknowledged" only when the id matches the delivery the deck gave that pane. Each re-send presses Enter first, never types the task again once it has shown as already submitted in the worker's pane, and otherwise types it again only when it is not visible in the worker's pane and the worker stays silent for a few seconds afterwards — never for a Codex worker, whose delivery the deck cannot always confirm, so a second copy could start the task twice; it skips the re-send if you have typed into the worker's pane since the deck last wrote to it. If every re-send goes unanswered, the orchestrator's went-quiet report says how many were made.

The schedule defaults to re-sends 20, 60 and 140 seconds after the first write; set `DOT_AGENT_DECK_DELEGATE_RETRY_SCHEDULE_MS` (comma-separated milliseconds) to change it, or `0` to turn it off. **Upgrade note:** a role whose tool allowlist names `work-done`, such as `Bash(/home/you/.local/bin/dot-agent-deck work-done:*)`, must also allow `ack` in the same form (`Bash(/home/you/.local/bin/dot-agent-deck ack:*)`), or the worker stops at an approval prompt on the first step of its task. The command is written with the deck's absolute path, so a rule naming the bare `dot-agent-deck` does not match it. A role whose agent the deck cannot identify is not re-sent to; declare its agent to cover it.

See [A lost task is re-sent into the same worker](https://agent-deck.devopstoolkit.ai/docs/orchestration#a-lost-task-is-re-sent-into-the-same-worker).
