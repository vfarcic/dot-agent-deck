## A card says why an agent's waiting messages are held, and what to do about it

When messages had waited a couple of minutes for an agent that was not working, the TUI card and the desktop tile said only `waiting to wake: send it a prompt`, even when the deck knew exactly what was keeping the doorbell from ringing. Now, when it knows, both clients say so under the agent's directory, and the badge keeps only the count: `✉N waiting: there may be an unsent draft. Send it or clear it.` when the deck checked a Claude Code agent's input box and found something in it, `✉N waiting: the deck can't check this agent's input box. Check its pane.` when it can't check that box right now, `✉N waiting: ask the agent to run dot-agent-deck inbox fetch; reinstall the deck integration to restore automatic delivery` when something was typed into the input box of a Claude Code agent whose box the deck can't check, such as one started through a launcher script or one running on macOS, `✉N waiting: a paste into its input has not finished.` when a paste into the pane has not ended, and `✉N not yet taken: the agent may be waiting at a prompt. Check its pane.` when the agent is waiting for an answer or the deck found no input box it could type into. The words go away once the agent takes its messages or starts working. An older TUI or desktop app attached to this deck shows each of these as `waiting to wake: send it a prompt`. An orchestrator told that a task has not reached its worker is told the reason too, as it stood when the report was sent.

See [Orchestration → Delivery in the TUI and desktop app](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#delivery-in-the-tui-and-desktop-app).
