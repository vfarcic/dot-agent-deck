## A card says why an agent's waiting messages are held, and what to do about it

When messages had waited a couple of minutes for an agent that was not working, the TUI card and the desktop tile said only `waiting to wake: send it a prompt`, even when the deck knew exactly what was keeping the doorbell from ringing. Now, when it knows, both clients say so under the agent's directory, and the badge keeps only the count: `✉N waiting: ask the agent to run dot-agent-deck inbox fetch; reinstall the deck integration to restore automatic delivery` when something was typed into a Claude Code agent's input box, which the deck can't check yet, `✉N waiting: the deck can't check this agent's input box. Check its pane.` when it can't check the box right now, `✉N waiting: a paste into its input has not finished.` when a paste into the pane has not ended, and `✉N not yet taken: the agent may be waiting at a prompt. Check its pane.` when the agent is waiting for an answer or the deck found no input box it could type into. The words go away once the agent takes its messages or starts working. An older TUI or desktop app attached to this deck shows the first two as `waiting to wake: send it a prompt`. An orchestrator told that a task has not reached its worker is told the reason too, as it stood when the report was sent.

See [Orchestration → Delivery in the TUI and desktop app](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#delivery-in-the-tui-and-desktop-app).
