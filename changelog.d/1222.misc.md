## The contributor rules now say what `gh pr merge --auto` actually waits for

`CLAUDE.md` rule 8 said an automated flow may arm auto-merge because "that waits for the same approval a manual merge needs, so it is not a bypass". Accurate about the approval and silent about status checks — which is exactly the reading that merged #1208, a lockfile update, inside Renovate's `renovate/stability-days` window on 2026-09-21. GitHub's auto-merge waits for the **required** contexts and the review rule, and this repository requires five of them (`build`, `build-macos`, `build-windows`, `security`, `e2e-deterministic`); `renovate/stability-days` is not one, so the approved pull request was already mergeable and `gh` dropped the `--auto` flag and merged on the spot. `isImmediatelyMergeable` counts `UNSTABLE` — the state a pending or failing *non-required* check produces — as immediately mergeable, so that degradation happens client-side, with exit 0 and, when stdout is not a terminal, no output; the tell is `gh pr view <n> --json autoMergeRequest` reading `null` *after* the call. Armed earlier, before the approval, `--auto` does arm, and the unrequired check still does not hold it: GitHub merges when the approval lands.

The correction lands in the four places that tell someone to arm it — rule 8's auto-merge bullet, `docs/develop/governance.md`'s "who merges" bullet and its never-merge-your-own paragraph, the `pr-create` skill's hand-off step, and the task text `prd-queue` composes for a dispatched unit — and each now says the same thing: auto-merge is a way of not bypassing the *review* rule, never a way of waiting for a check. Where a flow genuinely needs an unrequired check, poll `gh pr checks <n>` for that context and merge when it passes, or leave the pull request disarmed for a person.

**No repository setting, ruleset or Renovate configuration changed.** Whether `renovate/stability-days` should become a required context — enforcing the window it currently only advertises — is left as an open question for a maintainer on the pull request.
