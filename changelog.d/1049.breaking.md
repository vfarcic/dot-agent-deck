**Protocol break: `PROTOCOL_VERSION` 9 → 10.** The attach protocol gains a `stop-daemon` request, the first wire verb that stops a deck. A daemon speaking 9 fails the frame decode on a variant it does not have, so a client sending it needs a daemon that speaks 10 — check the `stop-daemon` capability on the `hello` reply rather than the version number.

Stopping a deck previously had one implementation and it was inherently local: `dot-agent-deck daemon stop` reads the daemon's PID off the socket with `SO_PEERCRED` and signals it, which needs a kernel-level view of a peer on the same machine. Over a forwarded socket that credential names the local `ssh` client, so a remote deck could not be stopped from the app at all. The new verb has the daemon terminate *itself*, so it works over any transport — including an `ssh -L` tunnel to a deck on another host.

**The refusal travels with it.** `daemon stop` refuses while the daemon holds orchestration roles whose panes still have a live agent, because those role maps live in the daemon's memory and nowhere else — an agent that survives the stop keeps running and keeps looking healthy, but can never delegate again. The wire verb runs that same policy and answers a refusal with a structured `stop_refusal` carrying the panes, the roles, and both the one-line and multi-line renderings, so a client that cannot see the deck's pane list can still present the choice informedly. `force: true` overrides it, exactly as `--force` does on the CLI.
