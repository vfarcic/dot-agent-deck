## The Deck's Own Git Commands No Longer Run Repository Hooks

When the deck runs git in your repositories on its own account, such as creating the worktree for a dispatch or checking whether a worktree has uncommitted work before closing it, it no longer runs the repository's git hooks or its `core.fsmonitor` command. An agent working in one of the repository's worktrees can change those for the whole repository, so before this fix a hook or command it set up could run in the deck's own process the next time the deck touched the repository. Git commands you or your agents run yourselves are unchanged. If you rely on a `post-checkout` hook to prepare a fresh worktree, it no longer runs for worktrees the deck creates; run that setup from the agent's task instead.
