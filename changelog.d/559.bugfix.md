## Codex Panes No Longer Receive an Automatic Prompt Twice When Their Hooks Are Untrusted

A Codex pane could have an automatic prompt typed in a second time: a mode's seed prompt, an orchestration role's first task, or a dispatched unit's task. It happened when the deck could not get Codex to trust its hooks for that pane, most often because `codex` was reachable only inside a launcher such as `devbox run codex-big` and not on the deck's own `PATH`. Without those hooks Codex cannot tell the deck it received the prompt. The deck kept waiting for that report and re-submitted a prompt the agent had already taken, so a task that deploys, deletes or opens issues could run twice.

The deck now recognizes a Codex pane in that state and writes its automatic prompt exactly once, the way it already treats Pi. A Codex pane whose hooks are trusted still has a lost prompt re-submitted, as before. To get that recovery back on an affected host, make `codex` reachable from the shell you start the deck in. [Troubleshooting › Codex events not showing](https://agent-deck.devopstoolkit.ai/docs/troubleshooting#codex-events-not-showing) has the other checks.
