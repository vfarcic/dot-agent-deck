## The terminal is handed back even when the TUI exits on an error

A terminal I/O error — an ssh link dropping, a terminal window closed under the process, a failed write to stdout — could return out of the event loop without restoring the terminal, dropping you into a shell still in raw mode and still on the alternate screen: the prompt did not echo, line editing misbehaved, and your scrollback had been replaced by the deck's last frame. Nothing in the output said the terminal had been modified, so it read as the shell being broken rather than as a deck exit.

The restore now belongs to the same guard that already turned mouse capture, bracketed paste and focus reporting off on those paths, and to the same once-only flag, so it happens exactly once whichever combination of the explicit teardown, the guard and the panic hook runs — in the order that was already deliberate.
