## Installing Codex hooks no longer widens the permissions on your Codex config

Installing or uninstalling the deck's Codex hooks rewrote `~/.codex/hooks.json`, and recording per-hook trust rewrote `~/.codex/config.toml` — the file holding your model choice, auth references, trust records and anything else you have hand-written there. Both went out through a temp file that was created with the process default of `0666 & !umask`: 0644 under a typical 022 umask, and **0664 — group-writable — under the 002 umask many distributions ship**. The rename that published it then replaced the destination with that wider file, so a config you had deliberately kept at 0600 came back readable, or writable, by every other account on the machine. Nothing reported the change, and it happened the first time the deck installed its hooks.

The publish now carries the destination's own mode over, and creates the file owner-only (0600) when it does not exist yet. A config you restricted keeps exactly the mode you chose; one the deck creates itself is private regardless of your umask, rather than inheriting whatever the umask allows.

Your Codex credentials were never exposed by this — `auth.json` is written by a different path that has always forced 0600 — and the same defect in the Devin adapter was fixed in an earlier release. The two adapters now publish through one shared helper, so this cannot survive in a copy again.
