## Zoom, on the keys you already use

The desktop GUI zooms. `Cmd +`, `Cmd -` and `Cmd 0` on macOS, `Ctrl` equivalents elsewhere, scale the whole window — the chrome and the agent terminals together — and the level survives a restart. A Tauri window gets none of that for free, so before this the app was fixed at whatever size it shipped with, and several of its labels are 6px.

Ten levels from 75% to 300%, with `Cmd 0` back to 100%. Settings → Zoom carries the same level in a list of percentages, which is worth knowing about: a webview zoom has no indicator of its own, so that row is the only place the app can tell you what level you are actually at. Choosing 100% there is the reset. The keys work while you are typing in an agent's terminal, which is where you spend most of your time.

**The terminals genuinely re-fit rather than just getting bigger.** Zooming changes how many rows and columns fit a pane, and the agent's own program has to be told or it keeps painting at the old width — text the right size in the wrong shape. Every zoom step re-measures each pane and passes the new size through to the daemon, coalesced so that holding a key down cannot flood it. The one thing to expect: the agent repaints, so a long-running TUI redraws itself as you zoom.

The level lives in `[zoom]` in `desktop.toml`, beside your appearance choice, and is applied before the window's first paint — so an app stored at 150% opens at 150% rather than flashing 100% and jumping. The file is hand-editable; a level that is not one of the ten snaps to the nearest one rather than being rejected, and a corrupt value falls back to 100% without taking your appearance choice with it.

Two limits worth stating. The browser fixture preview (`?fixture=1`) deliberately does **not** bind these keys, because a browser already has its own zoom and doing both would zoom twice — the Zoom row says so there rather than offering a control that does nothing. And zoom is global to the window rather than per-pane: per-pane text size is a different feature, tracked separately, and may turn out to be better answered by giving one pane the whole window than by making its text bigger.
