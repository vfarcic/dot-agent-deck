## The Desktop App Finds a Remote Deck Homebrew Installed

The desktop app now connects to and starts the daemon of a remote deck whose `dot-agent-deck` was installed with Homebrew, even when the deck's entry in the deck list records no binary path. Before, the app looked only in `~/.local/bin` on the host and reported "dot-agent-deck is not installed", while `dot-agent-deck connect` to the same deck worked.

When the app checks a disconnected remote daemon, or you press **Start daemon**, and `~/.local/bin/dot-agent-deck` is missing, it now looks for a Homebrew install the way `connect` does, checks that it runs, uses it, and records it in the deck list, so the next check, from the app or the terminal, runs it straight away. When the deck is installed nowhere the app looked, the message names both ways to install it: `brew install vfarcic/tap/dot-agent-deck` on the host, or `dot-agent-deck remote add` from this machine.

See [Hosts where Homebrew installed the deck](https://agent-deck.devopstoolkit.ai/docs/remote-environments.md#hosts-where-homebrew-installed-the-deck) and [When Start daemon fails](https://agent-deck.devopstoolkit.ai/docs/desktop/daemons.md#when-start-daemon-fails).
