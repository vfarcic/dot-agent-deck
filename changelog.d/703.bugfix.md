## A dispatched team is told that nobody is watching it, and which instructions win

A team started in the background by [dispatcher mode](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode) received the project's orchestrator `prompt_template` unchanged, including any step written for the case where somebody is sitting in front of the pane. This repo's own template has two: "Surface the plan to the user as a Markdown table and STOP. Wait for explicit approval" and "Then pause — the user reviews the PR". A dispatched unit has nobody to answer, and `dispatch` reports nothing back, so a coordinator that took such a step literally parked its whole team for as long as the run was left alone — with no error, no notification and no way to tell from the outside. Dispatched teams have sailed past that gate in practice, by reading their task as pre-approval; that was a fortunate reading of an ambiguity, not a designed outcome.

The composed coordinator context now carries two new sections, both immediately ahead of the task. A dispatched run gets **`## Unattended run`**: nobody has been asked to watch this pane, there is no channel back to whoever started it, a step that waits for approval does not apply to this run, and the dispatched task is the approval that step was waiting for. If the coordinator does reach a decision that is genuinely not its to make, it is told to say so through whatever notification its own template describes and then finish, rather than wait silently. Any run carrying a task — dispatched or not — also gets **`## Task precedence`**, which settles a conflict that until now only the section ordering spoke to: the task wins on *what to do and when to stop*, the template wins on *how to work*, and a later template step that would go past the task's stop condition (merging, releasing, publishing, deleting) does not fire unless the task asks for it. The same section declares that everything from `## Your task` onward is the task, so a task written with its own `##` sections is no longer read as amendments to the orchestration config.

**Nothing changes for a team you are watching.** Whether a human is attending the pane is declared by whoever starts the run, not guessed from whether a task was supplied — the desktop's live-loop launch requires a task prompt and has the operator who typed it in front of the panes, so inferring from the task would have stripped the one gate that operator was there to answer. An interactive `Ctrl+n` orchestration's context file is byte-for-byte what it was. Your `prompt_template` needs no edit and no branching: one template covers both cases.

No wire shape or meaning moved, so `PROTOCOL_VERSION` is unchanged at 9. A compaction or `/clear` re-assertion recovers the attendance from the published file alongside the task, so a re-armed dispatched coordinator is not quietly handed the attended text; a file written by an earlier release carries no notice, re-arms as attended and keeps its task.

See [Dispatcher Mode](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode) for the user-facing contract.
