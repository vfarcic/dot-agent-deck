## The TUI and the desktop app no longer attach to a replacement daemon on another attach protocol

If the daemon was replaced while the TUI was open, the TUI reconnected to the new one without checking that the two speak the same attach protocol, so it could show a normal dashboard while it could not read what that daemon sent. It now checks the daemon's protocol on the connection it is about to use whenever it reconnects, reattaches or restores a pane, opens a new agent pane, or lists the daemon's agents for one of those. When the protocols differ it does none of them: a footer row says `⚠ Not attaching: daemon speaks attach protocol vN, but this binary speaks vM`, with the same two ways out as the startup refusal, until a daemon on its own protocol answers again, and a new agent pane is not started on that daemon. If the check cannot be made at all, the TUI keeps retrying rather than attaching. In the desktop app, every agent terminal it opens, every list of a daemon's agents, every watch of their activity and every agent it starts checks the daemon the same way: a replacement daemon that the app would refuse when connecting, whether for another protocol or for a version that could make the app misread what it reports, is listed, watched and started on by nothing, and an agent terminal opened against one is refused. **Connect anyway** still applies to the second case.

See [Troubleshooting](https://agent-deck.devopstoolkit.ai/docs/troubleshooting.md#daemon-speaks-attach-protocol-vn-but-this-binary-speaks-vm).
