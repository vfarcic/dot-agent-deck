## A hook-socket request that breaks mid-write is no longer reported as never sent

`delegate`, `work-done`, `dispatch`, `pane restart` and `pane spawn` all send one line to the daemon's hook socket and classify what comes back. That classification used to call any write failure "unreachable — the request was never sent", which is the outcome a caller is allowed to retry on. It was not always true: the socket carries a write timeout, so a write can fail with part of the line already in the daemon's receive buffer, and the daemon treats a trailing unterminated line as a line — a write that broke after the last byte of JSON but before the newline hands it a complete, actionable request. Retrying that is how one `delegate` becomes two.

The client now counts the bytes it actually wrote. A failure with nothing written keeps the "not delivered, safe to resend" classification; a failure with any byte already gone is reported as unconfirmed instead, and logged with a warning naming how far the write got. In that narrow case `delegate`, `work-done` and `dispatch` now exit 0 without printing a delivery failure they cannot prove — deliberately silent, because the sender is usually an agent and a "may not have landed" line is an invitation to send it again — while `pane restart` and `pane spawn` still exit non-zero and now say "the daemon did not answer" rather than "did not answer in time", and still advise checking the pane before retrying.

No wire change: the bytes sent, the daemon's handlers and `PROTOCOL_VERSION` are all untouched, and `get-seed` is unaffected because it already collapsed both outcomes to "no seed".
