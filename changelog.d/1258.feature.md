## See how much room a deck's machine has left

Before you start more agents on a deck, you can check the machine it runs on: free and total disk space where the deck works, where sibling worktrees are created and where test scratch files go, plus load per core with the core count, memory used and available, and how old the figures are. For a remote deck these are the remote machine's figures, on Linux and macOS alike.

Each figure is coloured by how the machine is doing: green when it is fine, yellow (amber in the desktop app) for a warning and red when it is critical, with `(warning)` or `(critical)` written after it so the colour is never the only sign. By default a disk warns below 15% free and is critical below 5%, memory below 20% and 10% available, and load above 0.8 and 1.5 per core. Change the limits for a deck under `[host_metrics]` in its `config.toml`, or with `dot-agent-deck config set host_metrics.<key> <value>`.

In the TUI, press `m` in command mode to open the **Host of this deck** overlay, and `Esc` to close it. The key can be remapped as `host_metrics` under `[dashboard]` in `keybindings.toml`. In the desktop app, each daemon's section on the Dashboard has a small **Host** button beside its name, coloured by that machine's worst figure (for example **Host: critical**); click it to see the figures, and with several daemons shown you can compare every machine at a glance. A figure the machine cannot report reads `unknown` rather than `0`. A daemon from an earlier release, or one running on Windows, says **Host metrics are not available from this deck**.

See [Check the machine a deck runs on](https://agent-deck.devopstoolkit.ai/docs/session-management.md#check-the-machine-a-deck-runs-on).
