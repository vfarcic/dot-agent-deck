## Wrapped agent children can no longer outlive a killed wrapper in the test suite

`cargo test-e2e` could leave a wrapped agent process running indefinitely. The `wrap` process already self-terminates under `DOT_AGENT_DECK_TEST_MAX_LIFETIME_SECS`, but it bounded its child only by reaping it — which needs the wrapper alive to do the reaping. Any uncatchable end to the wrapper (the deck's own SIGKILL escalation, an OOM kill, a nextest timeout) stranded the child instead, and because the child is `setsid`'d into its own session, nothing above it could signal it afterwards. Measured strays ran for 21–29 minutes, and one for over eight days; each pinned its e2e temp directory against `cargo xtask clean-e2e-tmp`, which never reaps a directory whose owning process is still alive, so 14.2 GB accumulated that no cleanup pass could recover.

The wrapper now forks a small reaper alongside the child that holds the same deadline independently: it leaves the wrapper's process group so a group kill cannot take it too, holds no file descriptors, exits as soon as the child's group is gone, and otherwise applies the same SIGTERM-then-SIGKILL teardown the wrapper would have. Like the wrapper's own backstop it is armed only when `DOT_AGENT_DECK_TEST_MAX_LIFETIME_SECS` is set, which the test harness does and production does not — a normal `dot-agent-deck wrap` forks nothing extra and behaves exactly as before.
