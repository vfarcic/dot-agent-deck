## Workspace Modes Removed

Workspace modes — the `[[modes]]` block in `.dot-agent-deck.toml` and the Mode tab it opened, with an agent pane beside persistent and reactive side panes driven by regex watch rules — have been removed. They did not work well, and orchestrations, scheduled tasks and dispatcher mode cover what people used them for.

An existing `[[modes]]` block is ignored with a warning rather than rejected, so every config written before the removal keeps loading. The first time the New Agent form (`Ctrl+N`) opens a project that still declares one, the status line says workspace modes were removed and the full message, naming the config file, is printed when the deck exits. `dot-agent-deck validate` reports the block as a single warning and still exits `0`. Delete the block to silence both. A pane saved in a mode tab by an earlier version comes back as a plain dashboard pane, with a warning saying so.

The New Agent form's `Mode:` row keeps `No mode`, one `Orch: <name>` chip per orchestration, and the built-in `schedule`, `schedule: issues` and `dispatcher` options, all of which work exactly as before. `dot-agent-deck init` now writes a commented orchestration starter instead of a `[[modes]]` template, config generation (`g`) proposes orchestrations only, and `dot-agent-deck watch` remains available as a standalone command.

See [Orchestration](https://agent-deck.devopstoolkit.ai/docs/orchestration).
