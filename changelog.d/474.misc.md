## The one file that may not name its own crate is now checked rather than commented

`src/test_temp.rs` resolves the disk-backed `/var/tmp/dad-e2e-<uid>` scratch parent for tests that do not link the PTY harness. It is compiled into the lib target as an ordinary module and, via `#[path = "../src/test_temp.rs"]`, into ten integration-test crates as well — an arrangement that only works because the file is self-contained. In those crates `crate::` is the *test* binary's own root, where nothing the library defines is in scope, so one added `crate::` path breaks every consumer at once.

That property is load-bearing economics rather than a style preference. Containing those fast-tier crates with `mod common;` was priced at pulling the PTY harness into six more binaries and duplicating roughly 530 fast-tier executions; the `#[path]` route cost 12, measured as `cargo nextest list` going 2,315 → 2,327. The whole difference between those two numbers rested on one file staying free of `crate::`, and it was enforced by a comment.

`cargo xtask linkage-check` now has a ninth rule that refuses one, naming the file and line and explaining why the file is unusual. Two things make a mechanical check worth having over the compiler. A `crate::` path fails as N identical `E0433`s with no hint of the arrangement behind them, so the obvious "fix" is to unpick it rather than to drop the reference. And whether it fails at all depends on which names the *consumer* happens to have at its own crate root: measured by adding a `crate::features::experimental_enabled()` probe to the module, nine of the ten including crates failed with `cannot find features in crate` while `tests/features.rs` compiled clean, because its own `use dot_agent_deck::features::{self, Features};` puts a `features` at that test crate's root. A `crate::` path can therefore land green under whichever filtered `cargo test-fast` the author ran and break the next consumer to include the file. The scan runs over the comment-stripped source, so the file's own header note can point at the rule by name; a rename that left the rule's path constant behind fails the check rather than turning it into a no-op that still prints `ok`.

Five tests in `xtask/linkage-check` hold it, all against synthetic sources rather than the live checkout — whose copy is clean by construction and would make them pass for a reason unrelated to the rule working. They cover a rejected `use` and call, the `$crate::` and spaced `crate ::` forms, an accepted self-contained module including a crate whose name merely ends in `crate`, and the guarded file going missing. No change to the shipped binary.
