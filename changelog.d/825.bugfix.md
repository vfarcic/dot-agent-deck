## Hand-written comments and formatting in `desktop.toml` survive a save

PRD [#803](https://github.com/vfarcic/dot-agent-deck/issues/803) makes "a file a user can read, edit and delete without Agent Deck running" a success criterion for the desktop app's settings document — which invites people to annotate it. Those annotations then disappeared the next time the app wrote any setting: change the theme, and the comment explaining why a section is there was gone, an inline array came back re-flowed across lines, and key order and blank-line grouping were whatever the serialiser felt like. No *data* was ever lost — an unknown section written by a newer build always survived, and still does — but the document was re-rendered canonically on every write, because the merge round-tripped through `toml::Table`, which models data rather than text.

The save now merges into a format-preserving DOM. Comments above a key or a section header survive, a trailing comment on a line whose value **did** change survives with it (`mode = "light"  # my own note` becomes `mode = "dark"  # my own note`), inline tables and inline arrays keep their spelling, key order and blank lines are untouched, and a save with no new value to write leaves the file byte for byte as it found it. A section spelled `endpoints = { … }` by hand stays inline even when the app adds a deck to it.

Two limits, stated because a wide claim here would be false. A **changed** list is rewritten whole, so a comment between `[[endpoints.remote]]` rows goes with it the first time a deck is added, removed or edited; an unchanged list, comment included, is left alone. And a document missing a section this build owns gains that section on the next save, appended after what is already there.

This replaced the desktop crate's `toml` dependency with `toml_edit` rather than adding a second TOML library beside the first, so exactly one parser reads and writes the file. It is not a new dependency in any sense that costs anything: the root package has declared `toml_edit` since PRD [#20](https://github.com/vfarcic/dot-agent-deck/issues/20) for the same reason (a format-preserving edit of the user's `~/.codex/config.toml`), the desktop crate already links the root package, and the lockfile gains **zero** new packages — only two feature edges on a crate it already built.

The data-preservation guarantee and issue [#1072](https://github.com/vfarcic/dot-agent-deck/issues/1072)'s refusal to overwrite a `desktop.toml` this build cannot read both still hold, with their own tests still green. Nothing here crosses the TUI↔daemon protocol — `desktop.toml` is read and written entirely inside the desktop process and the daemon cannot observe it — so `PROTOCOL_VERSION` is untouched and CLAUDE.md rule 12's cross-version check does not apply.
