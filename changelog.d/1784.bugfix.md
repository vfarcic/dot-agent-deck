## Orchestrators know which workers restart for every task

An orchestrator that sent a worker more information about the task it was already doing could restart that worker without meaning to. On a role with `clear = true`, the default, every delegate restarts the worker's agent, `delegate --supersede` included, so the worker lost its conversation and anything it had not saved, and the new agent saw only the addition.

The orchestrator's instructions now mark each `clear = true` worker as starting fresh for every task, and say how to add to a task in progress without losing work. For a `clear = true` worker, the orchestrator waits for the `work-done` and delegates a follow-up that restates what the worker needs, or supersedes with the whole task restated. For a `clear = false` worker, `delegate --supersede` reaches the running agent, which keeps its work. If a role's work usually continues from one task to the next, set `clear = false` on that role.

See [Adding to a task in progress](https://agent-deck.devopstoolkit.ai/docs/orchestration.md#adding-to-a-task-in-progress).
