## An older TUI or desktop app meets refusals for orchestrations you have not approved

From this release the deck runs an orchestration from a project's `.dot-agent-deck.toml` only after you have approved that orchestration's role commands, descriptions and prompts as they read now, and asks again when any of that text changes. The TUI and the desktop app from this release show you the text and let you approve it in place. An older TUI or desktop app attached to a daemon from this release cannot show that prompt. Opening such an orchestration from an older desktop app's New agent dialog or Runs screen fails. An older TUI still opens it, but the deck refuses its agents' `delegate`, `pane restart`, `pane spawn` and `dispatch`. Schedules and issue dispatches that would start it are refused whichever client you use. Each refusal names the orchestration, the project and the command that approves it, to run from a terminal outside the deck: `dot-agent-deck trust approve <project> --orchestration <name>`. Upgrade the TUI and desktop app to this release, or approve once with that command.
