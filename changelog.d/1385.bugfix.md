## Dispatcher, Schedule and Pi Agents Reach the Deck That Started Them

The commands the dispatcher agent and the schedule-authoring agents run — `dispatch`, `dispatch --list-targets`, `schedule add` and `schedule update` — now name the deck by the absolute path of the running binary instead of a bare `dot-agent-deck`, as the orchestration commands already do since the previous release. A bare name was looked up in the agent's own `PATH`, which can hold a different, older `dot-agent-deck` than the deck that started the agent. The Pi extension's `delegate` and `work_done` tools and its status reports go the same way: the deck now tells every agent it starts where it is, and the extension runs that binary rather than whichever `dot-agent-deck` Pi's `PATH` finds first.

The commands are longer — `/home/you/.local/bin/dot-agent-deck dispatch …` — and a permission rule written against the bare name, such as a Claude Code allow rule `Bash(dot-agent-deck dispatch:*)` or `Bash(dot-agent-deck schedule:*)`, no longer matches them. Write such rules against the path the agent's pane shows.

See [Dispatcher Mode](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode.md) and [Schedules](https://agent-deck.devopstoolkit.ai/docs/scheduled-tasks.md).
