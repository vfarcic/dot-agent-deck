## The test suite's load-scaled wait ceilings now scale on macOS too

Issue #709 made the fast tier's boot-sensitive waits widen with the machine's load average, so a contended box stops reading "the child has not been scheduled yet" as "the child did the wrong thing". The measurement was Linux-only on the belief that the `libc` crate does not expose `getloadavg(3)` for Apple targets — it does — so on `build-macos`, a 3-core runner under a full `cargo nextest run`, every one of those ceilings stayed flat. `idle_worker_010` failed there at 8.248 s against its flat 8 s ceiling during PR #1238's CI.

Both copies of the measurement (`tests/common/mod.rs` and `src/test_budget.rs`) now call `getloadavg` on macOS. Linux still reads `/proc/loadavg` exactly as before, every other target still applies no multiplier, and the existing clamp still bounds the result. A macOS-only test in each copy asserts the load is measurable there, so a return to the old behaviour fails on `build-macos` instead of surfacing as a flake. It is macOS-only because on Linux an unreadable `/proc/loadavg` (a restricted container, say) legitimately yields no measurement. Test-support only: nothing in the shipped binary changes.
