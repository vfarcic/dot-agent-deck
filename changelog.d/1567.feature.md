## Pi agents confirm the prompts the deck sends them

The deck now handles a prompt it types into a Pi agent the way it handles one typed into Claude Code: the prompt counts as delivered only once Pi reports submitting it. That covers a dispatched unit's task, a scheduled job's prompt, and a mode or orchestrator prompt typed into the pane. If Pi never reports it, for example because Pi was still starting and the Enter was lost, the deck submits it again. A dispatched Pi unit that never reports its task now gets the same "task may never have arrived" notice on its card as other agents. Before, a prompt typed into a Pi agent was written once and never checked, so a lost one went unnoticed.

Pi also now reports a prompt you submit while it is busy, which Pi queues until its current step ends. That prompt shows on the agent's card when you submit it.

Nothing needs to be set up: the deck's Pi extension does this on its own. A Pi agent that was already running when you upgraded the deck keeps its older extension, and with it the old behaviour, until it restarts.

See [When a unit stays quiet](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode#when-a-unit-stays-quiet).
