## The L1 key-resolution seam applies all three orchestration chord scopings, so a test reasoning about `Ctrl+l` matches what the deck does

`key_action_for_mode` is the seam the TUI's L1 tests use to ask "what does this key do in this mode?", and its own doc comment promises it resolves a key *the way the live loop does*. It composed `global_action_for_mode` and then applied the MODE term of two of the three scoping passes the live call site applies — `scope_command_entry_lock` for `Ctrl+e` and `scope_zoom` for `Ctrl+z` — and skipped the third, `scope_orchestration_split`, which narrows `Ctrl+l` to an orchestration tab in command mode.

So for `Ctrl+l` in `UiMode::PaneInput` the seam answered `Some(Action::ToggleOrchestrationSplit)`, while the deck itself un-resolves the chord there and forwards `0x0c` to the focused pane's PTY, where it is readline's clear-screen. A test reasoning about `Ctrl+l` through that seam was reasoning about behaviour the deck does not have — the exact failure mode the seam's own doc comment describes for `Ctrl+e`.

**No shipped behaviour changed, and none could have.** The live event loop has applied the **split** pass since PRD [#336](https://github.com/vfarcic/dot-agent-deck/issues/336); the lock pass arrived in `82334c13` (2026-08-07) and the zoom pass in `47e5d26a` (PRD #313, 2026-08-30), so the loop has had all three only since then. The gap was between the test seam and the loop, and `key_action_for_mode` has no caller in this repository outside `tests/` and `src/ui.rs`'s own `#[cfg(test)]` module. What is fixed is the seam's fidelity, so a future test cannot be written green against a `Ctrl+l` the deck would never produce. The gap dates from #336 and was made visible by [#404](https://github.com/vfarcic/dot-agent-deck/issues/404), which added the `Ctrl+e` pass beside it.

`orchestration/layout/005` now drives a simulated `Ctrl+l` through the seam in both modes: command mode must still resolve `ToggleOrchestrationSplit`, `PaneInput` must forward `0x0c`. Verified with teeth — with the new pass removed, that test fails with `got Some(ToggleOrchestrationSplit)` while `orchestration/layout/003` and `/007` both stay green, so it is the only test that catches the gap.

One incidental correction in the same function: the inline comment on the zoom pass still described that binding as a plain `z` and argued from its being an ordinary character. `toggle_zoom`'s default has been `Ctrl+z` since PRD [#313](https://github.com/vfarcic/dot-agent-deck/issues/313) was revised, so the comment now names the chord and the reason that actually applies — `0x1a` is the tty's SUSP character, so over-reporting it would be claiming the agent's job control.

Nothing about the TUI↔daemon protocol moved — this is key resolution inside the TUI, which the daemon does not observe — so `PROTOCOL_VERSION` and `CONTRACT_BREAKS` are untouched.
