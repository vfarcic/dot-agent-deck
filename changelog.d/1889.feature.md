## One id for each piece of work, across restarts

The deck now gives every piece of work it runs an id of its own, and keeps it for as long as the work goes on: a pane you start, an orchestration, a task an orchestrator delegates, a unit started by `dot-agent-deck dispatch`, and a scheduled run. An agent restarted in its pane keeps its work's id, and every role of an orchestration shares the orchestration's.

Every agent the deck starts receives that id in the `DOT_AGENT_DECK_WORK_ID` environment variable, so a script or a skill the agent runs can tell which piece of work it belongs to. With telemetry on, each `agent.run` span carries it as `deck.work.id`, and so does each agent's own telemetry through `OTEL_RESOURCE_ATTRIBUTES`: group by `deck.work.id` to see every run one piece of work took and what they used together. See [Telemetry](https://agent-deck.devopstoolkit.ai/docs/telemetry.md).

The deck also keeps a history of what it ran in its state directory, which survives a daemon restart and records which agents a stopped or crashed daemon left unfinished. It holds ids, references and paths only, never prompts, reports or terminal output. The deck trims it in the background while it runs, a part at a time: finished work older than 30 days and finished work beyond the 10,000 most recent are removed, while unfinished work, and the work it belongs to, is kept.
