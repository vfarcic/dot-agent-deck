## Pause a schedule from the deck

The Scheduled Tasks dialog has a **`[Toggle t]`** action: press `t` on a row to pause that schedule, and `t` again to resume it.

The dialog has always *shown* whether a task is paused — a `disabled` row with `—` where its next-fire time would be — but there was no way to reach that state from the deck. Pausing meant asking an agent to run `dot-agent-deck schedule disable`, or hand-editing `enabled = false` in the global config. The dialog was displaying a state you could not act on.

**Pausing is not deleting, which is why this needed its own action.** `[Delete d]` discards the definition — prompt, cron, working directory and all. Toggling keeps every one of them and simply stops the fires, which is what you want for a schedule you are going away from, or one firing noisily while you debug the thing it drives.

There is no confirmation step. Delete gets one because it destroys something; this is reversible from the same key, so a prompt would be friction for nothing.

With this, everything you need to manage a schedule is a key in that dialog — creating, editing, deleting, firing now, pausing, and seeing what is scheduled.
