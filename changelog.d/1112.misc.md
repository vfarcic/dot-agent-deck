## The contributor rules now say who actually approves a pull request

`CLAUDE.md` rule 8 said every change goes through a pull request that "another maintainer approves", and `docs/develop/governance.md` said auto-merge means "a human still reads and judges". Neither has been true for some time: with the repository variable `PR_REVIEW_LIVE` set, the daily `pr-review-batch.yml` sweep casts real approvals unattended, and every pull request merged on 2026-09-17 was approved by `dot-agent-deck-reviewer` rather than by a maintainer. A third lane approves nothing at all — Renovate's `pull_request` bypass merges past both the review rule and the required checks.

The correction is narrow on purpose. It records who casts the routine approval; it does not say that nobody need look. The reviewer refuses what it cannot verify rather than waving it through, which is exactly what happened on #1112 the same day: it returned `REQUEST_CHANGES` because rule 12's cross-version manual test cannot be read off a diff, and it was right to — that branch had been rebased onto a `PROTOCOL_VERSION` bump which invalidated the cross-version evidence its own description recorded. So a `REQUEST_CHANGES` naming a manual obligation is still addressed to a person.
