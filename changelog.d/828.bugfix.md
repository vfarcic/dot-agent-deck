## Desktop settings no longer lose an edit saved from another window

Two desktop app windows open at once, or the app and a text editor both editing `desktop.toml`, used to silently undo each other. A save wrote back every setting the saving window had loaded, including the ones it never touched, so a theme change in one window could delete a remote deck that another window had added a minute earlier. Nothing reported it. The app was simply pointing at the wrong daemon afterwards.

A save now writes only what you changed, and every other setting keeps what the file holds when the save happens. Two windows changing different settings both keep their change. Remote decks merge deck by deck, so two windows can each add a deck, or edit different fields of the same deck, and keep both. A deck you edited is not deleted by a window that removed it from an older copy. After a save the window shows the file as written, including anything another window changed. When two windows change the same setting, the later save wins. Saves from two copies of the app are also serialised, using an empty `.desktop.toml.lock` file that now sits beside `desktop.toml` and is safe to ignore.
