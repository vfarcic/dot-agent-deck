## Answer an Agent's Questions by Voice

When an agent stops to ask you something — a permission prompt, a menu of options, or a form of several questions — you can now answer it by voice in the desktop app. Open the agent's pane and say what you would say to a person: "yes", "go ahead" or "no" to a permission prompt, "the second one" or an option's words for a menu, or "red for colour and large for size" for a form, in one sentence or several. On a question that takes several answers, name them together ("small and large"), and for an option that asks for your own words, choose it and then say them. The answer is shown with a five-second countdown that stops as soon as you speak, so saying "cancel" is never too late, and nothing is sent if the question was answered or changed in the meantime, or if the agent's terminal is not on screen. Choosing an "always allow" option first opens a confirmation that says exactly what it will always allow; press Confirm or say "confirm" — a plain "yes" does not confirm it.

This works for Claude Code 2.1.136 or newer, Codex and OpenCode, including their multiple-choice questions and forms, and for Pi, for the dialogs other Pi extensions show. Devin's permission prompts are supported from its documentation but have not been tried with a running Devin. A few options still have to be answered with the keyboard, such as Claude Code's "Chat about this" and Codex's "None of the above"; the docs list them per agent. After upgrading, run `dot-agent-deck hooks install` (and `dot-agent-deck hooks install --agent codex` for Codex), or restart the daemon, and restart agents that were already running.

While an agent's question is waiting, what you say is first sent to the Commands service together with that question — its text, its options and what it is about, which for a permission prompt is usually the command the agent wants to run — whether voice Names is shared or withheld.

Codex's multiple-choice questions and OpenCode's question menus now show **Needs Input** while they wait for you, instead of **Working**.

See [Voice Control](https://agent-deck.devopstoolkit.ai/docs/desktop/voice.md) for details.
