## A Dispatched Unit Starts at the Commit `dispatch` Reports

The commit named in `dispatch`'s `cut from <branch> at <sha>` reply is now always the commit the unit's worktree was created from. Before, `dispatch` read the commit once to report it and again to create the worktree, so a commit made in the dispatcher's checkout between the two could leave the unit on a different commit than the reply named. Units are still cut from the checkout's current commit, as before.

The unit's branch now records that commit by its sha: `git reflog` on the branch reads `branch: Created from <sha>` rather than `branch: Created from HEAD`.
