## A wrapped Codex no longer gets its prompt while its interface is still starting

The deck holds a delegated or scheduled prompt for a wrapped Codex until the wrapper reports that Codex has taken over its terminal, then waits a further 5 seconds so Codex can finish starting its interface. When that report came late, after the deck had already given up waiting and started the shorter 1-second wait it uses for a weaker signal, the deck ignored it and wrote the prompt when the 1 second ran out. That could put the prompt into a Codex that was still starting and throwing input away, so the worker sat idle with no task. The late report now restarts the wait: the prompt goes out 5 seconds after it, never sooner than it would have gone before. This mostly affects a Codex behind a slow launcher such as `devbox run` on a first run, and scheduled tasks run with a shortened readiness wait.
