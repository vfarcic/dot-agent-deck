## Card Supersession Keeps a Pane's Start Time and Refuses Cross-Pane Identity Takeovers

A pane's start time now survives an agent respawn, and the card-supersession path no longer trusts an assumption about session ids that nothing enforces. Both were unverified assumptions left behind by the earlier supersession work rather than regressions.

A pane's `started_at` used to be preserved only when the outgoing agent managed a graceful `SessionEnd`, because that was the sole place the pane-scoped start time was recorded. A `clear = true` delegate `SIGKILL`s its worker and never sends one, so a respawned pane silently reported that it had started at the replacement's first frame — and both respawn shapes did it, the cross-key retire and the same-key identity refresh alike. The start time is now recorded whenever a card is superseded, keeping the earliest instant seen for the pane, so the two respawn shapes agree and a pane's start time no longer depends on whether its previous agent got to exit cleanly.

The same-key identity refresh also matched purely on the producer's session id, on the reasoning that panes do not share session ids. Nothing in the code or the tests enforced that, so a frame reusing another pane's producer key would have handed that pane's card its identity — and, through the rebuild, its tool tally and prompt history — with no evidence the two were related. The refresh now additionally requires both sides to agree on the pane whenever both name one. This is a latent path rather than one reachable with today's producers: it hardens the supersession against a future producer or a change in how session ids are built.
