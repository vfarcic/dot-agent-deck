## Hooks only run a copy nobody else can change

Your agents run the deck's hook command as you, every time a hook fires. The deck now points those hooks only at a copy that nobody but you and root can change. The copy, every directory above it and any symlink on the way must belong to you or root, and no other account may be able to write to them. Before, the deck checked only the file's own permissions, so a copy placed by another account, or kept in a directory another account could write to, could still end up in your agents' hook settings.

A copy that fails this is skipped for the next one the deck finds. When no copy passes, the one you are running included, no hooks are installed, and `dot-agent-deck hooks install` names the file or directory at fault, the copies it skipped, and the fix: `chmod go-w` on what it names, or install the deck in `~/.local/bin`. Group write stays allowed where the group holds only you, which is the Debian and Ubuntu default, and, on macOS, for the `admin` group that Homebrew and `/Applications` use. So Homebrew, Nix, `cargo install` and `~/.local/bin` installs in their default layouts keep working, and a `cargo install` copy on Debian or Ubuntu is no longer passed over because its file is group-writable.

See [Agent hooks](https://agent-deck.devopstoolkit.ai/docs/installation.md).
