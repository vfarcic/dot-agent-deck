## Bounded allocation in the exported render seams

The `dot_agent_deck::ui::render_*_to_buffer` family — the L1 render seams integration tests drive the dashboard, bars, cards and modals through — now bounds the dimensions a caller asks for to 1024 x 1024 before allocating anything. Each seam builds a `ratatui` `TestBackend`, which allocates exactly one cell per `width * height`, so a call at `u16::MAX` on both axes asked for roughly 4.3 billion cells and took the process down with an out-of-memory abort rather than returning an error the caller could handle.

Nothing in the running deck calls these seams, so this changes no behaviour anyone sees on screen; it closes a hole in the crate's public API surface, where `pub mod ui` makes all two dozen entry points reachable by any dependent crate and half of them carry no `#[doc(hidden)]` at all. Dimensions in range are honoured exactly, so every existing test renders identically. The cap is `ui::RENDER_SEAM_DIM_MAX`, comfortably above any real terminal, and it matches the clamping the daemon already applies to child PTY dimensions through `PTY_RESIZE_DIM_MAX`.
