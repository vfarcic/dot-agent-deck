## The TUI render loop no longer drains a dispatch queue nothing writes to

`UiState::pending_dispatches` and the `process_pending_dispatches` that drained it were the leftover half of a seam PRD #93 round-5 closed. That round moved delegation dispatch into the daemon — the daemon's hook loop now writes the file-backed prompt and its one-liner straight into the worker pane's PTY (`AppState::handle_delegate` / `AppState::handle_work_done`) — and the producer went with it while the consumer stayed. Every frame since then has run a `retain` over a `Vec` that only ever had elements pushed into it by three tests in `src/ui.rs`'s own test module, verified by grepping the whole repository for writers. The field, the struct, the function and its call are gone.

The call-site comment is corrected in the same change, because it is what made the queue read as live to anyone skimming the loop: it credited `process_pending_dispatches` with ferrying the orchestrator's *initial* prompt across the agent-ready gate, which is `deliver_orchestrator_prompt`'s job and is called about twenty lines earlier. The two doc comments that counted "three spawn-time gates" now count the two that exist. The pre-daemon baseline references in `src/state.rs` stay — they cite the historical `2fc39c3:src/ui.rs::process_pending_dispatches`, which still resolves; the one that named the symbol without anchoring it to that commit now does, so it is not a dangling reference to something no longer in the tree.

Issue [#1005](https://github.com/vfarcic/dot-agent-deck/issues/1005)'s regression guard is kept, not dropped with the code it rode on. `prompt/pane-input/037` used this queue as its vehicle for one of the three gates; that half now asserts `spawn_time_agent_ready` — the predicate #1005 actually narrowed, which every delivery site calls — directly: false for a pane with no session, still false once the daemon's card-surfacing `SessionStart` has resolved an agent type off the command, true only once a producer announces a conversation. Pinning the predicate rather than one of its callers is what that half was always about, and it keeps standing for a caller added later. Reverting the narrowing in a throwaway edit reddens the rewritten half on exactly that assertion, so the guard is checked rather than assumed. The two `pending_dispatch_*` tests, which only exercised the dead drain, are deleted.

No TUI↔daemon contract change: this is TUI-local state with no producer, `PROTOCOL_VERSION` is untouched, and no wire shape or field meaning moves.
