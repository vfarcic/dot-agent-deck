## Issue Dispatch No Longer Removes a Worktree an Agent Is Starting In

When a scheduled issue dispatch cleans up a worktree that an earlier attempt left behind, it no longer deletes that worktree from under an agent that is starting in it at the same moment. An agent already starting there keeps the worktree, and the issue is skipped as claimed. An agent started there while the cleanup is removing it is refused with "working directory … is being removed" instead of running in a directory that is about to disappear. Start it again once the cleanup has finished.
