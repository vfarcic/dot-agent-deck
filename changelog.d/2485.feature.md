## A dispatched unit can send up to 20 updates to its report, and the dispatcher is told when it may be looping

A dispatched unit whose work keeps moving after it reports, for example a late review finding, then the merge, then a red run on `main`, can now keep its report current: it can send up to 20 updates with `work-done --done`, instead of three. A healthy unit rarely needs more than three, so from the fourth update on, each update the dispatcher receives also says that the unit has sent more updates than usual and may be looping. The update is still delivered. A 21st different report is refused with `report_updates_exhausted`, and running `work-done --done` again with the same report still sends nothing new. Units and orchestrators are told both numbers.

A daemon from an earlier release keeps the old limit of three updates until it is upgraded.
