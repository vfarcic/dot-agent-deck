## A card no longer stays on Working after a subagent's tool call outlives the turn

A Claude Code agent that had finished its turn could sit on **Working** indefinitely, with `Bash` or some other tool as its activity, until its next real event — fifteen hours in the reported case. After a turn ends, Claude Code can still run a subagent or background agent under the same session. That agent's tool call reached the card like any other, switched it to Working, and nothing afterwards switched it back: often its `PostToolUse` never arrived, and even when it did, only the main thread's next `Stop` returns a card to Idle.

Claude Code marks every hook that fires inside a subagent with an `agent_id`, and the deck now forwards it. A subagent's tool calls no longer set a card's status or its current tool. They still appear in the card's tool history and still count toward its tool total, and a permission prompt a subagent raises still shows **Needs Input** and clears when answered. While a foreground subagent runs, the card reads Working on the main thread's call that launched it, rather than switching to each of the subagent's own calls. A subagent's failed tool call no longer turns the card to **Error** either; the subagent handles that failure, not the main thread.

Codex marks its thread-spawned subagents the same way and is covered by the same change. Devin's hooks carry no such marker, so Devin cards are unchanged.
