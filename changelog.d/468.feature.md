## Continue Work in an Existing Directory with `dispatch --dir`

`dot-agent-deck dispatch` can now start a unit in a directory that already exists, instead of always making a new worktree. When an agent has finished analysing an issue and the work needs a team, the branch, notes and tests it left no longer get stranded: the team starts right where they are.

`dispatch <name> --dir <path>` starts a single agent or an orchestration in that directory, on whatever branch is checked out there and with every file in it, committed or not. `--dir .` means the directory you run the command from, so an agent can hand its own work to a team with `dispatch <name> --dir . --orchestration <team> --task-file .dot-agent-deck/<brief>.md`. Nothing is created, and closing the unit leaves the directory in place; `close` reports it as `left in place`. The orchestrations on offer are the ones that directory defines, and `dispatch --list-targets --dir <path>` lists them. A `--dir` dispatch into a directory where other agents of the deck are still running is refused, with a message naming the directory and what was found there, so two units never share one directory. The dispatcher pane is taught both forms: the default new worktree for a new line of work, and `--dir` to continue one.

Without `--dir`, `dispatch` works exactly as before. `--dir` needs a daemon from this release; an older daemon ignores it and starts the unit in a new worktree. Restart the daemon after upgrading.

See [Continue work in an existing directory](https://agent-deck.devopstoolkit.ai/docs/dispatcher-mode.md#continue-work-in-an-existing-directory).
