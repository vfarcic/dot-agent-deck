# PRD #163: Windows process, path & filesystem platform backends

**Status**: In Progress
**Priority**: Medium
**Created**: 2026-06-14

> **Phase 2 of native Windows support.** This PRD depends on the platform-abstraction foundation in **[#42](done/42-native-windows-support.md)** (the `src/platform/` seam, `cfg`-gated `libc`, the IPC abstraction, and the `windows-latest` CI job). Read #42 first — it holds the canonical architecture, the per-category Unix→Windows mapping table, the behavior-equivalence risk analysis, and the locked v1 decisions. This PRD implements the remaining platform backends on top of that seam.

## Problem

After #42 lands, the `src/platform/` seam exists and IPC works cross-platform, but five Unix-only mechanism categories still have no Windows backend, so the daemon cannot fully spawn, stop, signal, secure, or share-clipboard on native Windows:

1. **Paths & shell** (`platform::paths`, `platform::shell`) — `config::dirs_home()` resolves `$HOME` only; agent spawn wraps commands in `/bin/sh -c` / `$SHELL`.
2. **Daemon detach & spawn lock** (`platform::detach`, `platform::lock`) — `setsid`+`pre_exec` session-leader detach and `flock(LOCK_EX)` spawn serialization.
3. **Peer-PID & lifecycle signals** (`platform::peercred`, `platform::proc`) — `getsockopt(SO_PEERCRED/LOCAL_PEERPID)` peer-PID and `kill`/`killpg` SIGTERM→SIGKILL teardown.
4. **Filesystem security model** (`platform::fsperm`) — `umask`/mode-bits/`O_NOFOLLOW`/uid-verification.
5. **Clipboard** — `/dev/tty` OSC 52 write.

(Terminal resize needs no code change — see #42; it is validated in #164's e2e pass.)

## Solution

Implement the Windows backend (`windows.rs`) for each `platform/` submodule introduced in #42, preserving the Unix backend byte-for-byte. Per the decisions locked in #42:

| Backend | Windows implementation |
|---|---|
| `paths` | `dirs` crate → `%LOCALAPPDATA%`/`%APPDATA%`/`%USERPROFILE%`; per-user pipe-name suffix; `DOT_AGENT_DECK_*` env overrides stay authoritative. |
| `shell` | `%COMSPEC%`/`cmd /C`. |
| `detach` | `creation_flags(DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP)` + `NUL` stdin; handle `CREATE_BREAKAWAY_FROM_JOB` if launched inside a kill-on-job-close Job Object. |
| `lock` | named mutex `Global\dot-agent-deck-spawn-{user}-{lock-path}` (RAII shape preserved); treat `WAIT_ABANDONED` as acquired-after-crash. Doubles as the singleton-daemon guard. **M2 refinement:** the name carries a per-lock-**path** segment, not just `{user}`. `flock(2)` serializes per lock file and the two callers use two different files — `ensure_daemon_running` holds `<state_dir>/spawn.lock` across spawn *and* its poll-for-endpoint loop while the daemon it spawns needs `lock_path_for(endpoint)` for its own probe→bind — so one per-user name would deadlock every lazy-spawn. Keying on the path reproduces flock's granularity (and keeps `DOT_AGENT_DECK_LOCK_DIR` test isolation); the singleton-daemon doubling still holds because `lock_path_for` is a pure function of the endpoint. Created with a protected current-user-only DACL, the counterpart of the Unix 0o600-in-0o700-dir lock file. |
| `peercred` | `GetNamedPipeServerProcessId` / `GetNamedPipeClientProcessId` (`windows-sys`). **M3 refinement:** which of the two runs is dispatched on the `IpcStream` variant (`Client` → server pid, `Server` → client pid), because named pipes split the directions Unix's symmetric `SO_PEERCRED` merges. Getting it wrong fails silently, not loudly: asking for the *server* pid from the server end returns the caller's own pid, and the consumer is `daemon stop` — so a daemon answering a stop request would terminate itself. |
| `proc` | `daemon stop` routes through the existing `KIND_SHUTDOWN`/ACK protocol then escalates to `TerminateProcess`; agent teardown assigns each agent to a Job Object and `TerminateJobObject` reaps descendants; best-effort `CTRL_BREAK_EVENT` grace window. **M3 refinements:** (a) *which* mechanism delivers the graceful half of `daemon stop` is declared at the platform seam (`platform::proc::GRACEFUL_STOP_DELIVERY`) and consumed by the one shared graceful→poll→force state machine in `terminate_daemon_graceful`, so no wire format or protocol handler branches on the platform and Unix keeps its zero-protocol-bytes `SIGTERM` (the property that lets `daemon stop` kill a pre-`KIND_SHUTDOWN` daemon). (b) The `CTRL_BREAK_EVENT` grace step is best-effort in a stronger sense than "console apps honour it inconsistently": `GenerateConsoleCtrlEvent` requires the caller to share a console with the target (the daemon is `DETACHED_PROCESS`, so it has none) *and* the target to be a process-group leader (`portable-pty`'s ConPTY spawn passes no `CREATE_NEW_PROCESS_GROUP`), so in the daemon deployment it normally fails outright — logged at debug, not warn, because that is the expected path. `TerminateJobObject` is the guarantee; the grace window degrades to "poll `try_wait` for the same budget Unix uses". A faithful graceful path would mean writing `ETX` into the ConPTY *input* stream, which needs the agent's PTY writer and is out of scope for v1. (c) The Job Object carries no `KILL_ON_JOB_CLOSE`, matching Unix, where dropping a `Child` does not kill the agent. |
| `fsperm` | current-user-only pipe security descriptor (replaces socket `0o600` + `verify_socket_trusted`); per-user `%LOCALAPPDATA%` ACL for dirs (optional explicit `SetNamedSecurityInfo`); audit each `cfg(unix)` permission site individually. **M4 refinements:** (a) The pipe descriptor is `O:<sid>D:P(A;;GA;;;<sid>)` — an **explicit owner** clause, not just a DACL. Without it the object owner comes from the token's default, which the "default owner for objects created by members of the Administrators group" policy can make `Administrators`; the client-side check compares owner SIDs, so a defaulted owner would make an elevated daemon fail its own verification. The same `O:` was added to the M2 spawn mutex for the same reason. (b) The descriptor is applied to **every** pipe instance, including the replacement `IpcListener::accept` creates after each connection — each instance carries its own SD, so securing only the `bind` instance would have left every connection after the first world-readable while still passing a single-connect test. (c) `set_create_mode_owner_only` stays a no-op because `std::fs::OpenOptions` has no `SECURITY_ATTRIBUTES` hook; the owner-only property therefore rides entirely on `set_file_owner_only`, and the three secret-bearing writers (`remotes.toml`, `schedules.toml`, `session.toml`) now call it **immediately after `open`, before the first content byte**, so only an empty file can exist under a loose inherited ACL. `schedules.toml` was not calling it at all. (d) The client-side trust check is welded into both `platform::ipc` client constructors rather than left to callers: on Unix `verify_endpoint_trusted` is out-of-band and the connect that follows is unguarded, so a caller can forget; on Windows every connect verifies, so it is fail-closed by construction. Optional-`SetNamedSecurityInfo` became mandatory: the `DOT_AGENT_DECK_STATE_DIR`/`_REMOTES`/`_SCHEDULES` overrides can point anywhere, so `%LOCALAPPDATA%`'s default ACL is not a guarantee. |
| clipboard | `CONOUT$` OSC 52 (inline `cfg` in `copy_to_clipboard_osc52`). |

### v1 behavior-equivalence (locked in #42)

- Graceful agent shutdown is best-effort on Windows (`CTRL_BREAK_EVENT` then hard `TerminateJobObject`) — a faithful SIGTERM-trap grace window is not reproducible for console apps. Documented difference.
- The security model splits from uniform Unix mode-bits into "pipe security descriptor + dir ACL + `%LOCALAPPDATA%` defaults"; each site is audited so no security property is silently lost.

## Security & robustness requirements carried from #42's review (release-gating)

The #42 Foundation review (auditor + reviewer) confirmed no Unix regression but flagged concrete Windows-backend gaps that #42 deliberately left as compiling stubs / no-ops. In the Foundation, the Windows daemon was **hard-failed (`Unsupported`) at the `IpcListener::bind`/serve seam** so none of these gaps were reachable at runtime. **#163 unblocks the Windows daemon, so #163 MUST close all of these — the first item is a hard gate on any Windows release (#164):**

> **Status: all closed as of M4**, and the `IpcListener::bind` hard-fail was removed with them — the gate existed solely because that call would otherwise create an `Everyone`-readable pipe with no client-side verification, and both of those preconditions are now met. M5 (clipboard `CONOUT$`) is an unrelated presentation surface and is not a security precondition for the daemon. Runtime confirmation on a real Windows host remains #164's job; what M4 delivers is the code plus the compile/clippy/unit-test gates.

- **[BLOCKER] Named-pipe security descriptor.** `platform/ipc/windows.rs` currently creates the pipe with the *default* security descriptor (Everyone-read DACL) and `verify_endpoint_trusted` is a Windows no-op. Combined with the predictable per-user pipe name, a foreign local user could pipe-squat — read agent terminal output / hook payloads and impersonate the daemon to capture forwarded keystrokes. **Required:** create the pipe with an explicit current-user-SID DACL (`ServerOptions::security_attributes`, `Win32_Security` feature already enabled) **and** add client-side server-SID verification, replicating the Unix owner/mode trust check. The client-side verification must cover **both** client entry points — the ui/attach client (`IpcStream::connect`/`IpcClient::connect`) **and** the hook client (`hook::send_to_socket`/`request_from_socket`); the latter is *not* daemon-gated, so on Windows it can already connect to the predictable per-user pipe name and would leak hook payloads / accept spoofed replies from a foreign-squatted pipe unless it verifies the server SID before writing. Removing the #42 Windows daemon hard-fail is contingent on this landing. **Closed in M4.** Both halves landed and the hard-fail at `IpcListener::bind` was removed with them: the server side creates every instance (bind *and* accept) with `O:<sid>D:P(A;;GA;;;<sid>)`, and the client side verifies the pipe object's owner SID inside **both** `platform::ipc` client constructors, so the hook client is covered structurally rather than by remembering to call a checker. Everything fails closed — an unreadable SID, an unbuildable descriptor or an unverifiable server is an error, never a fallback to the permissive default.
- **Config-secret file ACLs.** `set_create_mode_owner_only`/`set_file_owner_only` are Windows no-ops, so `remotes.toml`/`schedules.toml` (may carry secrets) rely solely on the `%LOCALAPPDATA%` default ACL; a `DOT_AGENT_DECK_STATE_DIR` override to a permissive dir loses the Unix `0o600` guarantee. **Required:** explicit owner-only ACL on these writes (or refuse a world-writable target dir). **Closed in M4** with the explicit ACL (the stronger of the two options — refusing a world-writable target would still leave the file's own DACL inherited). `set_file_owner_only` applies a protected current-user-only DACL via handle-based `SetSecurityInfo`, the dir helpers via `SetNamedSecurityInfoW`, and the audit is machine-readable: `fsperm::SITE_AUDIT` carries one row per exported seam function and a test fails the build if any row claims a Windows no-op without justifying it.
- **Sync IPC client timeouts (TUI hang-risk).** `IpcClient::set_timeouts` is a Windows no-op, so the synchronous TUI request path (`ui::send_daemon_request_blocking`) has no read/write deadline vs Unix's 5s — a wedged daemon hangs the TUI key path. **Required:** implement named-pipe read/write timeouts on Windows. **Closed in M4:** the pipe is opened `FILE_FLAG_OVERLAPPED` and every read/write is reaped through `GetOverlappedResultEx` with a millisecond deadline (`CancelIoEx` + a blocking `GetOverlappedResult` reap on expiry, so the kernel is provably done with the buffer before it goes out of scope). Windows also carries a 5s **default** deadline from connect time, which Unix neither has nor needs: `shutdown_write` there is a real `SHUT_WR`, so a request/response caller can always drive its peer to EOF, whereas a named pipe has no half-close.
- **Pipe-name user suffix collision.** `paths::endpoint_user_suffix` falls back to the literal `"user"` when `USERNAME` is unset, colliding across users (Unix uses uid, which never collides). **Required:** a non-colliding fallback (or hard error) for the Windows pipe-name suffix. **Closed in M1** (the SID-derived `endpoint_user_suffix`).
- **Stale-endpoint dance on Windows.** `run_daemon_with` / `bind_attach_listener` run the Unix `path.exists()` + `remove_file()` stale-inode dance, which is semantically wrong on a `\\.\pipe\` name (named pipes have no inode; the singleton guard is `first_pipe_instance(true)`). **Required:** short-circuit the probe/remove dance on Windows when the daemon path is unblocked. **Closed in M4** via `platform::ipc::stale_endpoint_artifact` / `remove_stale_endpoint` (compile-time split, so Unix is bit-identical). **The audit found a third site the PRD had not listed:** `daemon_attach::ensure_daemon_running` used `socket_path.exists()` both as its "is the daemon already up?" pre-check *and* as its post-spawn poll condition. On Windows that is permanently false, so every lazy-spawn would have started a second daemon and then failed with `DaemonStartTimeout` — the Windows daemon would have been unusable even with the bind gate lifted. Where the endpoint is not a filesystem path the connect-probe is now the presence test, and it doubles as the trust check because `IpcStream::connect` verifies the server's owner SID.
- **`poll_daemon_gone` path-existence check (Greptile P2, PR #167).** `src/build_version_handshake.rs` (~L378–390) `poll_daemon_gone` uses `attach_path.exists()`, which returns false for a `\\.\pipe\…` name even when the pipe server is active (`GetFileAttributesW` → `ERROR_BAD_PATHNAME`) — so the first loop iteration would immediately (and wrongly) declare the daemon gone. **Required:** use a pipe-aware liveness check on Windows (e.g. attempt a client connect) rather than `path.exists()` once the daemon path is unblocked. **Closed in M3** (the daemon-stop escalation it breaks is M3's): the existence short-circuit is now gated on `platform::ipc::ENDPOINT_IS_FILESYSTEM_PATH`, leaving the connect attempt as the only liveness signal where the endpoint has no on-disk presence. A compile-time constant, so Unix behavior is bit-identical.

## Edge Cases

- `WAIT_ABANDONED` on the spawn mutex — treat as acquired-after-crash.
- Detached daemon inside a kill-on-job-close Job Object — may need `CREATE_BREAKAWAY_FROM_JOB`.
- `CTRL_BREAK_EVENT` honored inconsistently by console apps — `TerminateJobObject` is the unconditional backstop.
- Each `cfg(unix)` permission site must get a Windows counterpart or a justified no-op — easy to under-implement and silently drop a security property. **M4:** mechanized as `platform::fsperm::SITE_AUDIT`, one row per exported seam function (Unix mechanism, Windows mechanism-or-justification). A test asserts every row has both, that a "justified no-op" carries a real justification rather than a shrug, and — via typed function bindings — that renaming or deleting a seam function stops the audit *compiling*. Adding an export without a row trips the row-count assertion.
